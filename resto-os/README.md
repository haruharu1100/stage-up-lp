# 飲食店まるごと管理OS（resto-os）

飲食店の「注文 → 厨房 → 会計 → 経営数字」までを、ひとつのシステムでまとめて回すための土台です。
月額課金SaaSとして複数店舗に売る前提で、**契約（テナント）ごとにデータを完全に分離**して動きます。

> **設計書一式は [docs/00_目次.md](docs/00_目次.md) にあります。**
> 全体構成・画面/権限・DB・API・機能仕様・業務フロー・開発計画/テスト・課金運用/営業の8本。

## 画面一覧

| 画面 | URL | 内容 |
| --- | --- | --- |
| ログイン | `/login` | メール＋パスワード／店舗コード＋PIN の2通り |

| お客様の注文（実体） | `/t/<入場トークン>` | `/q/` から自動で飛ぶ。お会計のたびにトークンが入れ替わり、前のお客様の画面からは注文できなくなる |
| スタッフ注文（ハンディ） | `/staff` | 口頭注文をスタッフのスマホから入力 |
| 厨房モニター（KDS） | `/kitchen` | 注文を場所別に表示・経過時間で遅れを警告 |
| テーブル / 会計（POS） | `/pos` | 卓状況・呼び出し対応・お会計・注文取消 |
| ダッシュボード | `/admin` | 売上・客数・客単価・粗利・ランキング・AI店長 |
| 商品管理 | `/admin/menu` | 価格・原価・売り切れ・オプション |
| テーブル・QR | `/admin/tables` | QRコードの発行と印刷 |
| 注文履歴 | `/admin/orders` | 会計伝票／注文明細・会計の取消と返金 |
| クーポン | `/admin/coupons` | 割引クーポンの発行・停止 |
| スタッフ | `/admin/staff` | 追加・権限変更・PIN/パスワード変更・停止 |
| 操作ログ | `/admin/logs` | 誰が・いつ・何をしたかの全記録（CSV書き出し可） |

## 権限（5種類）

| 権限 | 主な範囲 |
| --- | --- |
| オーナー | すべて。原価・粗利も見える |
| 管理者 | すべて。原価・粗利も見える |
| 店長 | 会計・商品・スタッフ・ログ。原価は店舗設定で切り替え |
| スタッフ | 注文・卓の操作のみ。**原価と粗利は画面にも通信内容にも含まれない** |
| 厨房 | 厨房モニターのみ |

## 致命的な事故を防ぐ仕組み

| 事故 | 対策 |
| --- | --- |
| 注文が消える | 端末側に注文を保存して自動で入れ直す／電波復帰時にも再送／書き込みは順番待ちで取りこぼさない |
| 二重注文 | 注文ごとの固有キーで、同じ注文は何度送られても1件しか入らない |
| 他店舗の情報が見える | DBに触れる入口を1つに限定し、契約ID・店舗IDが付かない検索は実行時に停止する |
| 会計がずれる | 会計は「全部成功か全部無かったことにするか」で処理。同時押ししても2回は成立しない |
| 厨房に注文が届かない | 厨房モニターの生存確認を常時送信し、反応が無い／未着手が滞留するとPOSに赤い警告を出す |

取消・返金・値引き・価格変更・ログインなどは `audit_logs` に追記のみで記録し、書き換え・削除の経路はありません。

## お客様の注文画面に入っているもの

商品写真（絵文字 or 画像URL）／商品名／説明／税込価格／カテゴリー／人気ランキング／おすすめ／NEW／
売り切れ／アレルギー／カロリー／辛さ／大盛り・小盛り／トッピング／セット選択／数量変更／備考／
注文履歴／現在の合計金額／店員呼び出し（店員・お冷・おしぼり・皿交換・お会計）

- **アップセル**：カートに入れた瞬間に「一緒に◯◯はいかがですか？」を表示（店舗指定 or AI）
- **AIおすすめ**：人数・時間帯・注文済みの内容から一式を提案。経由売上はダッシュボードに表示
- **注文の振り分け**：ドリンク場／焼き場／刺場／厨房／デザート別に厨房モニターを絞り込み

## 料金プランと機能の対応

| プラン | 使える機能 |
| --- | --- |
| ライト | 注文・厨房モニター・商品管理・テーブル/QR |
| スタンダード | ＋ 会計(POS)・クーポン・売上分析・注文履歴・スタッフ管理・操作ログ |
| AI DX | ＋ AIおすすめ・AI店長・多言語メニュー |
| PRO | ＋ 複数店舗・在庫・シフト・予約 |

プランで使えない機能はAPI側で止まるため、画面を直接開いても中身は見えません。

## 動かし方

```bash
cd resto-os
npm install
npm run seed     # 初期データ（デモ店舗＋比較用の別契約）
npm run dev      # http://localhost:3800
```

`npm run seed` の最後にログイン情報が表示されます（デモ用の仮パスワードです。本番では必ず変更してください）。

| 権限 | メール | パスワード | PIN |
| --- | --- | --- | --- |
| オーナー | owner@demo.test | demo1234 | 1111 |
| 管理者 | admin@demo.test | demo1234 | 2222 |
| 店長 | manager@demo.test | demo1234 | 3333 |
| スタッフ | （PINのみ） | | 4444 |
| 厨房 | （PINのみ） | | 5555 |

ハンディ・厨房用の端末は「店舗コード + PIN」で入ります。店舗コードも seed の出力に表示されます。

### テストプレイ（パスワード不要）

`npm run dev` で動かしている間は、ログイン画面に「テストプレイ」の入口が出ます。
オーナー／管理者／店長／スタッフ／厨房をタップするだけで、その立場のまま入れます。
トップページにはQRを読まずにお客様画面を開くリンクも並びます。

この入口は本番ビルドでは自動的に消えます（`DEMO_LOGIN=1` を明示したときだけ本番でも出せます）。
商談デモ以外では付けないでください。

デモ用に過去7日分のダミー営業データを入れる場合：

```bash
npm run demo
```

seed は「よその店 梅田店」という別契約も作ります。そちらでログインすると、
デモ店舗のデータが一切見えないことをその場で確認できます。

## 公開サイト（お客様お渡し用）

- URL: https://resto-os-alpha.vercel.app
- 置き場所: Vercel（東京リージョン hnd1）／データベースは Turso（東京）
- ログイン画面に「テストプレイ」のワンタップ入口が出ます（`DEMO_LOGIN=1`）。
  URLを知っている人は誰でも入れる状態なので、**商談・テストが終わったら
  `DEMO_LOGIN` を `0` にしてください。**

```bash
npx vercel env rm DEMO_LOGIN production --scope haruharu1100s-projects
npx vercel deploy --prod --scope haruharu1100s-projects
```

必要な環境変数は `DATABASE_URL` / `DATABASE_AUTH_TOKEN`（Turso）と、
AI機能を本物にするなら `ANTHROPIC_API_KEY` です。

## AI機能について

`ANTHROPIC_API_KEY` を設定するとAI（Claude）が動きます。未設定でも止まらず、
店舗ルールベースのおすすめに自動で切り替わります（デモ・オフライン運用も可）。

```bash
# resto-os/.env
ANTHROPIC_API_KEY=（ご自身のキー）
ANTHROPIC_MODEL=claude-sonnet-4-6
```

`.env` は `.gitignore` 済みです。

## 表示ルール（重要）

- 価格はすべて **税込の通常価格のみ** を表示します。二重価格・カウントダウン等の煽りは実装していません。
- AIの提案文には「必ず」「絶対」などの断定・誇大表現を禁止する指示を入れています（景表法対応）。

## データの持ち方

SQLite（libsql）1ファイル：`data/resto.db`
`DATABASE_URL` を差し替えれば Turso 等のクラウドDBにもそのまま移せます。

主なテーブル：`tenants` / `stores` / `staff` / `menu_items` / `tables` / `orders` / `order_items` /
`checks` / `coupons` / `calls` / `audit_logs`

- 業務データはすべて `tenant_id` と `store_id` を持ちます。
- 金額はすべてサーバー側で再計算します（お客様の端末から送られた金額は使いません）。
- 取消・返金は履歴に残す方式です（不正防止）。
