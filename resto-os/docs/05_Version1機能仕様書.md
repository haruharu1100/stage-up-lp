## 6-2. 機能ごとの仕様

### ① 店舗アカウント
- LPから「30日無料で試す」→ メール・店名・電話・業種を入力 → tenant/company/store/オーナーを自動作成。
- サンプル商品22点・テーブル14卓を自動投入し、**申込直後から注文体験ができる**。
- 初期設定ウィザード（5ステップ）：店名 → 営業時間・営業日切替時刻 → 提供場所 → 商品登録（CSV取込可） → QR印刷。
- 権限は オーナー／管理者／店長／スタッフ／厨房 の5種類（02_画面と権限 の表に従う）。

### ② QR注文 / ③ タブレット注文
同じ画面（`/t/<token>`）。お客様のスマホでも卓上タブレットでも同じ体験。

画面に載せる項目（**すべてV1で実装済み**）：
商品写真（画像URL or 絵文字）／商品名／説明／税込価格／カテゴリー／人気ランキング（直近30日の注文数から上位5位にバッジ）／
おすすめ／NEW／売り切れ／アレルギー／カロリー／辛さ／大盛り・小盛り／トッピング／セット選択／数量変更／備考／
注文履歴／現在の合計金額／店員呼び出し（店員・お冷・おしぼり・皿交換・お会計）

- **セット提案（アップセル）**：カートに入れた瞬間に「一緒に◯◯はいかがですか？」を1回だけ表示。
  店が商品管理で指定でき（`pair_with`／`pair_message`）、未指定ならAIが選ぶ。しつこく出さない（同一商品につき1回）。
- **注文の消失防止**：カート内容はブラウザに保存。送信失敗は自動再送3回＋赤帯表示。
  受理番号を受け取るまで「注文完了」と表示しない。

### ④ スタッフ注文（ハンディ）
- PINログイン → 卓選択 → 商品選択 → 送信。片手操作前提。
- 誰が入れたか `staff_id` を記録。
- 送信失敗は赤で明示し、再送ボタンを出す。

### ⑤ 厨房モニター（KDS）
- 受付 → 調理中 → 完成 → 提供済 をタップで進める。
- 提供場所（ドリンク場／焼き場／刺場／厨房／デザート）でフィルタ。
- 経過時間：8分で黄枠、15分で赤枠。
- 新着は音とフラッシュ。
- **未達検知**：20秒以上サーバーと通信できない、または注文の取りこぼしを検知したら全画面赤の警告。
- 完了済み一覧から「戻す」ができる（押し間違い対策）。

### ⑥ 簡易POS
- 卓一覧（空席／着席／呼び出し中）。滞在時間と未会計金額を表示。
- 会計シート：人数 → 明細 → クーポン → 合計 → 均等割り表示 → 支払方法（現金／クレジット／QR決済／電子マネー／その他）→ 確定。
- **決済は自前開発しない。** V1は「支払方法の記録」のみ。Stripe/Square連携はV2。
- 確定でレシート表示・印刷、卓は空席に戻り、QRトークンを再発行。

### ⑦ 会計取消・返金
- 店長以上のみ。**理由入力が必須**。
- 記録は消さず、`checks.status` を voided / refunded に変え、監査ログに残す。
- 日次の売上からは除外し、ダッシュボードに「取消 n件 / ¥x」を表示。

### ⑧ 商品管理
- 価格・原価・写真・説明・カテゴリー・提供場所・アレルギー・カロリー・辛さ・バッジ・オプション・アップセル指定。
- 価格変更・削除は監査ログに変更前後を記録。
- CSV一括取込（既存メニュー表からの移行を数分で終わらせる＝導入のハードルを下げる）。

### ⑨ テーブル・QR
- 卓の追加・席数設定・QR発行。A4に3列で**一括印刷**（`@media print` 対応済み）。
- 会計完了でトークンを再発行（持ち帰られたQRを無効化）。

### ⑩ 注文履歴
- 直近300件。商品名・卓名で検索。取消も表示。削除不可。

### ⑪ クーポン
- 金額引き／％引き、最低利用金額、有効期間、停止・再開、利用回数。
- **表示は通常価格のみ。** 二重価格・カウントダウン等の煽りは実装しない（景表法対応）。

### ⑫ 売上ダッシュボード
- 売上・前日比・客数・客単価・注文点数・粗利益・原価率・割引額・支払方法内訳。
- 商品ランキング（注文数／売上／粗利の3タブ）。
- 時間帯別グラフ。
- 営業日は朝5時始まり。
- **原価・粗利はスタッフ／厨房には返さない。**

### ⑬ AIおすすめ
- 「✨おすすめを聞く」で、人数・時間帯・注文済み内容から提案。
- おすすめ経由・セット提案経由の注文に印（`via`）を付け、
  ダッシュボードに **「AIおすすめ経由の売上 ¥◯◯（全体の◯%）」** を表示。
  → これが「客単価が上がる」の証拠になり、営業で一番効く数字。
- APIキーが無くてもルールベースで動く（デモ・オフラインでも止まらない）。
- 生成文に断定・誇大表現の禁止指示を必ず入れる。

### ⑭ 操作ログ
- 注文取消・返金・値引・会計変更・商品削除・価格変更・ログイン・管理画面操作を全記録。
- 管理画面から日付・担当者・種類で検索、CSV出力。
- 追記のみ。削除・改変不可。

## 16. Version 1の完成条件（これを全部満たすまで売らない）

### A. 事故ゼロの証明（最優先）

| # | 条件 | 確認方法 |
| --- | --- | --- |
| A-1 | 通信を切って注文しても、復帰後に注文が失われない | 機内モードで注文→復帰→厨房に届くことを確認 |
| A-2 | 同じ注文ボタンを連打・再送しても二重登録されない | `client_order_id` 固定で10回送信→1件だけ登録 |
| A-3 | 他テナントのデータに一切アクセスできない | 全APIに対しA店トークンでB店IDを叩き、必ず404 |
| A-4 | 画面表示・レシート・DBの金額が完全一致する | 100会計分を自動照合し差異0 |
| A-5 | 厨房に注文が届かない状態を店が必ず検知できる | サーバー停止→20秒以内にKDSが全画面警告 |

### B. 機能の完成

- 上記14機能がすべて動作。多言語（日英中韓）で注文まで完了できる。
- 5権限が正しく効き、スタッフ・厨房のAPIレスポンスに原価・粗利が含まれない。
- 操作ログに8種類の操作がすべて記録される。

### D. 販売できる状態

- 30日無料体験の申込から、**店が自力で5分以内に最初の注文を厨房へ飛ばせる**。
- 操作マニュアル（PDF 10ページ程度）＋ 2〜3分のデモ動画がある。
- 契約・請求（プラン変更・解約・請求書）が管理画面で完結する。
- 利用規約・プライバシーポリシー・特定商取引法表記が整備されている。
- サポート窓口（電話 or LINE）の受付時間が明示されている。

### E. 実店舗での検証

- **実際の飲食店1店舗で、7営業日連続で無事故稼働**（これが最終条件）。
- ピークタイム（金曜19〜21時）を含む。
- 店側から「手書きに戻したい」と言われない。
