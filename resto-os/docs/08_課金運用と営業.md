# 08 課金運用と営業

対応：19 月額課金前提の運用設計 / 20 LPと営業デモで見せるべき機能

## 19. 月額課金前提の運用設計

### 19-1. 料金プラン

| プラン | 月額（税込） | 主な内容 |
| --- | --- | --- |
| ライト | 4,980円 | QR注文・厨房モニター・商品管理・テーブル管理 |
| **スタンダード（主力）** | **9,800円** | ライト＋簡易POS・売上分析・注文履歴・クーポン・スタッフ管理・操作ログ |
| AI DX | 14,800円 | スタンダード＋AIおすすめ・セット提案・AI店長コメント・多言語（日英中韓） |
| PRO | 24,800円〜 | AI DX＋複数店舗・本部管理・在庫・シフト・予約（V3以降） |

- **初期費用0円 / 30日間無料体験**（表示は通常価格のみ。二重価格・カウントダウン等の煽りは使わない）。
- 店舗数課金：2店舗目以降は1店舗ごとに加算（例：スタンダードで+7,800円／店）。
- 年払いの割引を用意する場合も、**根拠のある通常価格の提示にとどめる**（景表法対応）。

### 19-2. 契約のライフサイクル

```
申込（LP）
  → trial（30日無料。カード登録なしで開始できる）
     ├ 25日目：メールで残り5日を案内
     ├ 28日目：電話フォロー（使い方の詰まりを解消する）
     └ 30日目：カード登録があれば active、なければ read_only へ
  → active（課金中）
     ├ 決済失敗 → past_due（3日ごとに3回リトライ＋通知）
     ├ 3回失敗 → suspended（管理画面のみ閲覧可。**注文・会計は止めない猶予を7日設ける**）
     └ 解約 → canceled（データは90日保持。CSVエクスポート可）
```

**重要な運用方針：** 支払いが遅れても、**営業中の店の注文・会計をいきなり止めない**。
ピーク中に止めると店は潰れ、こちらは訴訟リスクを負います。
止めるのは管理画面の高度機能から。全停止は通知後7日の猶予を置いてから行います。

### 19-3. 課金の実装

- Stripe Billing（サブスクリプション）を利用。カード情報は自社で保持しない。
- `tenants.billing_customer_id` と `plan` / `status` を Webhook で同期。
- 請求書PDFは Stripe が発行したものを `/admin/billing` から閲覧・ダウンロード。
- プランによる機能ON/OFFは `lib/plans.js` の1つの表で管理（01章 13-3）。
  → 解約直後に有料機能が使えたまま、といったズレが起きない。

### 19-4. 提供側（自社）の運用

| 頻度 | やること | 画面 |
| --- | --- | --- |
| 毎日 | エラーログ確認。異常な店舗（注文0件・エラー多発）を検知 | `/ops/errors` `/ops/health` |
| 毎日 | 無料体験中の店舗の利用状況を確認。3日使われていなければ連絡 | `/ops/trials` |
| 毎週 | 解約リスク（ログイン頻度低下・注文数減少）の抽出と架電 | `/ops/tenants` |
| 毎月 | 請求状況・決済失敗の確認 | Stripe |
| 随時 | 障害対応（営業時間帯17〜23時は優先対応） | — |

### 19-5. サポート体制

| 項目 | 内容 |
| --- | --- |
| 窓口 | LINE公式アカウント（第一窓口）＋ 電話（緊急のみ） |
| 受付時間 | 平日10:00〜19:00 ＋ 営業ピーク帯（17:00〜23:00）の緊急対応 |
| 一次対応 | 画面内ヘルプ・FAQ・2〜3分の操作動画 |
| 障害情報 | ステータスページを公開し、障害時はLINEで一斉通知 |
| 導入支援 | メニュー登録の代行（初回のみ）・QR印刷物の提供・現地orオンラインの初期説明1回 |

### 19-6. 収益の見立て（現実的な線）

| 契約数 | 平均単価 | 月間売上 |
| --- | --- | --- |
| 10店舗 | 10,000円 | 100,000円 |
| 30店舗 | 10,000円 | 300,000円 |
| 50店舗 | 11,000円 | 550,000円 |
| 100店舗 | 12,000円 | 1,200,000円 |

- 主なコスト：ホスティング（〜1万円）＋DB（〜1万円）＋AI API（1店舗あたり数十〜数百円）＋決済手数料。
- **粗利率が高い代わりに、解約されると積み上げが崩れる。** だから「事故らないこと」が最大の投資対効果になります。

## 20. LPと営業デモで見せるべき機能

### 20-1. 営業の流れ

```
営業電話（目的＝契約ではなく「デモの約束を取る」）
  → LPを見てもらう
  → 2〜3分のデモ動画を見てもらう
  → 無料オンラインデモ（画面共有30分）
  → 30日無料体験
  → 月額契約
```

**電話のゴールは1つだけ：デモのアポイント。** その場で契約を迫らない。

### 20-2. 狙う店舗

- 手書き伝票で注文を取っている店
- 高額なハンディ端末をレンタルしている店（比較で強い）
- 人手が足りない店
- 外国人客が多い店（多言語が刺さる）
- 電話予約が多い店（V2の予約で刺さる）
- 個人店〜5店舗規模、大阪から着手
- 業種：居酒屋／焼肉／ラーメン／カフェ／レストラン／バル／食べ放題

### 20-3. LPの構成（1枚）

| ブロック | 内容 |
| --- | --- |
| ファーストビュー | **「月額9,800円で、注文・厨房・売上分析・集客まで。」** ＋ 初期費用0円・30日無料 ＋ CTA「無料デモを見る」 |
| 共感 | 「手書き伝票の書き間違い」「注文が抜ける」「レジ締めに時間がかかる」「外国人のお客様への対応」 |
| 解決（画面写真） | ①お客様のスマホで注文 ②厨房モニターに即表示 ③レジで会計 ④その日の数字が自動で出る |
| 客単価の話 | 「唐揚げと一緒にハイボールはいかがですか？」の実画面。**ダッシュボードの「AIおすすめ経由の売上」の数字**を見せる |
| 端末不要 | 「今あるiPad・Androidタブレット・お客様のスマホでそのまま使えます」（専用機の購入不要） |
| 料金表 | 4プランを並列表示。通常価格のみ表示。主力はスタンダード9,800円 |
| 導入の流れ | 申込 → 5分で初期設定 → QR印刷 → 当日から使える |
| よくある質問 | 決済は？ 途中解約は？ Wi-Fiは必要？ データは移せる？ サポートは？ |
| 最後のCTA | 無料デモ／30日無料体験／資料請求（**契約を迫らない**） |

**LPのゴールは契約ではなく、無料デモ・30日無料体験・資料請求の獲得。**

※ 第2段階のメッセージとして「AI店長が、あなたの代わりに店舗を分析する。」を用意。
　ただし断定・誇大表現は使わず、実際に表示される内容の範囲で説明する（景表法対応）。

### 20-4. デモ動画（2〜3分）の構成

| 秒数 | 見せるもの |
| --- | --- |
| 0:00–0:15 | 卓上QRをスマホで読む。メニューが開く |
| 0:15–0:45 | 唐揚げを注文 → **「一緒にハイボールはいかがですか？」が出て追加される** |
| 0:45–1:10 | 厨房モニターに即座に表示。焼き場・ドリンクに自動で振り分け。経過時間で色が変わる |
| 1:10–1:35 | レジ画面で会計。クーポン適用・均等割り表示・レシート |
| 1:35–2:20 | ダッシュボード。売上・客単価・粗利・原価率・商品ランキング・時間帯・**AIおすすめ経由の売上** |
| 2:20–2:40 | 「今ある端末で、初期費用0円、月額9,800円。30日間無料でお試しいただけます」 |

### 20-5. オンラインデモ（30分）で必ず見せる順番

1. **お客様のスマホで注文 → 厨房に届く**（ここで9割決まる。最初に見せる）
2. **セット提案が出る瞬間**（客単価アップの実演）
3. **厨房の振り分けと経過時間の色分け**（現場の人が一番反応する）
4. **会計 → レシート → 卓が空席に戻る**（レジ締めが楽になる話につなげる）
5. **ダッシュボードのAIおすすめ経由売上**（＝「月9,800円が回収できる」根拠）
6. **操作ログ**（「誰が取り消したか残ります」＝オーナーに強く刺さる）
7. **多言語切替**（外国人客が多い店には必ず見せる）

### 20-6. 見せない方がいいもの

| 見せない | 理由 |
| --- | --- |
| 未実装の機能（在庫・予約・電話AI） | 「できます」と言うと契約後にトラブルになる。「今後追加予定」とだけ伝える |
| 設定画面の細かい項目 | 難しそうに見えて離脱する。初期設定は代行する前提で話す |
| 数字の大げさな効果予測 | 「必ず客単価が上がる」等は断定・誇大表現にあたるため使わない。**実際の画面の数字で語る** |

### 20-7. 想定される質問と回答

| 質問 | 回答 |
| --- | --- |
| 「専用の機械は要りますか？」 | 不要です。今お使いのiPad・Androidタブレット・お客様のスマホで動きます |
| 「決済もできますか？」 | 現在は支払方法の記録までです。決済はStripe・Squareとの連携で対応予定です |
| 「ネットが切れたら？」 | 注文は端末に保存され、復旧後に自動で送信されます。厨房に届いていない場合は画面が警告します |
| 「他の店にデータが見られませんか？」 | 店舗ごとに完全に分離しています。他店舗のデータには技術的にアクセスできません |
| 「途中でやめられますか？」 | いつでも解約できます。データはCSVで出力できます |
| 「メニュー登録が大変では？」 | CSVで一括取込できます。初回は当方で代行入力します |
| 「高齢のスタッフでも使えますか？」 | スタッフの操作は着席・代理注文・会計の3つだけです |
