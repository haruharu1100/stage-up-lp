# 06 業務フロー

対応：8 店舗側業務フロー / 9 お客様側注文フロー / 10 厨房側フロー

---

## 8. 店舗側の業務フロー（1日の流れ）

### 8-1. 開店前（15分）

```
1. 厨房タブレットの電源を入れ /kitchen を開く（ブックマーク1タップ）
   → 「サーバー接続OK」の緑表示を確認する ← ここを毎日必ず見る運用にする
2. レジPCで /pos を開く
3. 前日の売れ残り・仕入れ状況から、売り切れ商品をチェック（/admin/menu か厨房画面から）
4. 本日のクーポンを確認（雨の日クーポン等）
5. 卓上のQRが汚れ・破れていないか目視
```

### 8-2. 営業中

```
お客様来店
  → スタッフが人数を確認し、卓に案内
  → POSで卓をタップ →「着席 4名」
     （またはお客様がQRを読んで人数を入力）
  → お客様が注文（QR / タブレット / 口頭→スタッフのハンディ）
  → 厨房で調理 → 完成 → スタッフが提供 → 提供済にする
  → 追加注文（同じ流れ）
  → 呼び出し（お冷・おしぼり・皿交換）はPOSと全スタッフのスマホに通知
  → 「お会計」ボタン → POSに赤で通知
  → レジで会計 → レシート → 卓が自動で空席に戻る
```

**スタッフの1日の操作は実質3つだけ**：着席させる／たまに代理注文する／会計する。
覚えることを増やさないのが導入成功のカギです。

### 8-3. 閉店後（10分）

```
1. /pos/close で日次締め（現金残高を入力 → 理論値との差異を記録）
2. /admin でその日の数字を確認
   売上・客数・客単価・粗利・原価率・時間帯・ランキング・AIおすすめ経由売上
3. AI店長コメントを読む（例：「本日は21時台の注文が前週比で少なめでした。
   唐揚げの注文数は好調です。」※断定・誇大表現は使わない）
4. 明日の売り切れ・仕込み量の目安を確認
5. 厨房タブレットは電源を入れたままでよい（自動スリープ防止）
```

### 8-4. 週次・月次

| 頻度 | やること | 画面 |
| --- | --- | --- |
| 週1 | 商品ランキングを見て、売れない商品を入れ替え検討 | `/admin` |
| 週1 | 取消・値引きの多さを確認（不正・オペミスの兆候） | `/admin/logs` |
| 月1 | 原価率の推移を確認、価格改定の検討 | `/admin` |
| 月1 | 請求書の確認 | `/admin/billing` |
| 随時 | スタッフの入退社に伴うPIN発行・無効化 | `/admin/staff` |

## 9. お客様側の注文フロー

### 9-1. 正常系（QR注文）

```
1. 卓のQRをスマホカメラで読む
2. 「4名様でご利用ですか？」→ 人数を選ぶ（初回のみ）
3. メニューが開く
   上部：カテゴリー横スクロール／言語切替
   一覧：写真・商品名・説明・税込価格・バッジ（人気1位／おすすめ／NEW／辛さ／売り切れ）
4. 商品をタップ → 詳細シート
   アレルギー・カロリー表示／サイズ（並盛・大盛り+150円）／トッピング（半熟卵+100円）／
   セット選択／数量 −1＋／備考「わさび抜き」
5. 「カートに入れる」
6. セット提案が1回だけ出る
   「唐揚げと一緒にハイボールはいかがですか？」→ 追加する / 閉じる
7. 画面下に常時「カート 3点 ¥2,480」→ タップして内容確認
8. 「注文する」→ 送信中… → 受理されると「厨房に届きました」
9. 注文履歴タブでいつでも確認、現在の合計金額も表示
10. 呼び出しボタン：店員／お冷／おしぼり／皿交換／お会計
11. 「お会計」→ スタッフがレジで精算（またはV2でスマホ決済）
```

所要：**QRを読んでから最初の注文まで、慣れていない人でも60秒以内**を目標にします。

### 9-2. 異常系（ここを丁寧に作ると解約されない）

| 状況 | お客様に見せるもの |
| --- | --- |
| 通信が切れた | 赤帯「電波が不安定です。注文はまだ送信されていません」＋自動再送＋「再送する」ボタン |
| 送信は成功したが返事が遅い | 「送信中…」のまま。**勝手に完了と出さない**。10秒後「時間がかかっています」 |
| 売り切れ商品を注文した | 「申し訳ございません、たった今売り切れになりました」＋代替のおすすめ2品 |
| 卓が空席状態（会計後） | 「この席は現在ご利用できません。店員をお呼びください」 |
| 二重に押した | 二重登録されず、1件目の注文完了画面が出る |
| AIが落ちている | おすすめボタンは残るが、ルールベースの人気順を返す（エラーを見せない） |
| 日本語が読めない | 言語切替（日／English／中文／한국어）。切替は1タップ、選択は端末に記憶 |

## 10. 厨房側のフロー

### 10-1. 画面の見え方

```
┌─────────────────────────────────────────────────────────┐
│ 全部 | ドリンク | 焼き場 | 刺場 | 厨房 | デザート      🔊  ● 接続OK │
├──────────────┬──────────────┬──────────────┬──────────────┤
│ 3番卓  19:42 │ 7番卓  19:38 │ カウンター1  │ 5番卓  19:20 │
│ 経過 2分     │ 経過 6分     │ 経過 9分 ⚠   │ 経過 24分 🔴 │
│ ─────────── │ ─────────── │ ─────────── │ ─────────── │
│ 生ビール ×2  │ 唐揚げ ×1    │ 刺身盛り ×1  │ 焼き鳥5本 ×2 │
│ 枝豆 ×1      │  大盛り      │  わさび抜き  │  タレ        │
│              │ ハイボール×1 │              │              │
│ [調理中にする]│ [調理中にする]│ [完成にする] │ [完成にする] │
└──────────────┴──────────────┴──────────────┴──────────────┘
```

- 経過 8分＝黄枠、15分＝赤枠。ひと目で「遅れている卓」がわかる。
- 新着は音＋一瞬フラッシュ。音量は店ごとに設定（うるさい厨房でも聞こえる／静かな店では小さく）。
- 提供場所タブで、焼き場の人は焼き物だけを見られる。
- 備考（アレルギー・わさび抜き）は**赤字で強調**。見落としは食物アレルギー事故に直結するため。

### 10-2. 状態の進め方

```
受付 ──[調理中にする]──> 調理中 ──[完成にする]──> 完成 ──[提供済にする]──> 提供済
                                                    ↑
                                        ホールが運んだ時点で押す
                                        （完成のままなら「上げ待ち」として残る）
```

- 押し間違いは「完了済み一覧」から1タップで戻せる。
- ドリンクは受付→完成の2段階だけにする設定も可（現場の手数を増やさない）。

### 10-3. 厨房から売り切れにする

品切れが分かった瞬間、厨房画面の「売り切れ」タブから1タップでSOLD OUT。
即座にお客様画面から注文できなくなります（**注文を受けてから謝る事故を防ぐ**）。

### 10-4. 「注文が届かない」を防ぐ二重の仕掛け

1. **未達検知（自動）**：KDSは5秒ごとにサーバーへ問い合わせ。20秒応答が無い、
   または最新注文の番号が飛んでいる（欠番がある）場合、
   **全画面を赤にして「注文が受信できていません」＋警告音**を鳴らし続けます。
   店は即座にレジ画面（`/pos`）で注文内容を確認して手動対応できます。

2. **POS側のバックアップ表示**：レジ画面にも「未着手の注文 n件」を常時表示。
   厨房が止まっていても、ホール側が気づけます。

3. **紙の保険**：レシートプリンタがある店は、注文をキッチンプリンタにも同時出力する設定を用意（V2）。
   タブレットが完全に死んでも営業が止まりません。

### 10-5. 厨房タブレットの運用ルール（マニュアルに明記）

- 電源は挿しっぱなし。スリープ防止ON。
- Wi-Fiは厨房用と客用を分ける（客のスマホが混んでも厨房が遅くならない）。
- 予備の1台を事務所に置き、故障時は5分で入れ替えられるようにする。
- 万一すべて止まった時のために、**紙の注文伝票を10枚だけ常備**しておく（運用手順として案内する）。
