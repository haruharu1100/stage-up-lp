## この設計を貫く1本の柱

機能を増やすことより、**実際の飲食店で毎日、事故なく使えること**を最優先にしています。
特に次の5つは「起きたら解約・訴訟・信用喪失」に直結するため、設計の一番上に置いています。

| 致命的な事故 | 設計上の対策（詳細は各章） |
| --- | --- |
| 注文が消える | 注文はまず端末に保存 → 送信 → サーバー確定の3段構え。通信断でも消えない（01章・06章） |
| 二重注文 | 端末が発行する注文キー（idempotency key）で同じ注文を二重登録しない（04章） |
| 他店舗の情報が見える | 全テーブルに `tenant_id` を持ち、DBに触る入口を1本に絞って強制付与（01章・03章） |
| 会計がずれる | 金額はすべてサーバー側で再計算。客側端末の申告額は一切使わない（03章・04章） |
| 厨房に注文が届かない | 厨房画面に「未達検知」。一定時間受信が無ければ全画面で警告＋音（06章） |

## 表示・表現のルール（全画面共通）

- 価格は **税込の通常価格のみ**。二重価格・カウントダウン等で購入を急かす表現は実装しない。
- AIが生成する文章には「必ず」「絶対」「最安」などの断定・誇大表現を禁止する指示を入れる（景表法対応）。
- 効能・健康への効果をうたわない。
