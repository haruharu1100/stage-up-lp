# 03 データベース設計

対応：4 データベース設計

---

## 4-0. 全テーブル共通のルール（これが崩れると事故る）

1. **業務データの全テーブルに `tenant_id` と `store_id` を必ず持たせる。**
   例外は `tenants` / `companies` / `plans` / システム設定のみ。
2. **主キーは連番。ただし外に見せるIDは別の `public_id`（ランダム文字列）**。
   URLを書き換えて他店を覗く攻撃を成立させないため。
3. **金額はすべて「円・整数」で保存**（小数を使わない＝1円ズレを防ぐ）。
4. **記録は消さない。** 取消・返金は行を削除せず、状態と理由を残す。
5. 日時は ISO8601（UTC）で保存し、表示のときに日本時間へ直す。
6. 「営業日」は **朝5時始まり**。深夜3時の注文は前日の売上として集計する。

インデックスは必ず `(tenant_id, store_id, …)` の順で作ります（テナント分離が最優先の絞り込みになるため）。

| 列 | 説明 |

### order_items（注文明細＝厨房が見る単位）
| 列 | 説明 |
| --- | --- |
| id, tenant_id, store_id, order_id, table_id, item_id | |
| name | 注文時点の商品名（あとで商品名を変えても履歴が崩れない） |
| unit_price | **注文時点の税込単価（サーバーが再計算した値）** |
| cost | 注文時点の原価 |

| options | 選んだオプションの文字列（表示用） |
| note | 備考（アレルギー・「わさび抜き」など） |

## 4-4. 監査・運用

### audit_logs（操作ログ・追記のみ）
| 列 | 説明 |
| --- | --- |
| id, tenant_id, store_id | |
| actor_id, actor_name, actor_role | 誰が |
| action | order.void / check.refund / check.discount / check.update / menu.delete / menu.price_change / auth.login / auth.login_failed / staff.role_change / settings.update / tenant.cross_access_denied |
| target_type, target_id | 何に対して |
| before_json, after_json | 変更前後の値 |
| reason | 理由（取消・返金・値引きは必須） |
| ip, user_agent | どこから |
| created_at | いつ |

- **UPDATE / DELETE を禁止**（アプリ側で挿入のみ許可）。
- 管理画面から日付・担当者・種類で検索。CSV出力可。
- 「割引の多いスタッフ」「取消の多い時間帯」を集計できる。

### webhooks / jobs（V2以降）
決済・LINE通知など外部連携の再送管理用。失敗したら指数バックオフで再試行し、
3回失敗したら管理者に通知。

## 4-6. 会計金額の計算ルール（1か所に集約）

```
明細単価 = 商品のprice + 選択オプションのprice合計   ← すべてサーバー側で計算
小計     = Σ(明細単価 × 数量)   ※status=void は除外
割引     = クーポン（amount＝そのまま / percent＝小計×率、1円未満切り捨て）
           ただし小計 < min_amount のクーポンは適用不可（エラーを返す）
合計     = 小計 - 割引（0円未満にはしない）
1人あたり= 切り上げ(合計 ÷ 人数)  ※均等割りは「表示のみ」。実際の会計は合計で行う
```

この計算は `lib/domain/pricing.js` の1関数だけが持ちます。
お客様画面の合計表示・POSのプレビュー・会計確定・レシート再発行が**全部同じ関数**を通るので、
「画面の金額とレシートが違う」が構造的に起きません。

## 4-7. 今の試作からの差分（実装で足すもの）

| 追加・変更 | 理由 |
| --- | --- |
| 全テーブルに `tenant_id` / `store_id` を追加 | マルチテナント（最重要） |
| `tenants` / `companies` / `stores` / `staff` テーブル新設 | SaaS化・権限 |
| `orders.client_order_id` ＋ UNIQUE制約 | 二重注文防止 |
| `order_items.void_reason / void_by / void_at` | 操作ログと不正防止 |
| `checks.status / voided_by / void_reason` | 会計取消・返金 |
| `audit_logs` 新設 | 30の必須要件 |
| `menu_item_translations` 新設 | 多言語 |
| `public_id`（ランダムID）を主要テーブルに追加 | ID推測による情報漏えい防止 |
| 会計完了時に `tables.token` を再発行 | 持ち帰られたQRの無効化 |
