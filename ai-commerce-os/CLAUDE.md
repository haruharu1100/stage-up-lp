## 絶対に崩さないルール

```
正確性 > 安全性 > 利益 > 自動化率 > 商品数
```

1. **無断で外部サイトを自動操作しない。** 公式API / 法人API / データフィード / CSV / Webhook / 規約上認められた方法のみ。
   使えないなら機能を落として `CONNECTOR_NOT_AVAILABLE` / `MANUAL_APPROVAL_REQUIRED` を返す。**スクレイピングで埋めない。**
2. **Connector の capability が `api` でなければ、自動実行を実行層が拒否する。** 環境変数で true にしても動かさない。
3. **金銭を動かす処理は必ず Action Gate を通す。** 直接 Connector を呼ぶ実装を書かない。
4. **idempotency_key に UNIQUE 制約。** 購入・出品・発送・注文取込の4つは必須。
5. **在庫は個体単位。** SKU×数量方式にしない（二重販売の原因）。
6. **外部APIの「応答不明」は再送しない。** 人間へエスカレーションする。
7. **LLMに金額計算をさせない。** 利益・ROI・スコア・資金配分は決定的なコードで計算する。LLMは説明と分類のみ。
8. **LLM出力は必ずスキーマ検証。** 落ちたら SKIP（Fail Closed）。
9. **AIは自分の閾値・予算・自動化モードを変更できない。** 提案のみ。変更は人間。
10. **APIキーをコードに書かない。** `.env` / Secret Manager のみ。
11. **既定は `COMMERCE_AUTO_MODE=SAFE` / `SANDBOX=true`。** 勝手に変えない。
12. **虚偽・誇大な商品説明を生成しない。** 景表法・古物営業法を守る。
13. **商品数を増やすために判定を甘くしない。** しきい値を下げるのではなく仕入先を増やす。
14. **重複防止3層（L1 出品重複 / L2 個体重複 / L3 商品重複）を必ず通す。** L1はDBのUNIQUE制約で担保する。
15. **LLM判定は段階的コストフィルタの最終段（L4）でのみ呼ぶ。** 想定粗利がLLM費用の20倍未満なら呼ばない。
16. **値上げは必ず上限クランプを通す。** 相場上限・`MAX_PRICE`・`MAX_STEP_UPS`・売却確率下限のいずれかに触れたら値上げしない。
17. **未定義の商品状態ラベルを推測でマッピングしない。** 共通6段階（N/S/A/B/C/D）に無ければ `MANUAL_REVIEW`。
18. **商品マスタの統合は `merged_into` で行い、削除しない。** 実行は人間のみ。

## Fail Closed の3原則

- 分からないなら買わない
- データがおかしいなら止まる
- APIがおかしいなら止まる

### 実装済みで壊してはいけないもの

- 価格方式は2種類に分かれる。**新品・型番商品＝金額ベースの+5%ステップアップ／中古一点物＝市場相場に対する倍率（Market Premium Ratio）を学習。** 片方に統一しない。
- `TARGET_NET_MARGIN`（15%）は「仕入価格×1.15」ではなく**全費用を引いたあとの純利益率**。必要販売価格の式を単純化しない。
- 除外理由（`SKIP_REASONS`）は画面に日本語で出す。英語コードをそのまま人間に見せない。
- `toHalfWidth` で長音符「ー」を半角ハイフンへ変換しない（商品名が読めなくなる）。
- 取込時に確定した `DUPLICATE` は再分析で上書きしない。
- 画面（クライアント側）から状態ランクを読むときは `lib/conditions.ts` を使う。`lib/normalize.ts` は `node:crypto` を持つのでバンドルできない。

Phase 2（全市場双方向アービトラージ）で追加。**ここも崩さない。**

- **市場は「仕入先」「販売先」に固定しない。** 同じ市場が両方になる。`can_buy` / `can_sell` を勝手に落とさない。
- **「できる」と「してよい」を別の欄に分ける。** 構造＝`can_buy`/`can_sell`、許可＝`terms_status`/`automation_permission`。
  規約で使えない市場も**計算はする。実行だけ止める**（`status='BLOCKED'`）。消すと「取り逃し」が見えなくなる。
- **BUY費用とSELL費用を1つの関数に混ぜない。** `calcAcquisitionCost()` と `calcNetReceipt()` は別。
  BUY側の内訳にSELL専用費用（販売手数料・梱包・保管）を入れない。逆も同じ。
- **BUY費用をすべてゼロにすると Phase 1 の `calcProfit` と純利益が1円単位で一致する。** 式を単純化しない。
- **異常価格チェックは除外条件の一番先に置く。** 後ろに置くとデータ誤りが「最優良Route」として上位に出る。
- **手数料は市場ごと×BUY/SELL別。** 一律◯%にまとめない。`is_estimated=1` のままで自動購入しない。
- **使えない市場（BLOCKED / NOT_ALLOWED）の取り逃しは、実際の相場観測がある時だけ出す。** 参考相場で金額をでっちあげない。
- **利益が最大のRouteをベストにしない。** 利益 × 売却確率 × 資金回転 × リスクで選ぶ。
- ルール版は Phase 1 が `v1-`、Phase 2 が `r1-`。**混ぜない。**
