# AI Commerce OS

> **状態：Phase 2 実装済み（2026-08-20）。** 範囲は 取得 → 比較 → Route生成 → 利益計算 → SHADOW記録 まで。
> 実購入・実出品・実決済・実発送・外部サイトへの自動ログイン・自動値上げは**コードごと存在しない**（フラグOFFではなく未実装）。
> 所有していない商品を先に売る処理も無い（在庫の所有状態は全件 `NOT_OWNED`）。

商品の発見 → 市場調査 → 同一商品特定 → 利益計算 → 仕入判断 → 購入 → 出品 → 在庫管理
→ 値付け → 販売 → 発送 → 利益分析 → 再仕入れ → 学習 までをつなぐ、AIによる物販経営システム。

**価格比較ツールではない。** 「何を買うか」だけでなく「いくら買うか」「どこで売るか」「いつ諦めるか」までAIが判断する。

## 最重要原則

```
正確性 > 安全性 > 利益 > 自動化率 > 商品数
```

金銭を伴う処理は Fail Closed。

- **分からないなら買わない**
- **データがおかしいなら止まる**
- **APIがおかしいなら止まる**

---

## 現時点で確定している前提（Phase 0 の調査結果）

- **スニダンの法人販売（出品）プランは新規申込を停止中** → 自動出品の入口が今は無い
- スニダンの法人購入（仕入）プランは受付中だが、年商1億円以上が目安・月200万円以上購入・古物商必須
- KOMEHYOオークション（BtoB）は古物商があれば参加可能・月4回開催 → 仕入口としては現実的。ただし**オークション型**なので固定価格ではない
- したがって **特定2サイト前提を捨て、仕入先／販売先を Connector として外出しする**
- **Phase 1 は外部契約ゼロ・CSV入力で中核（同一商品判定・利益計算・売却確率）を完成させる**
- 仕入先はKOMEHYOだけに限定しない。BOOKOFF / ハードオフ / セカンドストリート / 大黒屋 / 駿河屋 / 古物市場 なども Connector 候補。
  **ただし各社の規約・法人契約・API提供条件を文書で確認できるまで `capability: manual` から出さない**
- 目的関数は「最高値で売ること」ではなく **利益 × 販売数 × 在庫回転率** の最大化

## 起動方法

```bash
npm install
npm run seed -- --reset   # 架空データ1,022件を作って取込・分析まで実行
npm run dev               # http://localhost:3910
```

| コマンド | 内容 |
|---|---|
| `npm run seed -- --reset` | DBを作り直し、KOMEHYO風/BOOKOFF風/HARD OFF風の架空CSVを `samples/` に生成して取込・分析 |
| `npm run routes` | 全市場×全市場の組み合わせを計算し直し、Route（どこで買ってどこで売るか）を作り直す |
| `npm run test:phase1` | Phase 1 受け入れテスト（66項目）。利益計算はテスト側で独立に検算する |
| `npm run test:phase2` | Phase 2 受け入れテスト（49項目）。**仕様を変えたら phase1 と両方通す** |
| `npm run reanalyze` | しきい値や手数料を変えたあと、全商品を再判定 |
| `npm run dev` / `build` / `start` | ポート3910 |

## いまできること / できないこと

**できる**：CSVを入れるだけで数千件を一括で判定し、**全市場×全市場の組み合わせ**から
「どこで買って、どこで売るのが一番いいか」を順位付けする。市場を仕入先／販売先に固定しない。
1件ずつ「なぜそう判定したか」を日本語で説明する。買うと判断したものは SHADOW（仮想取引）として記録する。
規約で使えない市場も**計算だけはして「取り逃し」として見せる**（実行はしない）。

**できない**：実際の購入・出品・決済・発送。外部サイトからの自動データ取得。自動値上げ。AI（LLM）判定。
所有していない商品の先行販売。手数料は既定が概算値（ESTIMATED）なので、利益額は実額を入れるまで変わる。
