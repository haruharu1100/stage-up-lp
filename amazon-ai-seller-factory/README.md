# Amazon AI Seller Factory（Amazon AI Seller OS のMVP）

> **作業前に必ず読むこと**
> 正式仕様書は Obsidian の
> `事業Vault/Amazon AI Seller OS/00_仕様書_最上位.md`（＋ 01広告 / 02権限 / 03実装状況 / 04API優先順位）。
> このシステムを修正・拡張するときは、必ず最初に仕様書を読み、
> 新しい決定事項は必ず仕様書へ追記・統合すること。

「AI社員」が、Amazonで売る商品を探し・調べ・商品ページまで作る工場です。
入口は3つあります。

### ① リサーチツール `/research`

**あなたが商品を入力するのではなく、システムが勝手に探してきます。**

```
仕入先の商品を大量に集める（CSV / Alibaba / 1688 / AliExpress / 問屋 / メーカー）
→ Amazonの中から「同じ商品」を探して照合（MATCH SCORE 100点満点）
→ 推定月販を出して「月10個以上売れている」ものだけ残す
→ 全費目（仕入・中国国内送料・国際送料・関税・検品・Amazon手数料・送料・広告費・返品リスク）で利益計算
→ Research Score 100点満点で採点 → A/B/C/D
→ 有望なものだけ、同じ工場・同じブランド・別サイズ・別色へ芋づるで探索
```

朝いちで `/research` を開くと、いちばん上に**今日のおすすめ仕入候補**が出ます。

```
本日調査した商品 21件 → Amazon一致候補 19件 → 月10個以上 16件
→ 利益条件クリア 12件 → Aランク 4件 → 今日の強い推奨 2件
```

**「この2件だけ見れば判断できます」** の欄だけ読めば、その日の判断は終わります。

#### 同じ商品かの判定（MATCH SCORE）

商品名だけでは絶対に判定しません。100点満点の内訳は

| 配点 | 見るもの |
| --- | --- |
| 画像 40 | pHash（画像の指紋）で見た目の一致 |
| 型番・JAN 20 | JAN/GTIN完全一致 → 型番一致 → 商品名内の型番 |
| 商品名 10 | 文字の重なり（日本語・中国語混在に対応） |
| サイズ・容量 10 | 縦横高さ・重量・内容量 |
| 色・仕様 10 | 色・素材・セット個数 |
| その他 10 | ブランド・カテゴリー・価格帯の妥当性 |

- **90点以上** … 高確率で同一（自動で通す）
- **80〜89点** … 人が目で確認
- **79点以下** … 原則除外

★**画像が似ているだけでは同一商品と断定しません。** 型番・JANの一致も、サイズ・仕様の
裏付けも無い場合は、コード側で必ず「人が確認」以下に落とします（設定では外せません）。

#### AI料金がかからない設計（重要）

判定は**安い順**に進み、決着したらそこで打ち切ります。

```
① 通常計算（0円） → ② ルール判定（0円） → ③ 画像pHash（0円） → ④ テキスト類似（0円）
→ ⑤ Embedding（安い・上限あり） → ⑥ AI Vision（高い・判定が割れた候補だけ・上限あり）
```

何千件調べても、①〜④で決着した商品のAI料金は **0円** です。
実際にサンプルで21件を通しても `この実行で使ったAI課金：0回` になります。
上限は `RESEARCH_MAX_VISION_CALLS` / `RESEARCH_MAX_EMBEDDING_CALLS` で決め、
`0` にすれば完全無料で運用できます。

#### B・Cの見張りと、OEM候補

- B/C は毎日ひとりでに再評価され、条件を満たすとAへ昇格して通知されます
  （通知先は画面／LINE／Slackを差し替え可能）。
- 「売れているのにレビューの不満がいつも同じ」商品は、転売候補とは別に
  **OEM候補**として溜まります。

#### この画面がやらないこと

**仕入れの発注も、Amazonへの出品も、ここからは絶対に起きません。**
`AUTO_PURCHASE=true` になっていると、リサーチは実行そのものを拒否します。

### ② 商品を発掘する `/discover`

たくさんの商品を一気に採算計算して、A/B/C/D に仕分けます。

```
市場データ → 仕入先データと突合 → 相乗り/新規ページ/OEM を判定 → 自己発送の利益を計算
→ 輸入規制を点検 → A(今すぐ仕入れ) / B(値下がりしたら) / C(競合が減ったら) / D(販売しない)
→ 仕入れる個数と、FBAに切り替える目安を出す
```

ここは **AIの文章生成を1回も使いません**。何件調べても追加のAI料金はかかりません。
そして **仕入れ発注もAmazon出品も、この画面からは絶対に起きません**（調べて並べるだけ）。

B・C は「あといくら動けばAになるか」を逆算して見張り条件にします。
例：`仕入値が 1,481円以下（今 1,595円）になれば基準を満たします`

### ③ 商品ページを作る `/`

選んだ1商品を、出品データまで作り込みます。

```
商品を探す → 候補を絞る → 市場・競合を分析 → レビューを分析 → 利益を計算
→ 販売できるか確認 → 画像と動画を作る → 出品データを作る → 最終チェック → 完成
→（許可した時だけ）Amazonへ出品
```

## いちばん大事な約束

- **Amazonへの本番出品は既定で止まっています**（`AMAZON_AUTO_PUBLISH=false`）。
  `true` にしない限り、Amazonへは1件も送信されません。
- **仕入れの発注は、システムからは一切できません**（`AUTO_PURCHASE=false` が既定で、
  `true` にしてもコード側に発注する経路がありません。むしろリサーチが実行を拒否します）。
  AIが候補を「承認」することもありません（`RESEARCH_AUTO_APPROVE=false`）。
- **コンプライアンスAIが「停止」を1つでも出したら、自動出品は動きません。**
- **Amazonサイトのスクレイピングはしません。** 市場データは Keepa などの正規API、
  もしくは自分で用意したCSV・手入力のASINから読みます。
- **他社の商品画像はコピーしません。** 商品ページ画像は、権利のはっきりした
  「元画像（MASTER PRODUCT IMAGE）」を登録したときだけ、それを元に作ります。
  元画像が無ければ、AIは画像を1枚も作らずプロンプトだけ残します。
- **APIキーはコードに書きません。** 環境変数か `.env` から読みます。
- **Amazon内の他の出品者は仕入先にできません。** 他の小売業者から買って顧客へ直送させるのは
  Amazonのドロップシッピングポリシー違反です。仕入先CSVに `amazon` などが書かれていても
  読み込み時に自動で除外し、理由を画面に出します。
- **既にAmazonにある商品で新規ページは作りません。** 重複出品違反になるため、
  既存ASINがある商品は機械的に「相乗り」に固定します。新規ページを作れるのは
  ①Amazonにまだ無い商品 ②商標を持つ自社ブランド（OEM）の2つだけです。

## 使い方

```bash
cd amazon-ai-seller-factory
npm install
npm run dev          # http://localhost:3900
```

ブラウザで開いて「商品を探す」を押すだけです。データベースは初回に自動で作られます。

- `npm run doctor` … いま何が本物で動いて、何が足りないかを日本語で表示
- `npm run research 60 fbm` … **リサーチを1回だけ実行（毎日のcron用）**。仕入候補を探し、
  そのあとB/Cの見張り分も再評価します。`AUTO_PURCHASE=true` なら実行を拒否します
- `npm run run:once` … 商品ページ作成を1回だけ実行（サーバー起動中に実行。cron用）
- `npm run discover -- 30 fbm` … 商品発掘を1回だけ実行（毎朝のcron用。件数と販売方式を指定）

毎日9時に自動で回すなら（Macの例）:

```
0 9 * * *  cd /path/to/amazon-ai-seller-factory && npm run research 60 fbm >> /tmp/research.log 2>&1
```

## A/B/C/D の意味

| ランク | 意味 | 何が出るか |
| --- | --- | --- |
| **A** | 今すぐ仕入れ | 利益も競合もクリア。仕入れる個数と現金額まで出ます |
| **B** | 値下がりしたら | あといくら仕入値が下がれば（or 販売価格が戻れば）Aになるかを逆算して見張ります |
| **C** | 競合が減ったら | 利益は出るが出品者が多すぎる。何人まで減ればAになるかを見張ります |
| **D** | 販売しない | 規制で売れない／どう動いても基準に届かない。理由を残して毎日再評価しません |

判定の基準は `.env` で変えられます（`MIN_PROFIT_RATE` / `MIN_PROFIT_JPY` / `MIN_ROI` / `MAX_SELLER_COUNT`）。

## AI社員

| No | 名前 | 仕事 |
| --- | --- | --- |
| 01 | 商品探索AI | 販売候補を集めて100点満点で採点する |
| 02 | レビュー分析AI | 買う理由・不満・改善余地を読み解く |
| 03 | 商品企画AI | 売れる商品ページの中身を設計する |
| 04 | 画像制作AI | 権利のある元画像から商品ページ画像を作る |
| 05 | 動画制作AI | 15〜30秒の紹介動画の構成と絵コンテを作る |
| 06 | Amazon出品AI | 出品データを組み立て、許可時のみ送信する |
| 07 | コンプライアンスAI | 法令・規約違反を出品前に止める |

## 採点（100点満点）

需要25 ／ 利益率20 ／ 競合の弱さ15 ／ レビューから見つけた改善余地15 ／
販売安定性10 ／ 画像・訴求の改善余地5 ／ 仕入れやすさ5 ／ リスクの低さ5

ランキング上位だけでなく、**「売れているのに商品ページが弱い商品」を高く評価**します。

## だんだん賢くなる仕組み

商品詳細の「実際の売上を入れる」に結果（売上・個数・利益・広告費・CVR・セッション・
返品率・在庫回転日数・欠品日数・ランキング変化）を入れると、予測とのズレが記録されます。
実績が5件たまると、採点の重みを自動で調整します（1回の変更幅は±20%まで）。

AIモデル自体を再学習させることはしません。履歴データと評価ロジックで精度を上げます。

## データの入れ替え方（スクレイピングの代わり）

| やりたいこと | 方法 |
| --- | --- |
| 本物の市場データを使う | `KEEPA_API_KEY` を入れる |
| **リサーチを本物の仕入先で回す** | **`data/supplier_listings.csv` を置く**（見本 `samples/supplier_listings.csv`。日本語ヘッダ可・USD/CNYは自動で円換算） |
| リサーチを仕入先APIで回す | `ALIBABA_*` / `ALI1688_*` / `ALIEXPRESS_*` の鍵3点を入れる（正式APIのみ） |
| 自分で調べた候補を使う | `data/candidates.csv` を置く（日本語ヘッダで可） |
| 発掘の仕入価格を本物にする | `data/suppliers.csv` を置く（問屋・メーカー・eBay・Alibaba） |
| 本物のレビューで分析する | `data/reviews/<ASIN>.csv` を置く |
| Aランク昇格をLINEで受け取る | `LINE_NOTIFY_TOKEN`（またはSlackなら `SLACK_WEBHOOK_URL`） |
| 保存先をS3にする | `STORAGE_PROVIDER=s3` と `S3_*` を設定 |

見本は `samples/` にあります。`samples/supplier_listings.csv` を
`data/supplier_listings.csv` にコピーして自分の仕入先に書き換えれば、
その瞬間から本物の仕入データでリサーチが回ります（コードの変更は不要）。

置くまでは架空のサンプル仕入先で動き、その旨が画面と計算根拠に必ず表示されます。
**サンプルのまま「儲かる商品が見つかりました」とは表示しません。**

## 鍵が無いときの動き

| 機能 | 鍵あり | 鍵なし |
| --- | --- | --- |
| 文章生成 | Claude / OpenAI | サンプル文で流れだけ確認 |
| 商品画像 | OpenAIで生成 | **作りません**（偽の商品画像を出さないため） |
| 市場データ | Keepa | CSV → サンプル |
| リサーチの仕入先 | 各社の正式API | CSV → サンプル仕入先 |
| リサーチのAmazon照合 | Keepa | サンプル市場（実在の商品ではないと明示） |
| 画像の最終確認AI | OpenAI Vision | **「分からない」を返します**（推測で「同一商品」とは言いません） |
| 意味の近さ判定 | OpenAI Embedding | 文字の重なりだけで判定（無料） |
| 昇格の通知 | LINE / Slack | 画面に出すだけ |
| 紹介動画 | fal / Runway | 絵コンテと台本まで |
| Amazon出品 | SP-API | ローカルで項目チェックのみ |

鍵が無い部分は、**それらしい嘘の数字を作らず「分かりません」と表示します。**

## 構成

```
app/          画面とAPI（Next.js App Router）
components/   ボタン・フォームなどの部品
lib/
  agents/     AI社員01〜07 ＋ hunter.ts（商品発掘バッチ）
  providers/  外部サービスの差し替え口
              （LLM/市場/レビュー/画像/動画/Amazon/保存
               ＋ supplier 仕入先 / amazonSearch Amazon検索
               ／ embedding 意味の近さ / vision 画像の最終確認 / notification 通知）
  matching/   同じ商品かを判定する部品
    imageHash.ts  画像の指紋（pHash・DCT）と類似度
    textMatch.ts  日本語・中国語まじりの文字類似と属性の抽出
    matchScore.ts MATCH SCORE 100点満点（安い判定から順に打ち切る本体）
  research/   リサーチツール本体
    pipeline.ts       仕入先→照合→利益→採点→A/B/C/D→芋づる探索
    settings.ts       管理画面から変えられる基準（月販しきい値など）
    salesEstimate.ts  推定月販（「確定」とは言わない）
    researchProfit.ts 全費目の原価計算とA昇格の逆算価格
    priceGap.ts       仕入とAmazonの価格差／地味だけど儲かる商品のタグ
    researchScore.ts  Research Score 100点満点
    watch.ts          B/Cの再評価とA昇格（AI不使用）
  db/         スキーマ・接続・画面用クエリ
  workflow.ts 全体の流れ
  scoring.ts  100点満点の採点
  profit.ts   Amazon手数料と利益計算（FBA／自己発送の両方）
  compliance.ts 景表法・薬機法・食品表示のチェック
  importRules.ts 輸入規制（食品衛生法/薬機法/PSE/技適/商標）
  salesRoute.ts 相乗り／新規ページ／OEM の判定
  sourcing.ts  仕入先CSVの読み込み（Amazon仕入は自動除外）
  grading.ts   A/B/C/D判定と発動条件の逆算（LLM不使用）
  inventory.ts 仕入数量とFBA切替の判断
  oem.ts       レビューの不満を溜めてOEMの設計図にする
  learning.ts 実績から採点の重みを調整
scripts/      doctor / run:once / discover / research
```

PostgreSQLへ移すときは `lib/db/schema.ts` と `lib/db/client.ts` だけを直せば済むようにしてあります。
ジョブ実行を BullMQ 等に変えるときは `lib/queue.ts` だけを差し替えます。
