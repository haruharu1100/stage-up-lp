# 設計6: セキュリティと安全設計

「システムが暴走して損害を出す」経路を、実装レベルで潰す。

---

## 1. 二重ロック（外部副作用）

```env
AUTO_X_POST=false
AUTO_AFFILIATE_APPLY=false
AUTO_OFFER_CHANGE=false
AUTO_CONTENT_PUBLISH=false
```

**ロック1**: 上のフラグがfalseなら関数の入口で即return。ログだけ残す。
**ロック2**: フラグがtrueでも、実行直前に以下を検証し、1つでも合わなければ実行しない。

| 対象 | 直前チェック |
|---|---|
| X投稿 | `/2/users/me` で取得したアカウント名が `X_EXPECTED_HANDLE` と一致するか |
| LP公開 | デプロイ先プロジェクト名が `CF_EXPECTED_PROJECT` と一致するか |
| 案件差し替え | 差し替え先offerが `approval_status=APPROVED` かつ `adult_flag=0` か |

**ASPへの自動応募は、コードごと書かない。** 実装が存在しなければ暴走もしない。

## 2. 投稿ガード（`aura/lib/guard.ts` を移植）

全ての書き込みが必ず通る1本の関門。

| ガード | 内容 |
|---|---|
| 日次上限 | 1日の投稿数を超えたら拒否 |
| 最小間隔 | 前回投稿からの最小間隔（±35%のゆらぎを入れる。等間隔は機械的でスパム判定されやすい） |
| **重複検知** | 過去投稿とのレーベンシュタイン類似度が0.9以上なら拒否（X規約の「類似連投」違反を機械で防ぐ） |
| NGワード | 景表法NG（「必ず」「絶対」「保証」）＋成人向け語彙＋断定的な収益表現 |
| 画像必須 | 画像・動画のないテキストのみ投稿を禁止（既存X運用の検証済みルール） |
| 実ファイル存在確認 | メディアパスが実在するか。存在しなければ投稿しない |
| アカウント照合 | 投稿直前に対象ハンドルを再確認 |
| **AI開示チェック** | プロフィールに `AI-generated` 表記があるか、Automatedラベルが有効かを起動時に検証 |

## 3. Compliance AI の事前チェック（承認画面に出す前に通す）

| 観点 | 落とす条件 |
|---|---|
| X 成人向け | 露出・性的示唆（**暗示的も含む**）を示唆する語・構図指示が含まれる |
| X 自動化 | 特定ユーザーへのメンション、キーワード起点の返信になっている |
| X リンク | 本文にURLが含まれる（→リプライへ移動させる）、短縮URLを使っている |
| AI開示 | AI生成である旨の表示が投稿・プロフィールのどちらにも無い |
| 景表法 | 断定・誇大・二重価格・購入を急がせる表現 |
| ASP規約 | 対象案件の禁止トラフィック・禁止表現に該当 |
| 実在人物 | 実在の人物名・ブランド名を無断で使っている |

**Compliance AI を通っていない投稿は、承認画面に表示しない。** 人が誤って承認できないようにする。

## 4. 秘密情報の扱い

- 認証情報は `ai-yamato-nadeshiko/.env`（gitignore）に置く。**既存プロジェクトの `.env` を読みに行かない**（事故のもと）
- Xの認証情報は**この事業専用のアプリ・アカウントで新規発行**する。既存の @gorogoro_gacha / @KIKUSORA_gacha のキーを絶対に流用しない
- ログにトークン・シークレットを出力しない。エラー時にリクエスト全体をダンプしない（Prismaで過去に事故った既知パターン）
- Cloudflareのトークンは、**このPagesプロジェクトだけに絞ったスコープ**で発行する

## 5. 生成物のQA（Suzuho Awanoの品質を守る）

生成した画像・動画は、以下を通ってから承認画面に出す。

| 検査 | 落とす条件 |
|---|---|
| 顔一致 | 基準顔との類似度がしきい値未満（別人になっている） |
| 指・手 | 指の本数異常 |
| 文字化け | 画像内に崩れた文字が写り込んでいる |
| 露出 | 肌の露出面積が基準超過、または胸・脚の強調構図 |
| 年齢感 | 未成年に見える特徴（**最重要。ここは自動判定＋人の目の二重チェック**） |
| 実在人物への酷似 | 公開前に画像検索で類似人物チェック（当面は人が実施） |
| 解像度 | 規定サイズ未満 |

**未成年に見える判定は、迷ったら必ず捨てる。** 迷った時点でアウト。

## 6. 凍結・停止リスクへの備え

| リスク | 備え |
|---|---|
| Xアカウント凍結 | **作り直しは規約違反（ban evasion）**。凍結されたら事業が止まる前提で、Bluesky・Threads・Instagram等のサブチャネルを早期に確保しておく |
| ASPアカウント停止 | 1社依存にしない。最低3社を並行して持つ |
| 案件の終了 | X→自社LP→案件の構成なので、**LPの出口を差し替えるだけで済む**。投稿のリンクを張り替える必要がない |
| API単価の改定 | costs テーブルで日次のAPI費用を記録し、Cost Simulatorの予測と実績を毎日突き合わせる |
| ORICO未接続 | 起動時にマウントを確認し、未接続なら**安全停止**（無理に走らせない） |

## 7. 停止スイッチ

`data/HALT` というファイルが存在したら、全バッチが起動直後に停止する。
何かおかしいと感じたとき、人が `touch data/HALT` するだけで全部止まる状態を最初から作る。
