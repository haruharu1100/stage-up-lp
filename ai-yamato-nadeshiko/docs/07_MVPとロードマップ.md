# 設計7: MVP と実装ロードマップ

「全部作ってから動かす」は失敗する。**一番不確実なもの（海外Xで日本文化AI美女が伸びるのか）を最初に試す。**

---

## MVPの定義

> **Suzuho Awanoの画像付き英語投稿を1日3本、手動承認で30日続け、
> 「1万インプレッションあたり何クリック取れるか」を実測する。**

MVPに入れないもの: 動画、多腕バンディット、国別出し分け、8体のAI分離、管理画面のグラフ。
理由: 上の数字が取れないと、それより下流は全部机上の空論になるから。

---

## Phase 0: 土台づくり（実装なし・人が動く）
所要: 3〜5日 / 費用: ドメイン代のみ

- [ ] Xの新規アカウントを作る（Suzuho Awano用）。プロフィールに `AI-generated character` を明記、**Automatedラベルを有効化**、bioに運営者を記載
- [ ] X Developer Portal でアプリを新規作成し、従量課金を有効化。**既存アカウントのキーは流用しない**
- [ ] ドメインを1本取得（例: `yamato-nadeshiko.com` 等）
- [ ] Cloudflareアカウントで API トークンを発行（このPagesプロジェクトに絞ったスコープ）
- [ ] ASP登録: **NordVPN → Klook → GetYourGuide** の順に申請（審査の軽い順）
- [ ] 未確認事項を潰す（`09_確認事項一覧.md` 参照）

**この段階では投稿もLP公開もしない。**

---

## Phase 1: Suzuho Awanoを立てる（1〜2週間 / 追加費用ゼロ）

- [ ] `character_suzuhoawano.json` を作る（`ai-influencer/character.json` を雛形に）
- [ ] 基準顔を1枚生成し、人が最終確認して確定（**ここが全ての土台。妥協しない**）
- [ ] 30〜50枚のバリエーションを生成し、顔一致QAを回して合格率を測る
- [ ] Obsidian `01_CHARACTER/` に プロフィール・英語の話し方・NG表現を確定して記録
- [ ] 実在人物への酷似チェック（画像検索）

**完了条件**: 基準顔から「同一人物に見える画像」が8割以上の確率で出せる。

---

## Phase 2: 手動運用で数字を取る（30日 / 費用: X API 約$5/月）

- [ ] `aura/lib/x/` を移植し、**投稿は人が承認ボタンを押したときだけ**飛ぶ状態にする
- [ ] guard.ts（日次上限・類似連投検知・NGワード・画像必須）を移植
- [ ] 1日3投稿 × 30日 = 90投稿。全部Compliance AIを通してから承認
- [ ] **投稿から30日以内に metrics を毎日DBへ吸い上げるバッチ**を作る（ここだけは自動化必須）
- [ ] 30日後に集計: 1万表示あたりのプロフィールクリック数、フォロワー増加数、伸びた投稿の共通点

**完了条件（次に進む判断基準）**
- 月間インプレッションが 10万を超えている
- 1万表示あたりのプロフィールクリックが 30以上
- → 届かない場合、Phase 3へ進まずコンテンツの型を作り直す

---

## Phase 3: LPと計測をつなぐ（1〜2週間）

- [ ] Cloudflare Pages に LP を作る（**中身のある実体ページ**。リダイレクト専用は禁止）
- [ ] `functions/_middleware.js` で `request.cf.country` を読み、国別に出口を変える
- [ ] クリックID発行 → D1に記録 → ASPのPostbackで成果を受け取る
- [ ] **リンクは本文でなくリプライに置く**投稿フローを実装
- [ ] LPクリック → アフィリクリック → 成約 の3段が全部つながることを実データで確認

**完了条件**: 成約が1件でも計測できる。金額の大小は問わない。「線がつながったか」だけを見る。

---

## Phase 4: 学習ループを入れる（2〜3週間）

- [ ] `fanza-loop/lib/bandit.mjs`（Thompson Sampling）と `learn.mjs` を移植
- [ ] 投稿の「型」を5本定義し、リンクに型IDを埋め込む（`linkWithCh()` 方式）
- [ ] 週次で 型 × 国 × 時間帯 の成績を集計し、配分を自動で寄せる（**新規テスト枠を常に10%以上残す**）
- [ ] 最低サンプル数未満なら結論を出さない制約を実装
- [ ] Obsidian `06_EXPERIMENTS/` と `07_KNOWLEDGE/LEARNINGS.md` への自動追記

---

## Phase 5: 自動化と拡張（伸びてから）

- [ ] `AUTO_X_POST=true` へ段階的に移行（まず「承認済み投稿の予約実行」だけ自動化）
- [ ] 動画（段階2: fal.ai Kling + sync.so + ElevenLabs声クローン）を投入
- [ ] 案件を3社→5社に増やし、国別に出し分け
- [ ] Bluesky / Threads / Instagram へ横展開（X凍結リスクの分散）

---

## 判断ゲート（勝手に次へ進まない）

| ゲート | 進む条件 | 満たさない場合 |
|---|---|---|
| Phase 1→2 | 顔の一貫性8割以上 | キャラ設計をやり直す |
| Phase 2→3 | 月10万インプレッション & 1万表示あたりプロフィールクリック30以上 | コンテンツの型を作り直す |
| Phase 3→4 | 成約が1件以上計測できる | LPか案件を差し替える |
| Phase 4→5 | 月間の利益がプラス | 自動化せず手動のまま改善を続ける |

**利益がマイナスのまま自動化すると、赤字を自動で拡大するだけになる。**
