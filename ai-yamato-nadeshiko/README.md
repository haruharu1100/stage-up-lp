# AI YAMATO NADESHIKO AFFILIATE OS

日本文化をコンセプトにした実写級AI女性キャラクター「Suzuho Awano（粟野 鈴穂）」を1人固定運用し、
英語Xで海外ユーザーを集客 → 自社LP → 国別に最適なアフィリエイト案件へ送客し、
収益データをAIが分析して改善し続けるシステム。

**現在の状態: Phase 0 = PASSED。Phase 1（実装）進行中。**
**本番投稿・ASP申請・本番課金・本番送客は、まだ一度も行っていない。**
`AUTO_X_POST` / `AUTO_AFFILIATE_APPLY` / `AUTO_OFFER_CHANGE` / `AUTO_CONTENT_PUBLISH` は
すべて false 相当（外部へ副作用を出すコードを実装していない）。

## 使うコマンド

```
npm run gate           # ★まずこれ。今どこまで進んでよいかを見る（迷ったら必ずここから）
npm run db:init        # DBを作る（20テーブル）
npm run db:laws        # 法令台帳をDBへ入れる ← これを入れないとCompliance判定が全部 HALT する
npm run identity:check # 名前の状態と商標調査台帳の食い違いを点検する

npm run faces:prompts  # 顔候補8枚の生成定義を ai-influencer/ へ書き出す（名前がLOCKEDのときだけ）
npm run offers:import  # 案件台帳(CSV)を取り込む
npm run offers:rank    # 儲かるか(Offer)と続くか(Survival)で案件を並べる
npm run apply:check    # 申請前チェック13項目を機械で検査する
npm run apply:record   # 申請結果を記録する（PASS/REJECT/追加情報/無反応）
npm run plan:slots     # 30日×3投稿の「枠」を作る（本文は入れない）
npm run plan:week      # 次の7日ぶん21投稿だけを作る（ローリング）
npm run metrics:daily  # 30日以内の全投稿の実績を取る ← 毎日必ず動かす
npm run learn:attributes # 12属性のどれが効いたかを分析する
npm test               # 受入テストを全部走らせる
```

**`metrics:daily` を止めないこと。** X の実績（リンククリック数・プロフィールクリック数）は
投稿から30日で永久に取得できなくなる。取り逃すと後から復元できない。

この2つは**別々に管理する**。名前が確定しても、顔は人が8枚から1枚選ぶまで確定しない。

### 進んでよい順番（`npm run gate` が機械で止める）

後戻りのコストが段違いに違うので、**名前 → 顔 → 投稿**の順にしか進めない。
名前を変えると顔も投稿も全部やり直し、顔を変えると画像が全部やり直しになる。

| # | やること | 誰が |
|---|---|---|
| 1 | 商標・同名調査を実測で埋める（確認日＋出典URL必須） | 人 |
| 2 | 衝突なしを確認して名前を確定する | 人 |
| 3 | 基準顔の候補8枚を生成する | 機械 |
| 4 | 8枚から1枚を基準顔として選ぶ | 人 |
| 5 | 顔一致率を画像から実測する処理を実装する | 機械 |
| 6 | 顔固定の回帰テストを通す（同一人物=PASS / 別人物=FAIL） | 機械 |
| 7 | 第1週21投稿を作り直す | 機械 |
| 8 | 判断・理由・テスト結果を事業Vaultへ保存する | 機械 |

- 判定は `lib/phases.ts` の1か所だけ。**スクリプト側に条件を書き足さない**
  （片方だけ緩い抜け道ができるため）。`faces:prompts` と `plan:week` は
  `requireAllowed()` を呼ぶので、順番を飛ばすと止まる。
- **下書き・テストコード・ドキュメントはいつでも書いてよい。** 後戻りのコストが無いため。
- 調査台帳は用途で3つのゲートに分かれる。**名前の確定を止められるのは NAME_LOCK だけ。**

| ゲート | 項目 | 何を決めるか |
|---|---|---|
| `NAME_LOCK` | 日本商標 / 米国商標 / 英語Web / 日本語Web | その名前を**使ってよいか**（4件とも CLEAR 済み） |
| `ACCOUNT` | X / Instagram / TikTok のID空き | その名前で**世に出られるか**。顔を作る前に見る |
| `EXPANSION` | EU商標 / ドメイン | その地域・商材へ**広げてよいか**（今は不要） |

`ACCOUNT` を顔生成の手前に置いたのは、IDが1つも取れないと分かった時に名前を変える判断が
あり得るから。その時点で顔を作り終えていると顔ごと捨てになる（顔が一番戻れない）。

**SNSのID空き確認は機械にはできない。** 本プロジェクトはスクレイピング禁止・
ブラウザ自動操作禁止・X公式API以外を叩かない。人が目視で確認して台帳へ書く。

### 名前の書き方（使用場所で判定が変わる）

フルネームは検索で本人へ辿り着くために要る。
しかし本文まで機械的に強制すると英文が不自然になり、Xでの反応が落ちる。
だから**場所で分ける**。

| 判定 | 箇所 | 下の名前だけ（例: `Suzuho`）だったら |
|---|---|---|
| `BRAND_IDENTITY_STRICT` | 16箇所（X表示名 / X Bio / サイトtitle・metadata / About / アフィリ申請 / ASPプロフィール / メディアキット / 構造化データ / OG / Character Bible / analytics / キャンペーン名 / 法務開示 / 画像CharacterID / AI内部Identity） | **FAIL**（承認画面に出さない） |
| `CONTENT_NATURAL` | 3箇所（X投稿本文 / Xリプライ / LP本文） | **PASS**。ただし初出の自己紹介でフルネームが1度も無ければ **WARN**（止めない） |

- 別姓・別名への変化（`Suzuho Tanaka` など）は場所を問わず **NAME_COLLISION = BLOCK**。
- 名前は文字列ではなく `lib/identity.ts` の Character Identity Object で持ち回す。
- `identity_status` を書き換えるのは**人**。`npm run identity:check` は食い違いを見つけて止めるだけ。
- 商標調査で確認できなかった項目は `UNKNOWN` のまま残す。「問題なし」に丸めない。

### 基準顔が確定した後の機械QA

顔一致率が低いと「毎日違うAI女性を投稿するアカウント」に見える。
確定後は次を1枚ずつ実測して渡す。**測れなかった項目は合格にしない。**

類似度 0.80 以上 / 髪 0.85 以上 / 顔の形 0.85 以上 / 目 0.85 以上 / 鼻 0.85 以上 /
口 0.85 以上 / 肌の色み 0.80 以上 / 見た目年齢 25歳 ± 4歳

この処理はまだ**作っていない**（順番の5番目）。基準顔が決まるまでは比べる相手がいないため。
