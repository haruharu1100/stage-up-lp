# PILOT 10件入力テンプレート（メルカリ実市場）

用途：`localhost:3910/validation` の入力欄に貼り付ける。
**この10件はデータ集めではなく「どこを自動化するか決めるため」に入れる。**

---

## 1. 貼り付ける中身（1行目はそのまま。2行目以降を10行つくる）

```
確認日時,市場,商品名,ブランド,型番,JAN,カテゴリ,状態,出品価格,商品URL,販売状況,荷物サイズ,発送方法,入力秒数,発見秒数,情報確認秒数,型番確認秒数,状態確認秒数,記入秒数
2026-08-20 10:00,MERCARI,（商品名をそのまま）,,,,スニーカー,未使用に近い,12800,https://jp.mercari.com/item/mXXXXXXXXXX,出品中,,,150,40,30,35,25,20
```

### 絶対のルール

- **分からない項目は空欄。推測で埋めない。**（型番・JAN・サイズ・送料など）
- **測っていない秒数も空欄。0とは書かない。**
  空欄＝未計測として扱われ、集計から外れる。0と書くと「一瞬で終わった」ことになり、
  次に自動化する工程の判断を間違える。
- 最低限これだけは必要：**商品名／出品価格／状態／商品URL／確認日時／入力秒数**

### 状態の書き方（メルカリの表記をそのまま）

新品、未使用に近い、目立った傷や汚れなし、やや傷や汚れあり、傷や汚れあり、全体的に状態が悪い

### 販売状況の書き方

出品中／売り切れ（**売り切れ表示を実際に見たときだけ**）
ページが消えていた場合は「消えた」。**「たぶん売れた」とは書かない。**

---

## 2. 商品の選び方

| カテゴリ | 件数の目安 |
|---|---|
| スニーカー | 2件 |
| ゲーム機 | 2件 |
| カメラ | 2件 |
| 型番付き家電 | 2件 |
| トレカ | 1件 |
| 型番付きブランド品 | 1件 |

**1カテゴリ最大6件まで。**偏ると「このカテゴリだけの結果」になり、判断に使えない。

---

## 3. 時間の測り方

商品1件ごとに、スマホのストップウォッチで工程を区切って測る。

| 工程 | 何をしている時間か |
|---|---|
| 発見秒数 | 商品を探して「これにしよう」と決めるまで |
| 情報確認秒数 | 商品ページの説明・写真を読む時間 |
| 型番確認秒数 | 型番／JANを探して確かめる時間 |
| 状態確認秒数 | 傷・付属品の有無などを確かめる時間 |
| 記入秒数 | 実際に書き写す時間 |
| 入力秒数 | **上記の合計**（これだけは必須） |

きっちり測れなくてよい。**測っていない工程は空欄**にする。

---

## 4. 入力後にやること

```
npm run pilot
```

これだけで下記が全部出る。

- ファネル（観測 → 商品一致 → Route成立 → SHADOW対象 → STRONG BUY）
- Routeにならなかった理由の8分類の内訳
- 取り違え（FALSE MATCH）の件数
- 工程ごとの実測時間と、次に自動化すべき工程TOP3
- 100件へ進む安全条件7項目と、進んでよいかの結論

**10件で必ず一度止まる。100件へは勝手に進まない。**

---

## 5. 入力メモ（気づいたことをここに書く）

入力していて「面倒だった」「分からなかった」ことを、そのまま書き残す。
秒数には出ない詰まりが、次に直す場所になる。

- 例）型番が商品説明の一番下に画像で書いてあり、文字で拾えなかった
- 例）同じ型番でも色違いがあり、どちらか判断できなかった
