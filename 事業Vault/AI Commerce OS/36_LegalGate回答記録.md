# LEGAL GATE 回答記録

> [!important] このノートの役割
> 「**許可を取ること**」が最優先で、コードを書くことではない段階の**唯一の台帳**です。
> 問い合わせの返事や、人が読んだ規約の結果は、**すべてここに追記**します。
> 記録が無い許可は存在しないものとして扱います（＝ `UNKNOWN`）。

> [!danger] 絶対に守ること（3つ）
> 1. **AIは規約を補完しない。** 「書いていない＝可」は禁止（ルール58）。
> 2. **「原則可能ですが事前承認が必要です」は `YES` ではなく `CONDITIONAL`。** 事前承認が完了するまで `LEGAL_GATE = BLOCKED` を維持します。
> 3. **間違っていた記録も消さない。** 訂正は下に追記します（ルール76）。

> **入口でNOなら、その時点で調査終了。残りの規約・API調査に時間を使わない。**
> orosyで13項目を全部読んだ後に審査基準で落ちた失敗を、二度と繰り返さないためのルール。

| 順 | 項目 | 聞くこと |
|---|---|---|
| ① | `ACCOUNT_ELIGIBLE` | 当社の事業形態で会員登録・利用ができるか |
| ② | `MALL_SELLER_ALLOWED` | モール（Amazon・楽天・Yahoo!等）で販売する事業者でも利用できるか |
| ③ | `AMAZON_CENTRIC_ALLOWED` | Amazon中心の事業者でも利用できるか |
| ④ | `REQUIRED_LICENSES_MET` | 法人・古物商など必要な資格を満たしているか |
| ⑤ | `SCREENING_CONDITIONS_KNOWN` | 審査の条件（有無・必要書類・期間・落ちる条件） |
| ⑥ | — | **ここを通ってから** Legal Gate（下の §1 以降）へ進む |

判定は **`PASS` / `FAIL` / `UNKNOWN`**。**1つでもNOなら `FAIL` で打ち切り。**
証拠（原文・出典・確認日）が揃った YES が5つ揃ったときだけ `PASS`。それ以外はすべて `UNKNOWN`。

## 2. 回答が届いたときの手順（6ステップ）

回答メールを貼り付けてもらったら、こちらで必ずこの順に処理します。

1. **回答の原文をそのまま保存**する（要約しない・省略しない）
2. **質問ごとに `YES` / `NO` / `CONDITIONAL` / `UNKNOWN` へ分類**する
3. **条件付きの場合、条件の原文も保存**する
4. **Legal Gate を再計算**する
5. **Connector 候補の順位を更新**する
6. **このノートへ記録**する（確認日／出典／原文／判定／条件／Gate結果／次のAction）

> [!warning] 都合よく読まないための線引き
> - 「原則可能ですが、事前承認が必要です」 → `CONDITIONAL`（`YES` ではない）
> - 「個別にご相談ください」 → `CONDITIONAL`
> - 質問に触れていない・回答が返ってこない → `UNKNOWN`
> - 「禁止とは書いていない」 → `UNKNOWN`
> - 原文・出典・確認日のどれかが欠けた「可」 → 自動的に `UNKNOWN` へ落とす（ルール144）

## 4. `FIRST_LIVE_SUPPLIER` の最低条件（7つ）

最初に自動接続する仕入先は、**順位や過去の点数では決めません**。
下の7つが**すべて満たされた相手だけ**が候補になります。

| # | 条件 | 内容 |
|---|---|---|
| 1 | `COMMERCIAL_USE = YES` | 事業として使ってよい |
| 2 | `INTERNAL_USE = YES` | 社内の仕入判断に使ってよい |
| 3 | `AUTOMATED_RETRIEVAL = YES` | プログラムで自動取得してよい |
| 4 | `DATA_STORAGE = YES` | 取得データを社内に保存してよい |
| 5 | `PRICE_COMPARISON = YES` | 他市場（Amazon等）との価格比較に使ってよい |
| 6 | `PURCHASABLE = YES` | 実際にそこから仕入れられる |
| 7 | `AMAZON_RESALE = YES` **または** 商品単位で機械的に確認できる | Amazonで売ってよいか判定できる |

> [!danger] 通過禁止のルール
> - **重要条件が `UNKNOWN` なら通過禁止。**
> - **`CONDITIONAL` は「可」として数えません。** 条件を安全装置として実装しきるまで `BLOCKED` のままです。
> - **仕入先と情報源を混ぜない。** バリューコマース・Yahoo!・楽天は、Gateを通過しても `MARKET_INTELLIGENCE`（価格の情報源）として接続します。**`FIRST_LIVE_SUPPLIER` にはしません。**
> - ~~現在の仕入先候補は NETSEA と orosy の2社だけです。~~
> - **2026-08-26 更新：orosy が審査基準で不可になったため、仕入先候補は `NETSEA` 1社だけです。**
