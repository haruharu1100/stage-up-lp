## この文書のルール

ユーザー指示21：

> 「たぶん」「できそう」は禁止です。公式情報を確認できないものは、`UNKNOWN` です。

そのため、この文書に書いてある判定はすべて **その市場の公式サイト・公式規約・公式ヘルプ・
公式開発者ドキュメントを実際に開いて読んだ結果** だけを根拠にしている。
個人ブログ・まとめ記事・「〇〇はスクレイピング禁止らしい」といった二次情報は
**根拠として一切採用していない**（実際、そう書いているブログは多数あるが、
規約本文を読むと書かれていない市場があった）。

### 記号の意味

| 記号 | 意味 |
|---|---|
| ✅ | 公式情報で「できる」と確認した |
| ⚠️ | 公式情報で確認したが、条件・審査・契約が必要 |
| ❌ | 公式情報で「できない／禁止」と確認した |
| ❓ | **公式情報を見つけられなかった。「無い」とも「ある」とも言えない** |

### ❓ の読み方（ここを間違えると事故になる）

**❓ は「たぶん大丈夫」ではない。「調べたが分からなかった」である。**

とくに **「規約に禁止と書かれていない」＝「やってよい」ではない**。
多くの市場の規約は「当社が合理的な理由に基づき判断する行為を禁止する」という
包括的な書き方をしており、個別列挙が無いことは許可を意味しない。

したがって本システムでは、**❓ の市場は自動取得の対象にしない**（Fail Closed）。

### いま取るべき行動は「実装」ではなく「問い合わせ」である

コードを書いて解決する問題ではない。**書面で許可を取るところからしか進めない。**
問い合わせ先は3つに絞られる（後述 §5）。

## 2. 市場別の詳細

### 2-1. Amazon（優先順位1）

Amazon は「アフィリエイト側（カタログを読む）」と「出品者側（SP-API）」が完全に別物なので分けて書く。

| # | 項目 | 判定 | 根拠 |
|---|---|---|---|
| 1 | 公式API（一般開発者） | ⚠️ | カタログ取得は **Creators API**（アソシエイト登録が前提） |
| 2 | 法人向けAPI | ⚠️ | **SP-API**。「private seller application の開発には**大口出品（professional selling account）が必須。小口（Individual）は不可**」と明記 |
| 3 | Partner API（審査制） | ⚠️ | 開発者プロファイル審査（500語以内の独自文章）、セキュリティ設問、AUP／DPP／Solution Provider Portal Agreement の順守 |
| 4 | 正式なData Feed | ⚠️ | アソシエイト側の日本語ヘルプに「PA API、データフィード及び将来のAPI」と記載。仕様の中身は未確認。SP-API 側は `JSON_LISTINGS_FEED`（**出品投入用**）を確認 |
| 5 | 正式なCSV提供 | ❓ | Reports API の存在は確認。ファイル形式（CSV/TSV）は確認できず |
| 6 | Webhook | ✅ | **Notifications API v1**。配信先は Amazon EventBridge と Amazon SQS |
| 7 | 法人契約の要否 | ⚠️ | SP-API＝大口出品必須／Creators API＝アソシエイト会員登録必須。「法人格そのものが必要か」は ❓ |
| 8 | 利用条件（具体） | ✅ | Creators API は **「直近30日以内に10件以上の適格販売」** が必要。古物商についての記述は ❓ |
| 9 | 商用利用の可否 | ❓ | License Agreement へのリンクはあるが、規約本文（保存・利用制限を含む）は取得できず |
| 10 | 価格データ取得 | ⚠️ | SP-API **Product Pricing API**（`getCompetitiveSummary` 等）で競合価格・カート価格。ただし対象は「Sellers only」 |
| 11 | SOLD（成約）データ | ⚠️＋❓ | **自社が受けた注文**は Orders API で取得可。**市場全体（他社）の成約データ**を取る公式APIは確認できず＝❓ |
| 12 | 商品ページURL | ❓ | Creators API のリファレンスが**ログイン必須**で確認不能 |
| 13 | 購入API | ❌ | Orders API は注文情報を**取得する**ためのもの。購入・発注機能は無い |
| 14 | 出品API | ✅ | SP-API **Listings Items API** で出品の作成・更新・削除。一括は `JSON_LISTINGS_FEED` |

#### ★今回の最大の発見：PA-API 5.0 は廃止された

公式ページに「The Amazon Product Advertising API 5.0 (PA-API 5) has been deprecated」と明記され、
**旧エンドポイントを呼ぶと HTTP 403 / AccessDeniedException が返る**とサンプル付きで書かれている。
後継は Creators API（OAuth 2.0、エンドポイント `creatorsapi.amazon/catalog/v1/*`）。

> 「Amazon の商品情報は PA-API で取れる」という前提の記事・ライブラリは**すべて古い**。
> 本システムで PA-API を前提にしたコードを書いてはいけない。

#### Amazon のまとめ（非技術者向け）

- 商品カタログを正式に取れる窓口は、事実上 Creators API の一本になった。
  ただし**「直近30日で10件以上の売上（アフィリエイト成果）」という数値条件**が公式に書かれている。
  当社は現在ゼロなので、**入口が閉じている**。
- 出品者側の SP-API は**大口出品契約が必須**。個人（小口）アカウントでは使えないと明記。
- SP-API に「自動で商品を買う」機能は**無い**。あくまで自分が売る側のためのAPI。
- 規約本文（データ保存の可否など）は未確認。契約前に必ず原文を読む必要がある。

- **eBay には日本のマーケットプレイスが無いため、「日本の中古相場」を取る用途には直接使えない。**

#### スニダンのまとめ

- **9市場で唯一、利用規約にスクレイピング禁止が名指しで明記されている。** 自動巡回は完全にアウト。
- 「スニダンBiz」は実在するが、これは**売買するためのプランであってデータをもらうプランではない**。
  API・CSV・データ提供の記載は一切ない。
- 仕入プランの条件（年商1億円以上・月間200万円以上）は、当社の現状では満たせない。
- **この市場は自動化の検討自体を打ち切るべき。**
- なお `lib/venues.ts` では SNKRDUNK を `terms_status: 'BLOCKED'` かつ `can_sell: 1` としてある。
  これは意図的で、「規約で使えないが、使えれば儲かったはずの取り逃し」を画面に残すため。**消さない。**

| 6 | Webhook | ⚠️ | 「Webhookによる注文イベントのリアルタイム受信」がShops APIの機能。パートナー限定 |
| 7 | 法人契約の要否 | ⚠️ | Shops API はソウゾウとのパートナー契約が必要 |
| 8 | 利用条件 | ❓ | パートナー契約の審査基準・売上要件は公開されておらず確認できず |
| 9 | 商用利用の可否 | ❓ | 利用規約 全文を確認したが「商業」「複製」「収集」「アクセス」「インターフェイス」を含む条文は**存在しない** |
| 10 | 価格データ取得 | ❓ | 現在の出品価格を正規に取得する公式手段を確認できず |
| 11 | SOLDデータ取得 | ❓ | 同上 |
| 12 | 商品ページURL取得 | ❓ | 正規手段としては確認できず |
| 13 | 購入API | ❓ | Shops APIの公開機能一覧に購入系の記載なし |
| 14 | 出品API | ⚠️ | Shops APIに「商品の登録、更新、削除、参照」「在庫の登録、更新、参照」あり（パートナー限定）。**メルカリ本体（フリマ）の出品APIは ❓** |

#### ★ここは誤解が多いので詳しく書く

**「メルカリの利用規約にスクレイピング禁止と明記されているか」→ 明記は確認できなかった（❓）。**

- 利用規約 第8条は「弊社は、本サービスに接したユーザー及び第三者の、**ガイドの禁止されている行為**に
  該当すると弊社が合理的な理由に基づき判断する行為…を禁止します」とだけ定め、具体列挙を外部ガイドに委ねている。
- そのリンク先である公式ガイド「禁止されている行為」の全項目を確認したが、
  **クローラー・スクレイピング・自動化ツール・ボットを名指しした項目は掲載されていない**
  （掲載されているのは無在庫・虚偽記載・外部誘導・複数アカウント不正利用などの取引ルール系）。
- 「メルカリはスクレイピング禁止」と述べるブログ・まとめ記事は多数あるが、すべて**二次情報**であり根拠にできない。

**しかし——「規約に明記がない」＝「自動取得してよい」ではない。**
第8条は会社側の判断で包括的に禁止できる構造なので、無断巡回は依然として規約違反と判断されうる。
そして当システムの方針は「規約・API・法令上、自動取得が許可されていない場合は無理に自動化しない」である。
**許可が確認できない以上、やらない。**

## 4. FIRST_LIVE_CONNECTOR の選定（ユーザー指示22）

### 選定結果：**Yahoo!ショッピング 商品検索API（v3）／ただし条件付き・未確定**

#### なぜここか（すべて一次情報ベース）

1. Client ID を取れば使え、**売上実績などの数値ハードルが公式に課されていない**
   （Amazon の「30日で10件」のような条件が無い）。
2. **価格（`hits/price`）と商品URL（`hits/url`）が両方返る**ことが公式リファレンスで確認できた。
   本システムの「購入ページを開く」導線は、実在するURLが取れることが前提。ここを満たす。
3. 日本市場そのものを扱える（eBay には日本マーケットプレイスが無い）。
4. レート制限が公式に明記されている（1クエリー／秒、1日50,000リクエスト）＝守るべき数字がはっきりしている。

#### なぜ他が選ばれなかったか

- **Amazon**：PA-API 5.0 が廃止され Creators API に移行済み。
  「直近30日で適格販売10件以上」という明確な数値条件があるため、
  アフィリエイト実績ゼロの現状では**入口が閉じている**。
  SP-API は大口出品契約が前提で、かつ「自動購入」機能は存在しない。
- **eBay**：成約価格を取る手段が2025年2月に完全廃止、後継は新規受付停止。
  さらに日本マーケットプレイスが無いため、**日本の中古せどり用途には現時点で適合しない**。
- **メルカリ／スニダン／BOOKOFF／HARD OFF／セカンドストリート**：正規手段が無い、
  または規約で明確に禁止されている。
- **KOMEHYO**：入会すれば落札実績が見られるが、**自動取得の可否が公式に書かれていない（❓）**。
  入会金3万円を払ってから「自動取得は不可でした」となるのは避けたい。**先に書面で聞く。**

#### ★この選定は、まだ `CONNECTED` ではない

**必須の前提条件が1つある。**
公式ヘルプが Web API を**「原則 非商用」**と明記しており、
**事業利用の可否を Yahoo! 側の問い合わせ窓口に確認して書面で残す**ことが先決である。
**ここが取れなければ、この案は成立しない。**

設計書 §2.3 で決めた通り、`ConnectorState` を `CONNECTED` にできるのは次の4つが揃ったときだけ：

1. 出典URL
2. 確認日
3. 確認した人
4. 実際に1回以上の取得成功記録（`market_fetch_log`）

現時点の Yahoo!ショッピングは **`APPLICATION_REQUIRED`**（申請が必要）である。

#### 推測である点を明示しておく（ユーザー指示21）

- **「Yahoo が商用利用を許可してくれるかどうか」は推測である。**
  公式には「相談が必要」としか書かれておらず、承認基準・可否は公開されていない。
- **Amazon の Creators API が商品ページURL（`DetailPageURL` 相当）を返すかどうかも未確認（❓）である。**
  リファレンスがログイン必須のため。アソシエイト登録後に実際のレスポンスで確認する必要がある。

## 7. この調査からの学び（ルール化する）

1. **「APIがある」と「使ってよい」は別。** Yahoo は API があるのに原則非商用。
   スニダンは法人プランがあるのにデータ取得は禁止。**両方を別々に確認する。**
2. **廃止されたAPIを前提にした情報が大量に出回っている。**
   PA-API 5.0（Amazon）、Finding API（eBay）、オークションWeb API（ヤフオク!）は
   いずれも**すでに終了している**のに、それを前提にした解説が検索上位に残っている。
   **必ず公式の廃止告知まで確認する。**
3. **規約に禁止と書いていないことを許可の根拠にしない。**
   メルカリ・BOOKOFF本体・セカンドストリートは「スクレイピング」という語を使っていない。
   それでも禁止の根拠は別条項（包括禁止・営利目的利用・私的複製超）にある。
4. **robots.txt を規約と混同しない。** これは検索エンジン向けの技術的意思表示にすぎない。
5. **別サイトの規約を根拠にしない。** BOOKOFF で実際に起きかけた誤読
   （ファンサイトの規約をオンラインストアの規約と取り違える）。
