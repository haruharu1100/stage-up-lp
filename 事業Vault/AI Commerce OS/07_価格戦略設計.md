# 価格戦略設計（Dynamic Pricing）

> 上位文書: [[00_設計書v1_最上位]]（v1.1で追加）
> 関連: [[06_商品大量生成とパイプライン]] / [[03_安全設計と事故防止]]

## 0. この設計の一行まとめ

**「一番高く売る」のではなく「月にいちばん多く稼ぐ価格」を、売れるたびに+5%して探し当てる。**
ただし相場を無視した値上げはしない。上限に当たったら止まる。

---

## 1. 目的関数（何を最大化するのか）

```
最大化する対象 ＝ 月次利益 ＝ 1個あたり純利益 × 月間販売数
```

補助指標として **資金拘束日数あたり利益**（`PROFIT_PER_CAPITAL_DAY`）も見る。

### 具体例
```
価格 120,000円 → 月1個 → 1個利益 30,000円 → 月利益 30,000円
価格 105,000円 → 月4個 → 1個利益 18,000円 → 月利益 72,000円  ← ★AIはこちらを選ぶ
```

> [!danger] 最高価格で売れたことを「成功」と表示しない
> ダッシュボードでも「最高売却価格」を目立たせない。**月次利益と回転日数**を主役にする。
> 指標の見せ方が、そのまま行動を歪める。

## 2. 初期価格（INITIAL_MARKUP）

### 2.1 基本案
```
INITIAL_MARKUP = 15%（管理画面から変更可）
```

### 2.2 ただし「仕入価格 × 1.15」では決めない

```
STEP 1  基準原価を出す
  BASE_COST = 仕入価格 + 送料 + 梱包費 + 鑑定費 + 保管見込 + 返品期待損失 + 広告見込

STEP 2  必要売価（マークアップ案）を出す
  MARKUP_PRICE = BASE_COST × (1 + INITIAL_MARKUP) ÷ (1 − 販売手数料率 − 決済手数料率)
  ※ 手数料は売価に掛かるので、割り戻さないと利益が足りなくなる（よくある事故）

STEP 3  最低売価（絶対に割ってはいけない線）を出す
  MIN_PRICE = 純利益が MIN_PROFIT_JPY かつ MIN_ROI を満たす売価

STEP 4  相場から上限・下限を出す
  MARKET_MEDIAN     = 過去成約価格の中央値（同じ状態ランク・同じサイズで）
  COMPETITOR_LOWEST = 現在の競合最安値
  MARKET_CEILING    = MARKET_MEDIAN × (1 + MAX_MARKET_PREMIUM)

STEP 5  初期価格を決める
  INITIAL_PRICE = clamp(MARKUP_PRICE, 下限 = MIN_PRICE, 上限 = min(MARKET_CEILING, MAX_PRICE))

STEP 6  検証
  もし MIN_PRICE > MARKET_CEILING なら
    → この商品は「相場では利益が出ない」 → SKIPPED（LOW_PROFIT）
    → ★ここで無理に出品しない
```

### 2.3 設定値

| 設定 | 既定 | 意味 |
|---|---|---|
| `INITIAL_MARKUP` | 15% | 基準原価に対する上乗せ |
| `MIN_PROFIT_JPY` | 3,000円 | 1個あたり最低純利益 |
| `MIN_ROI` | 10% | 最低ROI |
| `MAX_MARKET_PREMIUM` | 10% | 相場中央値からどれだけ上に出していいか |
| `MAX_PRICE` | 商品別 | 絶対上限（未設定可） |
| `MIN_EXPECTED_SALES_PROBABILITY` | 60% | この確率を割る価格は付けない |

> [!warning] 相場データが無い商品に初期価格を付けない
> `MARKET_MEDIAN` が無い＝売れる保証が無い。`NO_MARKET_DATA` で SKIPPED にする。
> 「とりあえず1.15倍で出す」を許すと、売れない在庫が大量生成される。

## 3. 5%ステップアップ（Step-Up Pricing）

### 3.1 基本ルール
```
売れた → 次回価格 = 現在価格 × (1 + PRICE_STEP_UP)     PRICE_STEP_UP = 5%（変更可）
```
```
100,000 → 売れた → 105,000 → 売れた → 110,250 → 売れた → 115,762 → 売れなかった
```
「想定より早く売れた＝安すぎた可能性」を、実験で確かめる仕組み。

### 3.2 ★最初に整理すべき前提：中古の一点物には「次回価格」が無い

> [!danger] ここを間違えると設計が破綻する
> KOMEHYO等のブランド中古は基本 **一点物**。同じ現物は二度と入らない。
> **「その商品の次回価格」は存在しない。**

そこで、価格の学習単位を **3層** に分ける。

| 層 | 学習単位 | 対象 | ステップアップの適用 |
|---|---|---|---|
| **A. SKU層** | 同一型番・同一状態 | スニーカー、トレカ、新品、再仕入可能な商品 | ✅ そのまま適用 |
| **B. モデル層** | ブランド × 型番シリーズ × 状態ランク | 同型番だが個体差がある中古 | ✅ 適用（状態補正を掛ける） |
| **C. セグメント層** | ブランド × カテゴリ × 価格帯 × 状態ランク | **一点物**（一点ごとに違う中古） | ⚠️ 個別価格ではなく **「相場中央値に対する倍率」** を学習 |

### 3.3 一点物での実際の学習内容（C層）
一点物では「105,000円が最適」ではなく、**「相場中央値の何％で出すのが最も儲かるか」** を学習する。

```
学習する値：PREMIUM_RATIO = 出品価格 ÷ 相場中央値

例：ルイヴィトン × ショルダーバッグ × 10〜15万円帯 × 状態A
   PREMIUM_RATIO 0.98 → 平均9日で売却  月次利益指数 100
   PREMIUM_RATIO 1.03 → 平均14日で売却 月次利益指数 118  ← ★最適
   PREMIUM_RATIO 1.08 → 平均31日で売却 月次利益指数 84
   PREMIUM_RATIO 1.13 → 60日で売れず   月次利益指数 12
```

→ このセグメントの次の商品は **相場中央値 × 1.03** から出す。
これが「一点物でも価格を学習する」方法。

**+5%ステップアップは、この `PREMIUM_RATIO` に対して適用する。**
（該当セグメントで売れるたびに `PREMIUM_RATIO` を +5% 相当ずつ上げて探索する）

## 4. 値上げ前チェック（無限値上げの防止）

**売れたから上げる、ではない。上げてよいか毎回確かめる。**

### 4.1 チェック項目（1つでも落ちたら値上げしない）

| # | 確認項目 | 条件 |
|---|---|---|
| 1 | 現在市場相場 | 新価格 <= `MARKET_MEDIAN × (1 + MAX_MARKET_PREMIUM)` |
| 2 | 競合最安値 | 新価格が競合最安を大きく超えない（既定：+8%以内） |
| 3 | 過去成約価格 | 新価格 <= 直近90日の成約価格の上位25%点（P75） |
| 4 | 売却速度 | 直近の平均売却日数 <= `TARGET_DAYS_TO_SELL`（既定30日） |
| 5 | 閲覧数 | 出品あたり閲覧数が前回以上（取得できる販路のみ） |
| 6 | お気に入り数 | 需要のサイン。減っていたら上げない |
| 7 | 在庫数 | 自社在庫が2個以上（1個しかないなら実験より確実に売る） |
| 8 | 仕入可能数 | **再仕入できる見込みがある**（無いなら実験の意味が薄い） |
| 9 | 売却確率 | 新価格での予測売却確率 >= `MIN_EXPECTED_SALES_PROBABILITY` |
| 10 | 絶対上限 | 新価格 <= `MAX_PRICE` |
| 11 | サンプル数 | 直前の価格で **`MIN_SALES_PER_STEP` 件以上売れた**（既定2件） |
| 12 | 相場の動き | 相場自体が下落中でない（下落中の値上げは自殺行為） |

### 4.2 設定値

| 設定 | 既定 | 意味 |
|---|---|---|
| `PRICE_STEP_UP` | 5% | 1回の値上げ幅 |
| `MAX_MARKET_PREMIUM` | 10% | 相場中央値からの上振れ上限 |
| `MAX_PRICE` | 商品別 | 絶対上限 |
| `MIN_EXPECTED_SALES_PROBABILITY` | 60% | 30日以内売却確率の下限 |
| `MIN_SALES_PER_STEP` | 2件 | 1段階上げるのに必要な販売実績 |
| `MAX_STEP_UPS` | 6回 | 連続値上げの上限（暴走防止） |
| `TARGET_DAYS_TO_SELL` | 30日 | 目標売却日数 |

> [!warning] 1件売れただけで値上げしない
> 1件は偶然。既定で **2件以上**の実績を求める。
> 高額・低回転の商品では `MIN_SALES_PER_STEP` を上げる（設定は商品セグメント別に持てるようにする）。

### 4.3 AIの最終判断
上記チェックを全部通ったうえで、Judge が「+5%しても十分売れる」と判断した場合のみ上げる。
判断理由は必ず `ai_decisions` に記録する。

## 5. 値下げ（ステップダウン）

値上げだけでは片手落ち。**売れなくなったら戻す。**

```
条件：在庫日数 > STEP_DOWN_AFTER_DAYS（既定14日）かつ 閲覧数が伸びていない
  → 価格 = 直前に売れた価格（＝最後に成功した価格）へ戻す
  → それでも売れなければ 損切りAIの再評価スケジュール（7/14/30/60/90日）へ
```

**絶対条件：`listings.min_price_jpy`（赤字ライン）を下回る値下げは、実行層が拒否する。**
（[[03_安全設計と事故防止]] §2 の権限表：赤字ライン下の値下げは admin の二段階確認のみ）

## 6. 価格ABテストと価格弾力性の学習

### 6.1 何を学習するのか
**価格を変えると販売数がどう変わるか**（＝価格弾力性）を、実データから曲線として持つ。

```
価格帯       販売数/月   1個利益    月次利益     売却日数
 98,000円      6個      13,000円    78,000円      5日
105,000円      4個      18,000円    72,000円      9日
110,250円      3個      22,000円    66,000円     14日
115,762円      0個         —            0円      売れず
```
→ **最適は 98,000〜105,000円付近**。この曲線を保存する。

### 6.2 保存の粒度（[[01_DB設計案]] の `price_elasticity`）
| 粒度 | キー | 用途 |
|---|---|---|
| 商品（SKU） | `product_id` | 再仕入可能な商品 |
| モデル | `brand + model_series + condition` | 同型番の中古 |
| **セグメント** | `brand + category + price_band + condition` | **一点物**（PREMIUM_RATIO で学習） |
| 販路別 | 上記 × `marketplace_id` | 販路で最適価格は違う |

**サンプルが足りない粒度は、上位の粒度にフォールバックする。**
（SKUで5件しかない → モデル層を見る → それも足りない → セグメント層を見る）

### 6.3 統計の作法（ここを雑にすると学習が嘘になる）

| 罠 | 対策 |
|---|---|
| サンプルが少なすぎる | 既定 **各価格帯5件以上**。足りなければ「学習中」と表示して適用しない |
| 季節・トレンドの影響 | 同時期の**相場中央値で割った比率**で見る（絶対額で見ない） |
| 状態ランクの違い | 状態を必ず粒度に含める |
| 写真・説明文の質の違い | 出品品質フラグを持ち、大きく違うものは比較から除外 |
| 販路の違い | 販路をまたいで混ぜない |
| 「売れなかった」の扱い | 打ち切りデータとして扱う。**「0個売れた」を単純に平均へ入れない** |
| たまたま良い時期だった | 判定は最低4週間の観測期間を置く |

### 6.4 探索と活用のバランス
全在庫で値上げ実験をすると、その間の売上が落ちる。

```
在庫の 80% → 学習済みの最適価格で出す（活用）
在庫の 20% → ステップアップ実験に回す（探索）   EXPLORE_RATIO = 20%（変更可）
```

- 高額・低回転の商品は探索比率を下げる（失敗コストが大きい）
- 低額・高回転の商品は探索比率を上げる（早く学べる）
- **学習が十分に進んだセグメントは探索を減らす**

## 7. 価格決定の全体フロー

```
出品時／再評価時
  ↓
① セグメントを特定（SKU → モデル → セグメントの順にフォールバック）
  ↓
② 価格弾力性データはあるか？
   YES → 月次利益が最大になる価格を採用
   NO  → INITIAL_MARKUP（+15%）で初期価格を算出
  ↓
③ 探索対象か？（EXPLORE_RATIO の抽選）
   YES → ステップアップ候補価格を採用
  ↓
④ ガードを通す
   MIN_PRICE（赤字ライン）    … 下回ったら引き上げ
   MARKET_CEILING             … 超えたら引き下げ
   MAX_PRICE                  … 超えたら引き下げ
   MIN_EXPECTED_SALES_PROBABILITY … 割ったら引き下げ
  ↓
⑤ 販路別に最適価格を出し、最も月次利益が高い販路を選ぶ
  ↓
⑥ 決定価格・根拠・実験ID を price_experiments に記録
  ↓
⑦ Action Gate 経由で出品／価格変更
```

現在価格        110,250円

競合最安        104,800円
推奨価格        105,000円 ★

 98,000円  →  6個売れた（平均 5日）  月次利益 78,000円
105,000円  →  4個売れた（平均 9日）  月次利益 72,000円

115,762円  →  0個（21日経過）        月次利益      0円

## 9. 安全ルール（価格関連）

1. **赤字ラインを下回る価格は実行層が拒否する。**（AIも運用者も変更不可。adminの二段階確認のみ）
2. **相場データが無い商品に価格を付けない。**
3. **1件の販売実績で値上げしない**（既定2件以上）。
4. **連続値上げは `MAX_STEP_UPS`（既定6回）まで。**
5. **相場が下落局面のときは値上げしない。**
6. **在庫1個の商品では価格実験をしない**（確実に売る）。
7. **サンプル不足の弾力性データを適用しない**（「学習中」と表示する）。
8. **価格変更も Action Gate を通す**（監査ログに残す）。
9. **値上げの自動実行はモード依存**。SAFEでは提案のみ。
10. **1日の価格変更件数に上限を設ける**（既定100件。暴走検知）。

## 10. Phase 対応

| 機能 | Phase |
|---|---|
| 初期価格（INITIAL_MARKUP + 各種ガード） | **Phase 1**（利益計算と同時に作る） |
| 価格実験の記録（`price_experiments`） | **Phase 3**（SHADOWと同時に記録開始） |
| ステップアップの提案（人間が実行） | **Phase 4** |
| ステップアップの自動実行 | **Phase 5**（SEMI AUTO） |
| 価格弾力性カーブの学習と適用 | **Phase 7** |

> [!important] 記録は早く、自動化は遅く
> 弾力性の学習にはデータが要る。**Phase 3 の時点から価格と結果を記録し始める。**
> 自動で値上げするのは、データが溜まった後でよい。
