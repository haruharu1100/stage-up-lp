# 本物の案件をどう入れて、どう順位を付けるか

> 練習用（TEST）の案件は、本物として1件も数えません。数を揃えるために基準を下げることもしません。
>
> 最終更新: 2026-08-31 ／ 自動生成（`npm run obsidian:sync`）。手で書き足した内容は次回の実行で消えます。

## いまの数

| 種別 | 件数 |
| --- | --- |
| 本物（REAL）の案件 | **0件** |
| 練習用（TEST）の案件 | 100件 |
| 正式TOP5に切り替わる件数 | 20件 |
| いまの表示 | **暫定TOP5（暫定：REAL案件0件中）** |

## ★暫定TOP5と正式TOP5（言い方を1か所に固定する）

本物の案件が20件そろうまでは、いくら点数が高くても **「暫定TOP5」** と書きます。
見出しの横には必ず **「暫定：REAL案件◯件中」** を添えます。20件以上そろったら **「正式TOP5」** に変わります。

- **20件未満でも止めません。**入っているぶんだけで並べて、暫定として出します。
- **件数を揃えるために基準は下げません。**足りないときは「あと何件足りないか」をそのまま画面に書きます。
- この言い回しは `lib/jobs/stage.ts` の1か所だけで作ります。
  トップ画面・案件TOP5の資料・取り込み後のメッセージの3か所に同じ5件が出るので、
  3か所で別々に「20件以上か」を書くと必ずどこかが古いまま残り、
  **暫定の順位を正式だと思った人が1件目を出してしまいます。**

## 入れ方（スマホから貼るだけ）

管理画面の「案件を貼る」に、案件ページの本文や求人メールの本文を**そのまま貼る**だけです。
報酬や納期が読み取れなくても構いません。**分からない欄は空のままにします。0円とは入れません。**

貼って1回押すと、ここまで自動で進みます。

1. 保存
2. 重複していないかの判定
3. 案件の解析（何をする仕事か・報酬・納期）
4. HARD BLOCK（1日8時間拘束・常駐・出社必須・正社員 などを外す）
5. 自社の能力と照らし合わせ
6. 利益の分析
7. 応募文の作成
8. 規約の判定

そのうえで、本物の案件が20件を超えていれば、自動で順位付けと別AIの監査まで走ります。

> **押しても応募は送られません。**送る処理コードがこのシステムに存在しないためです。

## 入力元の種類

| 記号 | 意味 |
| --- | --- |
| REAL_EMAIL_ALERT | 本人に届いた求人通知メール |
| REAL_MANUAL | 手で貼った案件 |
| REAL_CSV | CSVでまとめて入れた案件 |
| REAL_REFERRAL | 紹介でもらった案件 |
| REAL_OFFICIAL_API | 公式APIから取った案件 |

規約に反するサイトの機械収集は行いません。求人以外のメールは案件にしません。

## ★知らないサイトの案件を捨てない（ただし規約は未確認のまま）

以前は、貼られたURLのドメインが規約台帳に無いというだけで、その案件を丸ごと捨てていました。
外で見つけた本物の案件が、貼った瞬間に消えるほうが実際には困るので、いまはこうします。

1. 台帳にドメインの行だけを作る（`auto_registered = 1`）
2. **規約の判定は全部「分からない（UNKNOWN）」のまま**にする。引用も確認日も勝手に書かない
3. 案件そのものは残る

**「分からない」は「安全」という意味ではありません。**
分からないサイトの案件は、点数がいくら高くても「人が読む」に回り、**応募する5件には入りません**。
規約台帳の画面には「自動で足りた行（未読）」として件数を出し、放置して溜まらないようにします。

人が規約を読んで記録した行を、機械が上書きすることはありません。
上書きすると「なぜ応募してよいと判断したか」の根拠が消えるためです。

動作確認のために架空のURLを貼ってしまったときは、`npx tsx scripts/jobs-delete.ts <案件番号>` で案件を消し、
`npx tsx scripts/sites-forget.ts <サイトコード>` で自動で足した行を消します。
**動作確認用の案件を本物として数えたままにしません。**

## 順位の付け方（10個の指標）

報酬 ／ 予想利益 ／ 予想作業時間 ／ 時給換算 ／ 受注確率 ／ AI自動化率 ／ 能力の仕上がり ／ 依頼主の危なさ ／ 手直しの起きやすさ ／ 規約の判定

- 出せない数字は**0で埋めません**。「出せない理由」を書きます。
- 上位10件は、応募文を書いたAIとは**別のAI**が監査します。
- 監査の結果は PASS ／ REWRITE ／ HUMAN_REVIEW ／ BLOCK の4つ。
  REWRITE は自動で直してもう一度監査にかけます。
- 監査に合格したものだけが「最初に応募する5案件」に出ます。
- 監査前の順位は「仮の順位」と画面にはっきり書きます。仮を確定と読み違えないようにするためです。
