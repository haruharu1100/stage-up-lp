## この表の読み方

- 「要用意」は、鍵を入れる・契約する・住所を書く、といった作業で終わります。
- 「要判断」は、作業では終わりません。作るか作らないかを人が決める項目です。
  いちばん重い「実行する処理そのもの」は全ての操作で「要判断」に固定してあります。
  ここを黙って埋めることはしません。

## おすすめの順番

1. 会社データは**鍵が無くても集まります**。国税庁が誰でもダウンロードできる形で配っている全件データを使うためです。
   `npm run companies:official` で会社を取り込み、`npm run companies:corpnum` で法人番号を国のデータと突き合わせます。
   **gBizINFO** と **法人番号Web-API** の鍵は、あとから差分を速く更新するための補助です。無いあいだは「鍵待ち（KEY_WAITING）」として、その機能だけを止めます。
   鍵が無いことを理由に、法人営業そのものを止めることはしません。
2. `npm run companies:verify` でHPの照合結果を見る。
3. 承認画面で、実際に送る文面を人が読む。**この時点ではまだ送りません。**
4. 1件目に選ぶ操作を**1つだけ**決める。問い合わせフォームを選ぶ場合は、**そのフォーム自身が営業目的の送信を受け付けているか**を先に読みます。「営業お断り」と書かれたフォームは非常に多く、書かれていなければ「分からない」として人が見て決めます。同意が要らないから無難、という考え方は取りません。
5. その1つについてだけ、実行する処理を作る。作る前に「誰に・何通・どの文面で」を紙に書いてから着手する。
