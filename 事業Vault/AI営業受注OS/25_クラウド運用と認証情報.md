# クラウド運用・認証情報の扱い・セキュリティ点検

> このページに、パスワード・APIキー・DB接続情報そのものは一切書きません。書き方の決まりと点検結果だけを書きます。
>
> 最終更新: 2026-08-31 ／ 自動生成（`npm run obsidian:sync`）。手で書き足した内容は次回の実行で消えます。

## いまの構成

| 役割 | 置き場所 |
| --- | --- |
| 画面（管理画面） | Vercel |
| データベース | Turso（クラウド） |
| 画面のパスワード | Vercelの環境変数だけ |
| 外部サービスの鍵 | Vercelの環境変数と、手元の `.env` だけ |

## 認証情報の決まりごと（例外なし）

1. パスワード・APIキー・DB接続情報を、**コードに書かない**。
2. **Gitに入れない**（`.env` は追跡しない。履歴にも残さない）。
3. **Obsidianに書かない**。同期先が増えるため、出た瞬間に取り消せない。
4. **ログに出さない**。画面にも出さない。
5. **AIの報告本文に書かない**。チャットに1度でも出た値は、その時点で寿命が終わったものとして扱い、作り直す。
6. 置いてよいのは、Vercelの環境変数（と手元の `.env`）**だけ**。
7. 一度どこかに出た値は、**必ず作り直す**。「たぶん大丈夫」で使い続けない。

## 画面を守る仕組み

- 管理画面全体にパスワードの関門を置いています。
- **失敗したときは通します、ではなく止めます**（fail-closed）。
  設定が読めない・比較でエラーが出た、という場合も「通さない」に倒します。
- 検索エンジンに載せません。
  - ページ側で「載せない」指定（`robots: noindex, nofollow`）
  - サーバー側の応答ヘッダでも「載せない」指定（`X-Robots-Tag: noindex, nofollow`）
  - `robots.txt` でも全ページを拒否
  - 3か所で重ねているのは、1か所の書き忘れで公開されるのを防ぐためです。

## 点検の観点（毎回この順で見る）

1. 認証情報がGitの履歴に無いか
2. 認証情報がObsidianに無いか
3. 認証情報がログに無いか
4. APIキーがブラウザへ送られるファイルに混ざっていないか
5. DB接続情報がブラウザへ送られていないか
6. パスワードの関門が、失敗時に「止まる」側へ倒れているか
7. 検索エンジンに載らない設定が効いているか
8. エラーの記録に、会社の電話番号・メールアドレス・担当者名が出ていないか

## Obsidianへ書き出す前の自動検査

`npm run obsidian:sync` は、書き出す直前に文字列を検査します。
メールアドレス・電話番号・APIキーらしき文字列が混ざっていたら、**書かずに止まります**。
「気をつける」ではなく、機械で止めます。
