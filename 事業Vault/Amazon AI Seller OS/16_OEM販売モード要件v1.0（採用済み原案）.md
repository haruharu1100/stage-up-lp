## 2. 【B】既存仕様を優先し、原案で上書きしなかったもの

> ここが一番重要。**要件書のほうが単純だからといって、検証済みの安全仕様を下げない。**

| 原案の記述 | 既存仕様（こちらが優先） | 理由 |
|---|---|---|
| 目標ACOS 20%以下 | **BALANCED GROWTH MODE が上位ルール**。最重要指標は ACOS ではなく **NET PROFIT AFTER ADS（広告後純利益）** | ACOSだけ下げると「黒字だが売れない」失敗になる。売れている×利益も残る、の両立が正解 |
| 広告自動運用ルール（入札増減・停止） | **`AD_AUTO_OPTIMIZE=false` は変更しない**。AIは提案までで、変更は人間承認 | 既存の絶対ルール |
| SNS自動投稿 | **`AMAZON_AUTO_PUBLISH=false` / 投稿前に人間承認**は変更しない | 既存の絶対ルール |
| 発注機能 | **`AUTO_PURCHASE=false` / `AUTO_REORDER=false` は変更しない** | 既存の絶対ルール |
| 「画像検索等によって特定する」 | **非公式APIや規約違反スクレイピングは禁止**。公式APIのみ | 既存の絶対ルール |

| A/B/C/D ランク（既存） | 互換性を残す。**OEMモードでは S/A/B/C を表示**、既存モードは A/B/C/D のまま | 既存データを壊さない |

| Amazon手数料・利益計算 | **既存のAmazon手数料Providerと利益ロジックは変更しない** | 既存の絶対ルール |
| 送料・MOQ・重量がUNKNOWNの商品 | **Aランク禁止**（B または要確認）。商品URLが確認できない商品もAランク禁止 | 既存の絶対ルール |

## 3. 【C】不採用・修正した箇所（原案の誤り／固定しすぎ）

### ① 仕入先を「1688＋Alibaba.com」に固定 → **不採用**

原案は仕入先を2サイトに固定しているが、**実際にAPIを監査した結果、現時点でこの2つを自動Discoveryの本命に固定するのは適切ではない**。

実装は **SupplierDiscoveryProvider 構造を維持**する。

```
SupplierDiscoveryProvider
  ├ AliExpress        ← 現在の本命（審査中）
  ├ 1688
  ├ Alibaba
  ├ 中国輸入代行
  ├ Google Sheets
  ├ CSV
  └ 将来の別仕入先
```

**DOCUMENTED → AUTHORIZED → CONNECTED → VERIFIED を実際に通った仕入先だけ LIVE 利用する。**
要件書に名前が書いてあることは、実装完了の根拠にならない。

### ② 「利益率27%」の例示 → **不採用（原案内の矛盾）**

原案は基本条件を「利益率30%以上」としながら、第37章の最終ゴール例で「利益率27%」の商品を合格例として挙げている。
**30%以上が正式基準**。27%は原案の記述ミスとして採用しない。

### ③ 「1688／Alibaba発注処理」 → **保留**

発注APIも同じ4段階ゲートの対象。VERIFIEDを通るまで発注連携は作らない。
それまでは「発注承認までシステム、実発注は人間」の運用とする。

## 5. 原案全文（2026-08-24 受領時のまま・書き換え禁止）

### 1. システムの目的
Amazon.co.jpで販売されているOEM・ノーブランド系商品を自動的にリサーチし、1688およびAlibaba.comから同一・類似商品の仕入候補を画像検索等によって特定する。Amazonでの販売需要、競合状況、レビュー数、推定販売数量、販売価格、仕入価格、FBA手数料、広告費、物流費等を総合的に計算し、自社の仕入基準を満たす商品のみを抽出する。仕入承認後は発注管理、Amazon FBA販売、Amazon広告運用、X・Instagramでの商品PRまでを一元管理する。

### 2. 対象マーケット
Amazon.co.jpのみ。海外Amazonには対応しない。将来Amazon.com等へ展開できるよう、マーケットプレイスを追加できる構造とする。

### 3. 仕入先（原案）
1688 と Alibaba.com。両方に候補がある場合は比較し、最も条件が良いサプライヤーを表示する。
比較項目：商品単価（数量別単価含む）／MOQ／送料（中国国内・国際）／OEM対応可否／サプライヤー評価・販売実績・取引条件／納期・仕様・サイズ・素材・セット内容。

### 4. Amazon販売方式
Amazon FBAのみ。利益計算はFBA前提。計算対象＝Amazon販売手数料、FBA配送代行手数料、FBA保管料、FBA納品送料、その他Amazon関連費用。

### 5. 商品リサーチ価格帯
Amazon販売価格 1,000円〜15,000円。初期設定値として使用し、管理画面から変更可能とする。

### 6. 商品レビュー基準
50件以上〜1,000件以下。理由＝レビューが極端に少ないと需要確認が難しく、多すぎると既存競合が強く新規参入難易度が高い可能性があるため。レビュー条件のみで完全除外せず、管理画面から条件変更または例外表示できること。

### 7. 月間販売数量基準
最低推定販売数量 月間100個以上。100個未満は原則除外。高単価・高利益商品等は例外判定可能な構造とする。

### 8. 競合商品販売数
正確な販売数量が取れない場合は複数データから推定する（BSR／「過去1か月で○点以上購入」表示／レビュー増加数／レビュー数／価格推移／BSR推移／外部Amazon分析サービス・API／システム内蓄積データ）。自社商品はAmazonの実販売データを使用する。
出力例：推定月間販売数650個／推定レンジ500〜800個／推定信頼度 A・B・C。

### 9. 最低利益条件
1商品当たり利益 500円以上／利益率 30%以上／ROI 20%以上／推定月間販売数量 100個以上／レビュー数 50〜1,000件。

### 10. 利益計算に入れる費用
販売価格、商品仕入原価、中国国内送料、国際送料、関税、輸入消費税、検品費、OEM加工費、パッケージ費、ラベル費、日本国内送料、FBA納品送料、Amazon販売手数料、FBA手数料、Amazon広告費、想定返品・不良コスト。

### 11. 利益率計算
利益 ÷ Amazon販売価格 × 100。最低30%以上。

### 12. ROI計算
利益 ÷ 投下原価 × 100。最低20%以上。投下原価に何を含めるかは管理画面から設定可能とする。

### 13. 商品判定ランク
- **S**：利益条件を大きく上回り、販売需要・競合・仕入条件も優秀。積極的に仕入検討。
- **A**：自社基準をすべて満たす。仕入候補。
- **B**：一部条件未達または情報不足。人間による確認が必要。
- **C**：最低利益基準未達またはリスクが高い。原則仕入対象外。

### 14. 商品総合評価（0〜100点・配点は管理画面から変更可）
利益性30／販売需要25／競合状況15／仕入安定性10／レビュー参入難易度10／広告適性5／商品リスク5。

### 15. 同一商品判定
Amazon商品画像から候補を検索し、画像・名称・サイズ・素材・重量・カラー・仕様・セット内容を比較。AIまたは画像類似検索で同一商品可能性 0〜100% を算出。初期基準として80%以上を仕入候補として表示する。

### 16. 発注機能
実発注までシステム対象。ただし**完全自動発注は禁止**。発注前に必ず管理者承認を必要とする。
フロー：商品発見 → 利益計算 → 仕入候補 → 人間確認 → 発注承認 → 発注処理。

### 17. 発注承認画面（1画面で確認）
Amazon商品画像／Amazon商品URL／Amazon販売価格／推定月間販売数／レビュー／BSR／仕入商品画像／仕入URL／サプライヤー／仕入単価／MOQ／発注数量／商品代金／想定送料／想定総原価／1個利益／利益率／ROI／月間利益予測／商品リスク／AI分析。ボタン＝発注承認／保留／却下。

### 18. Amazon広告
目標ACOS 20%以下。Amazon Ads API等で広告費・広告売上・注文数・ACOS・ROAS・CPC・CTR・CVR・インプレッション・クリック・検索語句・キーワード・ターゲットASINを取得する。

### 19. 広告最適化基準（管理画面から変更可）
ACOS 10%＝拡大候補／15%＝良好／20%＝目標範囲内／25%＝改善対象／30%以上＝入札調整または停止候補。

### 20. 広告自動運用ルール例
| 区分 | 条件 | アクション |
|---|---|---|
| 高成果キーワード | 注文3件以上 かつ ACOS15%以下 | 入札10%増額候補 |
| 目標範囲 | ACOS15〜20% | 現状維持 |
| 要改善 | ACOS20〜30% | 入札10〜20%減額候補 |
| 赤字キーワード | 一定クリック以上 かつ 注文0 | 停止候補 |
| 大幅赤字 | ACOS30%以上 | 停止または大幅減額候補 |

### 21〜24. SNS
対象＝X と Instagram。新商品の販売開始後にPR投稿。基本頻度＝1商品につき週2投稿（管理画面から変更可）。
AIが自動生成する内容＝新商品紹介／メリット／使用シーン／商品特徴／他商品との違い／FAQ／販促文／キャッチコピー／ハッシュタグ。**同一内容の単純転載はせず、媒体ごとに最適化する。**
スケジュール例＝月曜:商品紹介／木曜:使用メリット・使用シーン／翌週月曜:特徴・差別化／翌週木曜:FAQまたは使い方。

### 25. Amazon商品画像6枚作成・コンプライアンス確認
仕入後、Amazon商品ページ用の画像を合計6枚作成する。Amazonの画像要件およびカテゴリー別スタイルガイドを遵守し、規約違反の可能性がある画像は自動登録しない。
作成タイミング＝仕入候補が承認され、商品仕様・同梱物・JAN等が確定した後。
入力＝仕入先商品画像、サプライヤー提供画像、サンプル撮影画像、商品仕様、同梱物、サイズ、カラー、素材、訴求ポイント。
出力＝Amazon登録可能な画像（初期はJPEG、必要に応じPNG）。生成後は**必ず人間が確認・承認**してから登録する。

**25-1. 6枚の内訳**
| 画像 | 目的 | 主な要件 |
|---|---|---|
| 1枚目：メイン | 検索結果・詳細ページの代表画像 | 白背景、販売商品のみ、商品が画像領域の大部分、文字・ロゴ・透かし・装飾なし |
| 2枚目：別角度 | 形状・質感を補足 | 商品を正確に示し、誤認を招く加工をしない |
| 3枚目：サイズ・仕様 | サイズ・素材・セット内容 | 商品内容と一致する情報のみ。虚偽・誇張なし |
| 4枚目：使用シーン | 利用イメージ | 同梱されない小物で誤解を与えない |
| 5枚目：特徴訴求 | 差別化ポイント | 薬機法・景表法・知財・Amazonポリシーに抵触しない |
| 6枚目：比較・補足 | 不安解消、FAQ、セット内容 | 競合を誹謗せず、根拠のないNo.1表記・保証表現を使わない |

**25-2. コンプライアンスチェック（最低限）**
メイン画像は実際の商品を正確に示す／白背景を基本とし不要な小物・背景・装飾を入れない／商品に含まれないアクセサリー・誤解を与える小物・文字・ロゴ・透かし・枠線・カラーブロック・挿入画像を入れない／商品が画像領域の大部分を占める／不鮮明・ピクセル化・ギザギザ加工を使わない／販売商品・同梱物・仕様と一致／サブ画像の説明文も虚偽・誇張・根拠不明を避ける／商標・著作権・意匠権・キャラクター・ブランドロゴの知財リスクを確認／薬機法・景表法・食品表示・電波法・PSE等のカテゴリー別法令リスクを確認／登録前に人間承認を必須とする。Amazon側の規約が変わったらチェック条件を更新できる構造にする。

**25-3. 画像作成フロー**
仕入商品情報の確定 → サプライヤー画像・サンプル撮影画像の取り込み → 仕様・同梱物・訴求ポイントの整理 → メイン1枚＋サブ5枚の生成案作成 → Amazon画像要件チェック → 知財・法令・誇大表現チェック → NG画像の自動差し戻し → 人間による確認・修正指示 → 承認済み画像のみAmazon登録候補として保存。

**25-4. 画像承認画面**
画像プレビュー／種別（メイン・サブ）／使用元画像／生成プロンプトまたは作成指示／Amazon画像要件チェック結果／知財・法令・誇大表現チェック結果／修正指示欄／承認者／承認日時／ステータス（生成中・要修正・承認待ち・承認済み・却下）。ボタン＝承認／修正依頼／再生成／却下。

**25-5. 禁止事項**
Amazonメイン画像要件に違反する画像を自動登録しない／実際の商品と異なる色・サイズ・素材・セット内容に見える画像を作らない／他社ブランドロゴ・キャラクター・第三者の画像を無断利用しない／存在しない認証・受賞歴・レビュー・ランキング・保証・効果効能を記載しない／サプライヤー画像の無断転載を前提にせず、利用許諾または自社撮影・自社作成素材を優先する／AI生成画像のみで実物と異なる印象を与えない。必要に応じサンプル実物撮影を必須にする。

**25-6. 商品管理との連携**
商品詳細画面に6枚の作成状況・承認状況・登録状況を表示。**画像未承認の商品はAmazon出品登録・販売開始の次工程へ進めない制御**を行う。

### 26. LINE通知
Sランク発見／Aランク発見／発注承認待ち／Amazon販売開始／在庫不足／売上急増／売上急減／広告ACOS悪化／広告費上限到達／SNS投稿失敗／APIエラー／仕入価格急騰／Amazon販売価格急落／競合急増／利益率30%未満への低下。通知条件は管理画面からON/OFF可能。

### 27. LINE承認機能
将来的にLINE通知から管理画面へ遷移できるようにする。通知例＝商品／Amazon販売価格／仕入価格／想定利益／利益率／ROI／月間販売推定。管理画面操作＝詳細を見る／承認／保留／却下。

### 28. 商品管理フロー
商品発見 → 自動分析 → 仕入先検索 → 同一商品判定 → 利益計算 → ランク判定 → 仕入候補 → 人間承認 → 発注 → 輸送 → FBA納品 → **Amazon商品画像6枚作成・承認** → Amazon販売開始 → Amazon広告開始 → SNS販促開始 → 販売分析 → 広告改善 → 追加発注判断。

### 29. 商品詳細画面
Amazon情報（商品名/ASIN/価格/レビュー/評価/BSR/推定販売数/推定売上）／仕入情報（候補/仕入価格/MOQ/サプライヤー/商品一致率）／利益（原価/物流費/Amazon手数料/広告費/利益額/利益率/ROI）／発注（発注数/発注金額/承認者/発注日/納期）／Amazon販売（販売数/売上/在庫/利益）／広告（広告費/広告売上/ACOS/ROAS）／SNS（投稿数/予定/済/結果）／商品画像（メイン/サブ5枚/要件チェック/承認状況/登録状況）。

### 30. AI分析
仕入理由／リスク／競合（勝てる可能性）／差別化（OEMでどこを変えれば優位性が出るか）／販売価格（販売数と利益を両立できる価格帯）／広告（開始時の推奨戦略）／最終判断（仕入推奨・要確認・非推奨）。

### 31〜32. リサーチ結果一覧とソート
一覧項目＝Amazon画像／商品名／ASIN／販売価格／レビュー／推定月販／仕入価格／商品一致率／利益／利益率／ROI／総合点／ランク／状態。
ソート＝総合スコア／利益額／利益率／ROI／推定販売数／推定月間利益／レビュー数／商品一致率／Amazon価格。

### 33. 商品リサーチの最重要指標
単純に「Amazon価格−中国価格」だけで選ばない。**販売需要 × 競合難易度 × 利益率 × ROI × 商品一致度 × リスク**で判断する。
例：利益2,000円・月販20個＝非推奨／利益800円・月販800個＝有力候補。

### 34. 開発優先順位（原案）
- Phase1：リサーチ → 仕入先検索 → 一致判定 → 利益計算 → スコアリング → 仕入候補一覧 → LINE通知
- Phase2：発注承認 → 発注連携 → 発注管理 → 画像6枚作成・承認 → FBA商品管理 → 販売実績連携
- Phase3：広告管理 → ACOS分析 → 改善提案 → 自動最適化
- Phase4：X / Instagram → AI投稿作成 → 週2回投稿 → SNS分析
- Phase5：商品選定AI高度化（予測と実績を学習に利用）

### 35. 現時点の確定条件（原案）
Amazon＝日本国内のみ／仕入サイト＝1688＋Alibaba.com／販売＝FBA／価格1,000〜15,000円／利益500円以上／利益率30%以上／ROI20%以上／月販100個以上／レビュー50〜1,000件／目標ACOS20%以下／SNS＝X＋Instagram・1商品週2回／発注＝システムから発注まで対応、人間承認必須／画像＝メイン1＋サブ5の6枚、要件チェックと人間承認必須／通知＝LINE。

### 36. 残りの確認事項
Q6 リサーチカテゴリー／Q9 Amazon広告運用／Q11 SNS投稿／Q14 システム利用者 — 原案では4点とも未確定。

### 37. 開発の最終ゴール
毎日Amazon.co.jpをリサーチし、「4,980円で販売・推定月600個・レビュー320件・仕入680円・FBA費用と物流費と広告費を考慮して1個1,350円の利益、利益率27%、ROI60%」等を自動計算する。自社条件（利益500円以上／利益率30%以上／ROI20%以上／月間100個以上／レビュー50〜1,000件）を満たす商品のみ自動抽出する。人間が最終承認した商品を発注し、画像6枚を作成・承認したうえでFBA販売を開始し、広告・X・Instagram販促をシステムが運用する。最終的に「商品を探す → 利益を判断する → 発注する → 画像を作成・承認する → 販売する → 広告を回す → SNSでPRする → 売上を分析する → 売れる商品条件を学習する」までを一つのシステムで完結させる。

> ※第37章の「利益率27%」は、第9章「利益率30%以上」と矛盾する。**30%が正式基準**（→ 第3節【C】②）。
