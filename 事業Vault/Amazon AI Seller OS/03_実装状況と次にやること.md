### 第2段階（発掘エンジン）— 2026-08-19 完成

**画面**: `/discover`（「① 商品を発掘する」）／**API**: `POST /api/discover`／**CLI**: `npm run discover -- 30 fbm`

- **販売ルート自動判定** `lib/salesRoute.ts` — ①自社ブランド（`OWN_BRANDS`）→ OEM新規ページ可／②既存ASINあり → **相乗り一択**（`canCreateNewListing: false` で新規ページを機械的に禁止＝重複出品違反の防止）／③Amazonに無い → 新規ページ可。Amazon本体が販売中なら相乗り「avoid」判定
- **仕入先データ層** `lib/sourcing.ts` + `data/suppliers.csv` — 問屋／メーカー／国内EC／eBay／Alibaba に対応。USD・CNYは自動円換算、実仕入原価＝単価×(1+関税率)＋送料。**`amazon`/`FBA`/`マケプレ` を含む行は読み込み時に自動で弾き、理由を画面に出す**（ドロップシッピングポリシー違反）。突合優先度 JAN>ASIN>キーワード>商品名
- **輸入規制チェック** `lib/importRules.ts` — 食品衛生法（輸入届出）／薬機法／PSE／技適／商標（並行輸入）／ワシントン条約・検疫／有害物質。海外仕入が確定していれば **blocking（販売不可）**、仕入先未確定なら **warning（要確認）**。本体のコンプラAI（`lib/compliance.ts`）にも合流させたので、商品ページ作成の流れでも必ず点検される
- **自己発送（FBM）の利益計算** `lib/profit.ts` — FBA手数料の代わりに実配送料（ネコポス210円〜160サイズ1,900円）、保管料0円。**冷蔵＋220円／冷凍＋330円のクール便加算**
- **A/B/C/D 判定** `lib/grading.ts` — **LLMを1回も呼ばない純粋計算**。1万商品回してもAI料金ゼロ。A=今すぐ仕入れ／B=値下がりしたら／C=競合が減ったら／D=販売しない。B・Cは**二分探索で「いくらまで下がればAになるか」「販売価格がいくらに戻ればAになるか」「出品者が何人まで減ればAになるか」を逆算**して見張り条件にする
- **仕入数量・FBA切替判断** `lib/inventory.ts` — 自己発送は原則MOQのみ（在庫リスクゼロ）、初回予算 `FIRST_BUY_BUDGET_JPY` で頭打ち。週`FBA_SWITCH_UNITS_PER_WEEK`個でFBA切替を提案。**冷蔵冷凍はFBA不可と明示**。仕入リードタイム10日超は出荷遅延率（4%未満）に触れると警告
- **毎朝ダッシュボード** — 調べた商品／見込みあり（A+B+C）／利益基準を突破（A+C）／今すぐ仕入れ（A）の4数字＋ランク別リスト（売り方・理由・発動条件・輸入規制の赤字・仕入れ目安）
- **OEM改善要件の蓄積** `lib/oem.ts` — 商品を1つ分析するたびに、レビューの不満・改善要望をカテゴリー別に自動で積み上げ、同じ不満の回数で優先度（3回以上=高）を付ける。**これが自社OEM商品の設計図になる**
- DB追加：`discovery_runs` / `discoveries` / `oem_requirements` / `account_health`
- 判定基準はすべて環境変数：`MIN_PROFIT_RATE`(15%) / `MIN_PROFIT_JPY`(500) / `MIN_ROI`(30%) / `MAX_SELLER_COUNT`(12) / `AVOID_AMAZON_SELLING` / `USD_JPY` / `CNY_JPY` / `OWN_BRANDS`
- **この画面から仕入れ発注もAmazon出品も一切起きない**（調べて並べるだけ）

### 第2.2段階（リサーチツール）— 2026-08-19 完成 ※詳細 [[06_リサーチツール仕様]]

**画面**: `/research`（「① リサーチツール」）／**API**: `POST /api/research`・`/api/research/settings`・`/api/research/watch`／**CLI**: `npm run research 60 fbm`

メニューを **① リサーチツール ／ ② 商品を発掘する ／ ③ 商品ページを作る** の3つに再編。

- **システムが勝手に探す** — ユーザーが商品を入力するのではなく、
  `安い仕入先の商品 → Amazonで売れている同一商品 → 利益が出る商品` を自動でつないで並べる
- **SupplierProvider** `lib/providers/supplier.ts` — CSV／Alibaba／1688／AliExpress／サンプルを差し替え可能。
  **正式APIかCSVのみ。無理なスクレイピングは実装しない。** 仕入先名にamazon等が入る行は自動除外
- **AmazonSearchProvider** `lib/providers/amazonSearch.ts` — Keepa（domain=5）実装済み／PA-APIはスタブ／
  鍵が無ければサンプル市場で動き「実在の商品ではありません」と画面に明記。
  検索は安い順に `GTIN → 型番 → キーワード`
- **MATCH SCORE 100点満点** `lib/matching/matchScore.ts` — 画像40（pHash実装：32×32→DCT→8×8→64bit）／
  型番・JAN20／商品名10（2-gram Dice・日中混在対応）／サイズ容量10／色仕様10／その他10。
  **90以上=自動／80〜89=人が確認／79以下=除外**。
  ★**証拠が画像だけの時は強制的に「人が確認」未満へ落とすハード制約**（設定で外せない）
- **多段階でAI料金ゼロ** — `通常計算 → ルール → pHash → テキスト類似 → Embedding → AI Vision` の順に進み、
  決着したら打ち切る。上限は `RESEARCH_MAX_VISION_CALLS`(20)／`RESEARCH_MAX_EMBEDDING_CALLS`(200)。
  **サンプル21件を通してAI課金0回を実測確認**
- **推定月販** `lib/research/salesEstimate.ts` — `scale/BSR^0.75`（カテゴリー別）。
  **「確定」とは絶対に書かず「推定月販 約N個」＋根拠を併記**。しきい値は管理画面から10/20/30/50/100/300
- **全費目の利益計算** `lib/research/researchProfit.ts` — 仕入／中国国内送料／国際送料／関税／輸入諸費用／
  検品費／Amazon手数料／自己発送送料 or FBA費用／広告費／返品リスク／その他変動費を積み上げてNET PROFIT・利益率・ROI。
  **仮置きした数値は「前提」として全部画面に出す**
- **PRICE GAP と意外な商品発見** `lib/research/priceGap.ts` — 「中国では異常に安いのにAmazonでは普通に売れている」
  を高評価。地味だけど儲かる商品のタグ（競合少・Amazon本体不在・小さい軽い・消耗品・セット可 等）
- **Research Score 100点満点** `lib/research/researchScore.ts` — 需要20／利益25／一致精度15／競合の弱さ10／
  価格差10／価格安定性5／仕入安定性5／ページ改善余地5／リスク低さ5 → A/B/C/D
- **芋づる探索** — A/Bの候補からだけ、同じ工場・同じブランド・別サイズ・別色へ拡張。
  探索済みIDのSet＋深さ上限＋件数上限で**無限ループを構造的に防止**
- **B/Cの見張りとA昇格** `lib/research/watch.ts` — 価格・競合を取り直して再計算し、条件を満たせばAへ昇格して通知。
  **ここでもAIは一切使わない（料金0円）**
- **NotificationProvider** `lib/providers/notification.ts` — 既定は画面のみ。
  `LINE_NOTIFY_TOKEN` / `SLACK_WEBHOOK_URL` を入れると外部へ。**外部送信に失敗してもDBには必ず残す**
- **OEM候補の別管理** — 需要があるのに同じ不満が繰り返される商品を転売候補とは別枠で蓄積
- **毎朝の6数字**（調査→Amazon一致→月N個以上→利益クリア→Aランク→今日の強い推奨）＋
  **「この3件だけ見れば判断できます」** の抜粋
- **安全**：`AUTO_PURCHASE=true` ならスクリプトが実行を拒否。`RESEARCH_AUTO_APPROVE=false`。
  この画面から発注も出品も起きない
- DB追加：`research_runs` / `research_candidates` / `research_settings` / `notifications` / `embedding_cache` / `image_hash_cache`

> [!warning] 実測で見つけた事故と対策（再発禁止）

> pHash 91〜95%＋型番一致の正しい候補が14件壊れ、架空データに実課金も発生した。
> → 両側に実画像が無ければVisionを呼ばない／JAN完全一致ならVisionの「別商品」だけで除外しない／
>   確信度0.6未満は保留。**修正後：Aランク1件→4件に回復・AI課金28回→0回。**

### 第3段階（実績学習ループ）— 2026-08-20 完成 ※詳細 [[07_実績学習ループ仕様]]

メニューを **6つ** に再編（④仕入れ・販売の記録／⑤予測の答え合わせ／⑥自動運転とAPI代 を追加）。
方針は **「新しい派手な機能より、本当に儲かる商品を見抜く精度を優先する」**。

**【最優先1】Keepa本番接続の完成**
- `KEEPA_API_KEY` を `.env` に書くだけで次のリサーチから本番へ自動切替。画面に緑の **`LIVE DATA`** バッジ
- 鍵が無い時は琥珀の `サンプルデータ` バッジ＋「これは練習用の仮データです。この数字で仕入れを判断しないでください。」
- **Mockと本番の混在を機械的に禁止** — 本番実行に混入したサンプル候補は自動で捨て、件数を `mixed_data_blocked` に記録して赤帯表示
- 最低13項目（ASIN／商品名／画像／現在価格／30日平均／90日平均／Sales Rank／Sales Rank履歴／出品者数／Amazon本体販売有無／Buy Box／月販推定／取得日時）
- **取れなかった項目は推測で埋めず `UNKNOWN（取れていません）`**。候補ごとにUNKNOWN一覧を表示し「分からない項目は推測で埋めていません」と明記

**【最優先2】実績学習ループ**
- **10ステータス** `DISCOVERED / WATCHING / APPROVED / ORDERED / RECEIVED / LISTED / SELLING / SOLD_OUT / STOPPED / FAILED`。APPROVED以降は全部**人間が押して進める**
- **承認ボタンは1円も発注しない** — 2段階確認＋「実際の注文は仕入先サイトでご自身で行ってください。ここでは記録だけを残します。」＋`AUTO_PURCHASE`/`RESEARCH_AUTO_APPROVE` 二重ロック。承認時にその瞬間の予測値を**凍結スナップショット**保存
- **PURCHASE_QUANTITY_RECOMMENDER** `推定月販÷30×(リードタイム+安全在庫)` を 初回予算／上限個数／MOQ で頭打ち。**LLMは使わず数式・統計のみ**。必ず 推奨数／理由／**最悪ケース**／想定売切日数 の4点を表示
- **FORECAST_ACCURACY** 需要・利益・価格を**別々に**採点（まとめない）
- **カテゴリー別補正** 予測に対する実績倍率の**中央値**で計算（平均でなく中央値＝1件のバズで歪まない）
- **Research Score の自動改善は提案どまり** — 「AI推奨重み」を出すだけ。人間が `/learning` で承認して初めて配点が変わる。変更幅±20%・**実績5件未満は学習を動かさない**
- **失敗の10分類** 件数と損失額を集計し、次回リサーチで同条件の商品に「過去の失敗からの注意」を出す
- **横展開8方向** 1個当たったら周辺（同じ仕入先／同カテゴリ／色違い／サイズ違い／上位モデル／セット／消耗品 等）に種をまく

**【最優先3】自動運転（調べる・数える・学ぶ だけ）**
- **仕入先取込のAdapter化** CSV／Googleスプレッドシート／メール添付CSV・XLSX／API／SFTP／共有URL。使える／未設定を画面表示
- **差分取込** 行ごとの内容ハッシュで **前回と同じ商品は再計算しない**（読込／新規／変更／変化なし／消えた の5数字で表示）
- **仕入価格の変動監視 → 自動ランク昇格（記録だけ）** 例「昨日1,595円→今日1,420円、A条件1,481円以下 → A昇格」＋理由「仕入価格175円下落によりA昇格」。条件割れならBへ降格＋理由。**上がっても買うかは人が決める**
- **毎日9:00の定期リサーチ**（`/ops` から時刻変更可）／**ランク別24時間監視**（A=高頻度・B=中・C=低・D=原則停止）
- **APIコスト管理** 今日の回数／今月合計／**1件あたり**／上限使用率。上限接近でB・Cの見張りから自動停止（**Aの見張りは止めない**）
- **DATA_FRESHNESS** 古すぎるデータの商品はAランクにしない（`stale` 赤字表示）
- **CONFIDENCE SCORE** 「Aランク Confidence 96%」と「72%」を区別。内訳7項目と下がった理由を日本語で表示。`minConfidenceForA` 未満はAに上げない
- **今日の強い推奨** なぜ良いか／何個買うか／予想利益／予想売り切り期間／最悪ケース／過去の失敗からの注意 を1画面に＋その場に承認ボタン
- 実装：`lib/learning/*`（lifecycle・forecastAccuracy・categoryBias・scoreWeights・postmortem）／`lib/suppliers/*`／`lib/ops/*`／画面 `app/lifecycle` `app/learning` `app/ops`／CLI `npm run scheduler` `scheduler:loop` `supplier:import`

### 第4段階（本番運用基盤）— 2026-08-20 完成 ※詳細 [[08_本番運用基盤仕様]]

- **広告週次監査** — 7日ごと12指標・5状態（SCALE/OPTIMAL/OVERSPEND/UNDEREXPOSED/POOR）。`AD_AUTO_OPTIMIZE=false` 維持
- **アカウント健全性画面（9項目）＋出荷期限アラート** — 広告や新規仕入れよりアカウント保護を最優先
- **停止対策** — `npm run scheduler:install` でlaunchdに登録。**パソコンをつけっぱなしにする必要がなくなった**。サーバーは落ちても自動再起動、定期実行は5分ごとの「1回きり起動」なので固まったまま気づかれない状態が起きない
- **ジョブ管理5状態＋自動再試行（1分→5分→30分の3回まで・無限リトライ禁止）＋Provider健全性（HEALTHY/DEGRADED/DOWN）** — 止まっている時は推測で埋めず「見送りました」と記録して飛ばす
- **バックアップ**（毎日・18種類・30世代・自動削除は写しのみ）— **一番価値が高いのは自社販売実績DB。Keepaは買い直せるがこれは二度と買えない**
- **Aランクの的中率を管理画面の最上部に**＋**AI社員5名の成績表** — すべてわり算。実績3件未満は「まだ判定できません」と正直に出す（1勝0敗を100%と表示しない）

### 第5段階（AliExpress LIVE化の土台）— 2026-08-20 完成 ※詳細 [[14_AliExpress_LIVE化計画]]

**きっかけは失敗です。「存在しないAPIを実装していた」事故が起きたため、二度と起こさない仕組みを先に作りました。**

- **4段階ゲート**（`api_contract_registry`）— `DOCUMENTED`（公式資料で存在確認）→ `AUTHORIZED`（権限取得）→ `CONNECTED`（認証成功）→ `VERIFIED`（実商品を取得して中身を確認）。
  **4つ揃わないと `LIVE_DISCOVERY_READY` は false のまま。公式資料のURLが無いAPIは DOCUMENTED にすらしない**（自動で降格する）
- **現在地：5つのAPIすべて DOCUMENTED、VERIFIED は0件。** 鍵がまだ無いので、ここから先へは意図的に進めない
- **段階的取得（1件 → 5件 → 20件）** — 鍵が入っても、いきなり100件は取らない
- **異常値の関門** `npm run aliexpress:audit` — `-1` / `null` / 空文字 / 0円 / 異常通貨 / 異常MOQ など**23種類を全部はじけることを実測で確認**。
  Keepaで `-1` の寸法がFBA手数料計算へ流れた事故と同じことを、AliExpressでは起こさない
- **7つの結果コード** `0_RESULTS / API_ERROR / AUTH_ERROR / PARSE_ERROR / RATE_LIMIT / NO_PERMISSION / NO_MATCH` —
  **「壊れているのに0件と表示する」を禁止。**画面にも日本語で理由を出す
- **PURCHASE_URL 必須** — 人がクリックして実際に購入ページへ行けるURLが確認できない商品は**Aランク禁止**
- **Aランク条件は据え置き** — 送料・MOQ・重量など重要コストがUNKNOWNなら**Aランクにしない**（B または要確認）
- **DISCOVERY KPI 10項目**（`npm run discovery:kpi`・`/research` 画面）— Amazon候補件数／AliExpress検索件数／一致候補数／MATCH_SCORE90以上／利益条件突破／Aランク／**Keepa消費トークン**／AliExpress API使用回数／OpenAI使用回数／利益商品1件あたり費用
- ★KPIで守る3つの約束
  1. **数えていない値を0で埋めない**（画面には「まだ出せません（数えていません）」と出す）
  2. **⑦は「消費トークン数」であって「呼び出し回数」ではない**（実測で 7回＝70トークン。代用したら嘘になる）
  3. **⑩は利益商品が0件なら計算しない**（0で割らない・目安も出さない）
