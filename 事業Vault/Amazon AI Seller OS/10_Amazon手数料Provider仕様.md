# 10. AmazonFeeProvider 仕様（Amazon手数料を仮置きから実データへ）

> [!important] この仕様が存在する理由
> 同じような商品でも **Amazon紹介料は5%と15%で3倍違う**。FBA配送代行手数料も商品ごとに違う。
> 一律の仮置き率で計算すると **「Aランク → 実際は赤字」** が起きる。
> 実測例（2026-08-20 Keepa本番）：無印良品のシリコン蓋＝紹介料5%／FBA 252円、IKEAのシリコン蓋＝紹介料15%／FBA 318円。
> **これだけでA判定とD判定がひっくり返る。**

---

## 1. 位置づけ

- 実装：`lib/providers/amazonFee.ts`
- 手数料だけを担当する **独立したProvider**。他のProvider（AmazonSearch / Market / Supplier など）とは分離する。
- 機能凍結（[[09_機能追加凍結と本番20商品検証]]）の期間中に、**唯一許可された精度改善**として実施。
- 変更していないもの：**Research Score / A・B・C・Dの判定基準 / MATCH SCORE / 月販判定 / Confidence Score**。

---

## 2. 3つの状態を絶対に混ぜない

| 状態 | 意味 | 画面・レポートでの表示 | 扱い |
|---|---|---|---|
| `ACTUAL` | Amazon/Keepaから取れた、その商品の実際の手数料 | **実データ** | **必ずこれを最優先で使う** |
| `ESTIMATED` | 取れないのでサイズ・カテゴリーから計算した推定値 | **推定値** | 使ってよいが、必ず「推定値」と明示する |
| `UNKNOWN` | 分からない | **不明** | **絶対に0円にしない。** 安全側の概算を置いたうえで **Aランク禁止** |

★ 推定値を確定値のように見せることを禁止する。

---

## 3. 取得している費目

| 費目 | 取得元（ACTUAL時） | 取れない時 |
|---|---|---|
| Amazon紹介料（カテゴリー別販売手数料） | Keepa `referralFeePercent`／`referralFeePercentage` | カテゴリー別推定率（ESTIMATED） |
| FBA配送代行手数料 | Keepa `fbaFees.pickAndPackFee` | サイズ区分からの推定（ESTIMATED） |
| FBA在庫保管料 | （FBM時は0円＝ACTUAL） | 体積からの推定（ESTIMATED） |
| 自己発送送料（FBM） | — | 配送区分からの推定（ESTIMATED） |
| サイズ区分 | 寸法から判定 | 寸法が無ければUNKNOWN |
| 重量区分 | Keepa `packageWeight`／`itemWeight` | 取れなければUNKNOWN |

★ 手数料のために **追加でAPIを叩かない**。商品取得と同時に `AmazonCandidate.feeData` に載せて運ぶ（トークン消費ゼロ）。

---

## 4. FEE_DATA_FRESHNESS（手数料データの鮮度）

- 取得元の更新日時（Keepa `fbaFees.lastUpdate` → 無ければ `lastUpdate`）を保存する。
- **30日を超えたら `stale`** とする。
- **取得日時そのものが分からない場合も `stale` 扱い**にする（古い可能性があるため実データ扱いしない）。
- 古い手数料のままAランクにしない（料金改定で赤字化するため）。

---

## 5. Aランクの新しい禁止条件（2つ追加）

`lib/research/researchScore.ts` に追加。**既存の判定基準は一切変更していない**（Aの条件を後から降格させるだけ）。

1. **利益に重大な影響がある手数料がUNKNOWNならAランク禁止**
   - FBM：Amazon紹介料 / 自己発送送料
   - FBA：Amazon紹介料 / FBA配送代行手数料 / FBA在庫保管料
2. **手数料データが古い（stale）ならAランク禁止**

どちらもBランクへ落とし、理由を日本語で明記する。

---

## 6. 旧「仮置き」との差の記録（legacyComparison）

実データが取れた商品では、**旧・一律仮置き計算との差**を必ず記録する。

```
仮計算利益 1,200円 / 実データ利益 760円 / 差額 -440円
```

- **マイナス＝仮置きは利益を多く見せていた（＝赤字を見落とす方向だった）**
- 保存先：`research_candidates.cost_detail` の `legacyComparison`
- 表示先：`/research` 画面の内訳、レポート `⑨-2` セクション

### 2026-08-20 実測（Keepa本番20商品×FBA/FBM＝120費目）

| 項目 | 結果 |
|---|---|
| 実データ(ACTUAL) | 80件 |
| 推定値(ESTIMATED) | 40件 |
| 不明(UNKNOWN) | **0件** |
| 手数料データが古い | 0件 |
| 仮置き→実データの利益変化 | 平均 **−33円** ／ 最も減った **−157円** ／ 最も増えた +126円 |

観測された実際の紹介料率：**8% / 10% / 15%** と商品ごとにバラついた。仮置き一律では必ずズレる。

## 7. 画面・レポートへの反映

- `/research` 各候補に「1円単位の内訳を見る」を追加。
  - Amazon販売価格 − 仕入価格 − 中国国内送料 − 国際送料 − 関税等 − 輸入関連費 − 検品費 − Amazon紹介料 − FBA/自己発送送料 − 保管料 − 広告費 − 返品リスク − その他 ＝ **NET PROFIT**
  - 各手数料の横に **実データ／推定値／不明** のバッジ
  - サイズ区分・重量区分・鮮度・仮置きとの差も併記
- `npm run report:test` のレポートを **26項目 → 32項目** に拡張（手数料6項目を追加）＋ `⑨-2 Amazon手数料：実データ／推定値／不明の内訳` を新設。
