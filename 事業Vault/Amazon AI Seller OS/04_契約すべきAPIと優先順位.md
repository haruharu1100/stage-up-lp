# 契約すべきAPIと優先順位

親: [[00_仕様書_最上位]]

> 「AIを大量に契約する」のではなく、**役割ごとにAPIを分ける**。
> 追加契約する価値はあるが、順番を守って1つずつ増やす。

| 優先 | API | 役割 | 状態（2026-08-19） |
|---|---|---|---|
| ① | **Amazon SP-API** | 出品・価格・商品属性・既存ASIN・Listing の正式な情報源。カテゴリ別必須属性は Product Type Definitions API から取得 | ❌ 未契約（`SPAPI_CLIENT_ID` / `SPAPI_CLIENT_SECRET` / `SPAPI_REFRESH_TOKEN` / `SPAPI_SELLER_ID` が必要） |
| ② | **OpenAI API** | 画像生成 ＋ 商品理解 ＋ 最終チェック（AI二重チェックの片方） | ✅ 稼働中（既存.envから借用） |
| ③ | **Keepa API** | 商品発掘。90日の価格・ランキング推移、出品者数変化、Amazon在庫有無 | ❌ 未契約（`KEEPA_API_KEY`）**発掘AIの心臓部。SP-APIの次に効く** |
| ④ | **Claude API** | 司令塔・開発・文章生成 | ✅ 稼働中（既存.envから借用） |
| ⑤ | **動画生成API**（fal / Runway） | 紹介動画の生成 | ❌ 未契約（`FAL_KEY` / `RUNWAY_API_KEY`） |
| ⑥ | **Firecrawl等** | Amazon**以外**の公開Web市場調査（Google Trends・楽天・Yahoo!・SNS・ニュース） | ❌ 未契約 |
| — | **Amazon Ads API** | 広告実績の取得と入札・予算変更 | ❌ 未申請（SP-API契約後に申請） |

## 注意

- Firecrawl等は **「公開Web上の市場トレンド調査用」**。Amazon商品ページを無制限にスクレイピングする目的では使わない。
- 鍵はすべて環境変数／`.env` に置く。コードに書かない。
- 鍵が無い状態でもシステムはサンプルデータで動く（**画像だけは例外**：MASTER画像が無ければ1枚も作らない）。
- 「いま何が本物で動くか」は `npm run doctor` で日本語表示される。

## 仕入先データの入口（2026-08-20 調査済み）

> [!important] ここは「**人が作った商品一覧を受け取る入口**」の話。
> **自分で安い商品を探しに行く**のは別層 → [[12_仕入先自動探索仕様]]（下の節）
> 結論：受け取り口として契約すべき有料APIは無い。Googleスプレッドシートが最短かつ費用ゼロ。
> 詳細 → [[11_仕入先LIVEデータ仕様]]

| 入口 | 費用 | 審査 | 期間 | 判定 |
|---|---|---|---|---|
| **Googleスプレッドシート** | **無料** | **なし** | **その場** | **`LIVE_READY` ← 今すぐこれ** |
| CSV（`data/supplier_listings.csv`） | 無料 | なし | その場 | `LIVE_READY`（毎回置き直す手間あり） |
| **AliExpress Dropshipping API** | **無料** | 開発者登録＋アプリ審査 | 目安2〜5営業日（実際は1〜2週間見る） | `PARTIAL`（鍵が入れば `LIVE_READY`） |
| Alibaba.com（ICBU）公式API | 無料 | — | — | **`UNAVAILABLE`**（2026-08-20 降格。買い手用の検索APIが無い） |
| 1688 公式API | — | 中国本土の実名認証Alipay＋ホワイトリスト＋GMV要件（月16万CNY 等） | — | **`UNAVAILABLE`**（日本の個人は不可） |

- **1688の非公式API代理サービスは使わない**（規約違反リスク）。代行業者・問屋からの提供データを
  スプレッドシートで受け取る方が、早くて確実で、規約上も安全。
- AliExpressの**アフィリエイトAPIは「探すため」だけに使う**（アクセストークン不要で最速）。
  MOQ・在庫・重量は返らないので、**仕入判断は必ず `ds.product.get` と `ds.freight.query` で裏を取る**。
  アフィリ枠の数字だけで採算計算はしない。

## 自動探索の入口（2026-08-20 調査済み）※こちらが「自分で安い商品を探す」層

> [!warning] 現在 **`LIVE_DISCOVERY_READY` は0件**。鍵が無いため、システムはまだ自分で商品を探せない。
> 配線・安全弁・上限・不採用理由の保存は完成・検証済み。詳細 → [[12_仕入先自動探索仕様]]

> [!important] 2026-08-20 第2回監査で本命を変更した
> **本命＝AliExpress。** Alibaba.com（ICBU）には**買い手が全カタログをキーワードで探すAPIが無い**ことが判明し、
> 「Amazonで売れている商品 → 中国で同じ物を探す」という主軸の作り方がAlibabaでは成立しない。
> Yahoo!は**仕入先ではない**ので、鍵が早く出ても仕入の課題は1歩も進まない（前回「最短」と推した判断の訂正）。

| 探索先 | 費用 | 審査 | 期間 | 判定 | 備考 |
|---|---|---|---|---|---|
| ★**AliExpress Open Platform** | **無料** | 開発者登録＋アプリ審査 | **公式記載なし**（体験談で2〜5営業日） | **`PARTIAL` ← 本命** | キーワード検索・**公式の画像検索**・MOQ・在庫・実重量・**日本向け実送料**が全部そろう唯一の選択肢。アフィリ枠は**トークン不要で最速**。手順 → [[13_AliExpress申請手順]] |
| Yahoo!ショッピング商品検索 | 無料 | なし | 15〜20分で即時発行 | `PARTIAL`／**役割＝市場調査** | ★仕入先から外した。国内小売価格を仕入値にしないため、コード上も仕入先として選ばれない。商用可否をYahoo!に確認するまで `COMMERCIAL_USE_APPROVED=false` |
| Alibaba.com（ICBU）API | 無料 | — | — | **`UNAVAILABLE`** | **買い手用のキーワード検索APIが存在しない。** `product.list`/`.get`/在庫/物流はすべてSeller用（自分の出品専用）。`distribution.product.query` は引数が頁数のみで逆引き不可。待っても解決しない |
| 1688 公式API | — | 中国本土の実名認証Alipay＋ホワイトリスト＋GMV要件 | — | **`UNAVAILABLE`** | 非公式のAPI代理販売は使わない |
| 楽天市場API | — | — | — | **使用不可** | 楽天ウェブサービス規約**第10条**が閉じた環境・内部利用を認めていない。実装もしていない |

## ユーザーにしか用意できないもの（依頼リスト）

0. **★★AliExpress の App Key / App Secret** — **いま唯一のブロッカー**。
   手順は [[13_AliExpress申請手順]] に全部書いた。`.env` に2行貼るだけで探索が本物になる。
   （後日 `ALIEXPRESS_ACCESS_TOKEN` が入ると MOQ・在庫・実重量・日本向け実送料・公式画像検索も使えるようになる）
1. **仕入先の商品一覧（Googleスプレッドシート）** — 作って共有し、URLを `.env` に貼るだけ。※受け取り口。自動探索とは別
2. **商品の元画像（MASTER PRODUCT IMAGE）** — 自社撮影／メーカー／問屋／許諾済み／自社所有 のいずれか
3. ~~**Keepa APIキー**~~ → 2026-08-20 設定済み
4. **SP-API の4点**（クライアントID・シークレット・リフレッシュトークン・セラーID）
5. （後日）Yahoo!ショッピング Client ID ※**市場調査用**。発行前に商用利用の可否をYahoo!に確認すること
6. 動画生成の鍵（fal または Runway）※後回しでよい
