## 前提

これは「AI GACHA OS」（オンラインガチャ／オリパ運営システム）の
**販売用LP・デモ画面・営業資料ページ**です。技術構成は
Next.js 14 App Router / TypeScript / Tailwind CSS / React Three Fiber / Framer Motion。

重要な前提が2つあります。

- **LP上の表現が、実際のガチャ本番システム（別リポジトリ `sneaker-gacha/`, `cocohoreone/`）の
  実装内容と乖離していないか**、という「表現と実態の一致」も監査対象です。
- **虚偽の実績数値・絶対保証表現は1箇所も許されません。**
  「必ず儲かる」「絶対に落ちない」「100%安全」等は景品表示法上のリスクとして扱ってください。

## 監査観点（この順で見てください）

### A. セキュリティ

1. **フォーム／API** — `app/api/contact/route.ts` の入力検証・長さ制限・レート制限・
   ハニーポット（`hp`）・ログへの個人情報流出・SSRF（Webhook転送先の指定方法）・
   XSS・環境変数の扱い・エラー時に内部情報を返していないか。
2. **管理者権限** — デモ画面 `app/demo/page.tsx` / `components/demo/DemoConsole.tsx` は
   ログイン無しで誰でも触れます。**本番の管理機能と誤認される危険**、
   および LP が説明している権限設計（誰が何をできるか、販売停止・還元率変更・返金等の
   高権限操作の権限分離、監査ログ、二要素認証、操作者の記録）が
   実装を伴わない誇大表現になっていないかを見てください。
   デモ内に本番の管理URL・エンドポイント・内部用語が漏れていないかも確認してください。
3. **抽選整合性 / 二重抽選** — LP・デモが説明している抽選ロジック
   （抽選前残数 → 結果 → 抽選後残数、監査ログ）が実運用として成立する説明になっているか。
   矛盾・誤解を招く記述がないか。
4. **残数競合（Race Condition）** — 「在庫整合性」「同時アクセス」系の記述が
   実装を伴わない断定になっていないか。
5. **ポイント不正** — 「不正ポイント付与防止」系の訴求が実態と乖離していないか。
6. **決済Webhook** — Webhook署名検証・冪等性の訴求が実態と乖離していないか。
7. **AI顧客対応による個人情報漏洩** — 「会員ごとの発送状況・購入履歴・追跡番号に答える」
   という設計上、**他人の情報を返す危険**、本人確認、エスカレーション条件
   （返金・法的トラブル・アカウント停止・高額補償・不正利用）が十分に説明されているか。
   `components/sections/AiSupport.tsx` と `DemoConsole.tsx` の AI OPERATOR を見てください。

### B. 表現と実態の一致

8. **市場価格の取得方法** — `components/sections/MarketPrice.tsx` と FAQ。
   スニダン等からの価格取得について、**利用規約・正式なデータ取得方法を前提とした表現**に
   なっているか。スクレイピング前提と読める記述が1箇所も残っていないか。
9. **AWS構成・負荷の表現** — `components/sections/Aws.tsx`。
   「絶対に落ちない」系の保証表現が残っていないか。
   「アクセス集中を想定した構成」等、実装に即した表現になっているか。
10. **実績・数値** — `components/sections/BuiltFromOps.tsx` と `content/site.ts` の `metrics`。
    確認できない数値が表示されていないか。null の項目がうっかり `0` や `—` で
    表示されていないか（**空欄すら出さず、ブロックごと非表示が正**）。
11. **試算の免責** — `RoiCalculator.tsx` / `TimeSaving.tsx` の数値に
    「モデルケース」「シミュレーションであり成果を保証しない」旨が明示されているか。
    計算式が非現実的な数字（人員の稼働時間を超える削減時間など）を出さないか。
    `lib/simulate.ts` のガチャ生成デモが、還元率・粗利で破綻した値を出さないか。

### C. 品質・到達性

12. **SEO** — 以下を具体的に見てください。
    - `app/layout.tsx` の metadata（title / description / OGP / canonical / lang / viewport）
    - `app/sitemap.ts` と `app/robots.ts` の整合（`/demo` と `/sales` は
      noindex 扱いにしているが、sitemap 側と矛盾していないか）
    - `app/sales/page.tsx` の `robots: noindex` が実際に効くか
    - 見出し階層（1ページに h1 が1つか、h2/h3 の飛びがないか）
    - 画像の alt、リンクの実体（`<div onClick>` でリンクを作っていないか）
    - 構造化データ（JSON-LD / Organization / Product / FAQPage）の有無と、
      **入れるべきか否かの判断**（FAQセクションがあるので FAQPage の候補）
    - 本文が JS 実行前に存在するか（サーバーコンポーネント中心になっているか）
13. **3D負荷 / スマホ性能** — `components/Hero.tsx` の `useEnable3D` 条件、
    `components/three/HeroScene.tsx` の draw call・テクスチャ枚数・
    IntersectionObserver による停止、`components/DashboardMock.tsx` のフォールバック、
    `prefers-reduced-motion` 対応、バンドルサイズ、メモリリーク（テクスチャ／ジオメトリの dispose）。
14. **CV導線** — Hero CTA →「3分ツアー」→ 各機能 → ROI試算 → 料金 → `/demo` → 相談フォーム
    の導線に断絶がないか。アンカーリンク（`#tour` `#roi` `#scope` `#pricing` `#contact`）が
    全部生きているか。スマホでの可読性・タップ領域・固定CTAバー（`MobileCTA.tsx`）の被り。
    フォームの入力項目が多すぎて離脱を招かないか。
15. **アクセシビリティ** — キーボード操作（タブ・ツアーの `role="tablist"`、FAQの開閉、
    スライダー）、フォーカスリング、コントラスト比、ARIA属性の正しさ、
    JavaScript無効時に最低限の情報が読めるか。
16. **法令表現** — 景品表示法（優良誤認・有利誤認）、特定商取引法、資金決済法、個人情報保護法。
    断定・誇大表現、根拠のない二重価格、カウントダウン等の煽りが1箇所も残っていないこと。
    料金表示が通常価格のみになっていること。

## 出力形式

問題点ごとに、以下の形式で列挙してください。

```
[緊急 | 高 | 中 | 低] 見出し
場所: ファイルパス:行番号
問題: 何が問題か（1〜3行）
根拠: なぜ問題か（規約・法令・技術的理由）
修正案: 具体的にどう直すか（差分ではなく方針＋該当箇所の書き換え案）
```

深刻度の基準は次のとおりです。

- **緊急** — 情報漏洩・権限突破・法令違反に直結する。公開前に必ず直す
- **高** — 誤解を招く表現、CV導線の断絶、明確なバグ。公開前に直す
- **中** — 品質・SEO・アクセシビリティの明確な不足。公開後すぐ直す
- **低** — 改善提案・好みの範囲

最後に、**優先度順の対応リスト**を10件以内でまとめてください。
