# 製品マニフェスト（まだ残っていること）

最終更新：2026-08-26

---

## この紙は何か

「もう出来ていること」ではなく、**まだ出来ていないこと**だけを書く紙です。

出来たことは、画面と試験が証明します。
出来ていないことは、誰かが書き留めておかないと、そのまま忘れられます。
忘れられたまま契約すると、契約書のほうが先に約束してしまいます。

★ここに書いてあるものは、**まだ自動では直しません。**
　直すときは、必ずご本人の確認を取ってから直します。

## 1. 納期の書き方を、書類ぜんぶで合わせる（優先）

LPには、こう書きました。

    制作期間：20〜40日程度
    （ご依頼内容・ご確認のお戻り時期により前後します）

★「必ず20日で完成」「40日以内を保証」とは書きません。
　景品表示法の有利誤認にあたるおそれがあるためです。

### 合わせる必要がある書類

| 書類 | いまの状態 | やること |
|---|---|---|
| LP（`content/` 一式） | ✓ 統一済み。ビルド前検査（`DELIVERY_PERIOD_REQUIRED`）で固定 | — |
| 見積書のひな形 | **未確認** | 同じ文言に差し替える |
| 契約書のひな形 | **未確認** | 同じ文言に差し替える。★納期の「保証」と書かないこと |
| 営業資料（PDF・スライド） | **未確認** | 同じ文言に差し替える |
| 送信完了ページ・自動返信メール | ✓ LP側は統一済み | メール本文を実装したら、もう一度確認する |

★ここが食い違うと、いちばん困る場所（お金の話）で食い違います。
　「LPには20〜40日と書いてあったのに、契約書は30日固定だった」は、
　そのまま揉めごとになります。

## 2. LPの「実還元率」を、3種類の呼び分けに合わせる（★2026-08-26 完了）

ご承認をいただいて、二つとも行いました。

| | |
|---|---|
| 設計還元率 | 作ったときの予定 |
| 残数還元率 | 残っている景品 ÷ 残っている口数 |
| 実績還元率 | 実際にお客様へ返った額 |

### やったこと①　言葉を、意味に合わせて直した

**204 か所** を、意味ごとに直しました。

| 直した先 | 何件 | どういう場所か |
|---|---|---|
| 残数還元率 | 大半 | 「残っている景品 ÷ 残りの販売総額」を指していた場所 |
| 実績還元率 | 9か所＋「実還元率モニタ」6か所 | 管理画面の「実績還元率」の画面そのものを指していた場所 |

★**わざと直さなかった箇所が6つ**あります。

    「★「実還元率」に戻さないこと」

という、戻さないための警告文です。
ここまで書き換えると、警告の意味そのものが消えてしまいます。
（`components/console/menu.ts` ／ `screens/RtpScreen.tsx` ／ `screens/GachaList.tsx`
　／ `lib/console/rtp.ts` ／ `tests/adminShell.test.ts`）

★そのあと、公開先のLPを実際に目で見て、**言い方の揺れを13か所**見つけ、直しました。

| 直す前 | 直したあと |
|---|---|
| 設定時還元率／設定還元率 | 設計還元率 |
| 残数ベース還元率／残数ベース | 残数還元率 |

　あわせて、行の途中で言葉が割れないための一覧（`lib/jp.tsx` の `NO_BREAK_TERMS`）にも、
　**設計・残数・実績の3つをそろえて登録**しました（「実績還元率」が抜けていました）。

★以後、**設定還元率・設定時還元率・残数ベース還元率・実還元率**という呼び方には戻さないこと。

### やったこと②　「実績還元率」を、新しい売り文句としてLPに足した

新しい幕を1つ足しました（`components/sections/ActualRtp.tsx`）。

    設計値は、約束にすぎません。
    実際にいくら返したかまで見張ります。

中身は3つです。

1. 設計・残数・実績を、**横に並べて言い切る**（いつ見る数字なのかも書く）
2. **分母と分子を、必ず一緒に出す**（割合だけでは、人が正しさを確かめられない）
3. **分からないときに 0％や100％を出さない**（「まだ判断できません」と理由を出す）

★置き場所は「販売中に、システムが何を見張っているのか」の**いちばん先頭**です。
　これから の数字（設計・残数）の話より **前** に置いています。
　「予定の数字だけを信じないでください」を先に言うためです。

★金額の直前の要約（`OsSummary`）の 04 番も差し替えました。

    前： リアルタイム還元率 ／ 残り口数と売上が動く
    後： 還元率を3つで見張る ／ 設計・残数・実績を分けて出す

　ここに入っていないものは、お客様にとって「買うもの」に入りません。

★書かなかったこと（景品表示法）
　「必ず儲かる」「絶対に赤字にならない」とは書いていません。
　この機能がするのは **気づける状態をつくること** までで、
　止めるか続けるかを決めるのは運営の方です。そう書いてあります。
