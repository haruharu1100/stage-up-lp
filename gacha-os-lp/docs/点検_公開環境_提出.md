## 5. Previewでしか見つからなかった不具合（重要）

### ★還元率の単位取り違え（実害あり・修正済み）

- **症状**：画面に「設計還元率 88.0％」と出ているのに、実際にお客様へ返っていたのは **18.23％** だった。
- **数字**：売上 50,000pt に対し、お返し 9,113pt（500回の抽選記録より）。もう1社も 17.00％。
- **原因**：還元率を「％」で受け取る計算に、「比率（0.88）」が入っていた。結果、D賞が1ptまで潰れ、上位賞も下限値に貼りついていた。
- **なぜ気づかなかったか**：エラーが一切出ず、画面もきれいに表示され、**お客様に不利な方向にだけ**ずれていた。手元のテストでは検出できず、Previewの実データを数えて初めて分かった。
- **対処**：
  1. 計算側で単位を自動でそろえ、間違った値が来たら警告を出す
  2. 種データを「％」表記に統一
  3. Preview のDBを正しい値へ修正
  4. 公開前検査に専用テストを追加（4件）
  5. Preview実測に「画面の還元率どおりの額が本当に用意されているか」の確認を追加
- **確認**：修正後、設計88％ ／ 箱の中身88.0％ ／ 等級5種すべて一致。

### 点検の仕掛け側の不具合（修正済み）

抽選の口数を足すときに、賞ごとの本数を足していなかったため 409 エラーが出ていた。点検スクリプト側の問題であり、製品の不具合ではないが、同じ間違いは運用でも起こり得るため、口数と中身を必ず一緒に増やすよう直した。

## 6. キャッシュ検査

**サーバー側（7件・すべて合格）**
ログイン情報・会社の要約・お客様の残高・監査ログ・注文一覧は、すべて `private, no-store, no-cache, max-age=0, must-revalidate`。
一方、ログイン不要の会社案内ページは no-store にしていない（表示速度を落とさないため）。

**ブラウザ側（7件・すべて合格）**
通常更新／強制更新／別タブ／別ブラウザ／戻る・進む／ログアウト後の戻るボタン、いずれでも古い残高は出ない。
ログアウト後に戻るボタンを押すと、中身は表示されずログイン画面へ送られる。

**ビルド時の見張り**
認証・権限に関わる入口をキャッシュ扱いにしたら、ビルドが止まる仕組みを入れてある。

## 7. 会社ごとの分離（Tenant Isolation）

A社 ↔ B社 の**双方向**で8項目すべて合格。
担当者・お客様・注文・発送・要約・監査ログのどこにも相手の会社は出ない。
会社をまたいだ抽選（404）、他社の発送操作（404）、他社の景品交換（404）も、すべて拒否される。

## 8. 権限変更・アカウント停止の即時反映

**権限を外した直後、再ログインなしで、開いたままの画面が使えなくなる**ことを実測（403 FORBIDDEN）。
**利用停止した直後も、再ログインなしで**抽選・ポイント交換・発送依頼・住所変更のすべてが止まる。
停止した人は、ログインし直しても入れない。どちらも試験後に元へ戻し済み。

## 9. 抽選とポイント

- 二重抽選の防止：鍵なしは拒否、同じ鍵の再送は1件のまま、6回同時に押しても1件のみ
- 残高・在庫・履歴・商品が、すべて同時に正しく動く
- 抽選が監査ログに残る
- DBの残高を変えたら、次の読み取りで必ず新しい値になる
- 24台のサーバーに当たっても、全部同じ残高が返る

## 10. 注文と発送

- 3点まとめて依頼 → 運営の一覧にすぐ出る
- 2点だけ発送（分割発送）→ 残り1点は「まだ発送していない」まま
- 同じ明細を2回発送できない（409）／同時に2回押しても二重にならない
- 運営が発送を進めると、お客様の画面にすぐ出る
- **住所を変えても、すでに作った送り状の宛先は動かない**（住所の写しが効いている）
- 交換済みの商品は発送できない／発送依頼した商品は交換できない
- 同じ商品に「交換」と「発送依頼」を同時にぶつけても、片方しか通らない

### ★構造的な指摘：実績還元率が、どこにも表示されていない

抽選のたびに「売上」と「お返しした額」は記録されています。しかし、**それを表示する画面が1つもありません**。

今回の88％→18％の不具合を唯一暴けたはずの数字が、集めておきながら捨てられている状態でした。

| **PRODUCT** | **PRODUCT PASS = NO** | 下記のとおり、契約者にそのまま渡せる状態ではありません。 |

### PRODUCT PASS = NO とした理由（2026-08-26 判定変更）

当初これを「条件付き合格」としていましたが、**甘い判定でした**ので取り消します。

**TECHNICAL PASS と PRODUCT PASS は別物です。**
中核の処理が強くなってきたことと、契約者にそのまま渡せることは、まったく別の話です。
中身が正しく動くことは、製品として売れることを意味しません。

NO の理由は4つです。

1. **管理画面19本のうち13本が見本データ**
2. **権限変更・利用停止に、管理画面からの操作口が無い**（DBを直接触るしかない）
3. **実績還元率を見る画面が無い**
4. **外部のメール・決済・配送が未接続**

### PRODUCT PASS = YES にできる条件

以下を **すべて** 満たしたときだけ YES にします。1つでも欠けたら NO です。

- [ ] 主要な管理画面が実データで動く
- [ ] 実績還元率を確認できる
- [ ] 権限を変更できる
- [ ] 利用を停止できる
- [ ] その操作が保存される
- [ ] 会社ごとに分離されている
- [ ] お客様側と連動している
- [ ] LP で AVAILABLE と書いた機能が、実際に動く
