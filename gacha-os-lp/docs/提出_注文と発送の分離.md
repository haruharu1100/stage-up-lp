作成日：2026-08-25
確認に使った場所：`http://localhost:3218`（Preview専用のデータベース `.data/dev.db`）

## 0. 先に、いちばん大事なところ

**画面だけを分けて、中身は同じ、にはなっていません。**

- 注文（`orders` / `order_items`）と、発送（`shipments` / `shipment_items`）は、
  データベース上でも**別の表**です。
- 1つの注文を、複数の発送に分けられます。
- 同じ商品を2つの発送へ入れることは、**データベースの決まりとして**できません
  （画面で押せないようにしただけ、ではありません）。

## 2. データベースの構造

```
orders                受注そのもの（誰が・いつ・いくら・全体の状態）
 └ order_items        注文の明細（商品ごと）
                      assigned_quantity … いま発送へ割り当てている数
                      shipped_quantity  … 実際に出した数
shipments             箱（1注文に何箱でも作れる）
                      shipping_address_snapshot … 作った時点の宛先の写し
 └ shipment_items     箱に入れた明細
                      released_at … 発送を取り消した時に入る（行は消さない）
number_series         注文番号・発送番号を採る場所（同時でも重ならない）
```

### 二重発送を止めている決まり（機械が止めます）

```sql
CREATE UNIQUE INDEX ux_shipment_items_live
  ON shipment_items (tenant_id, order_item_id)
  WHERE released_at IS NULL;
```

同じ注文明細が、生きている発送に2回入ることはできません。
発送を取り消すと `released_at` が入り、その商品は**もう一度発送できる状態へ戻ります**
（行は消しません。消すと「一度箱に入れた事実」が消えます）。

```sql
CREATE UNIQUE INDEX ux_order_items_prize
  ON order_items (tenant_id, prize_id) WHERE prize_id IS NOT NULL;

CREATE UNIQUE INDEX ux_shipments_tracking
  ON shipments (tenant_id, carrier, tracking_number) WHERE tracking_number IS NOT NULL;
```

- 同じ景品を2回注文には入れられません。
- 同じ配送会社で、同じ追跡番号を2つの荷物に付けられません。

★追跡番号は**出荷（発送済み）より先に**登録しなければ進めません。
番号のない「発送済み」を作ると、お客様に「出しました」とだけ言って、
追う手段を渡さないことになるためです。

（`scripts/seed-shipping-scenario.mjs`）。きれいに終わったデータだけでは、
「残り1点」の欄が正しいかを確かめられないためです。

| 注文 | 作った状態 |
| --- | --- |
| ORD-00001 | 3点のうち2点だけ発送済み（追跡番号あり）＝分割発送 |

| ORD-00003 | 一度作った箱を取り消した（商品は発送待ちへ戻った） |

## 7. 記録（監査ログ）の実例

実際に残っていたものです（`scripts/peek-audit.mjs` で読めます）。

```
seq=2  2026-08-25T08:22:25.862Z  SHIPMENT_SPLIT  対象=shp_01M0W06XA6…
       要約： 注文 ORD-00001 を分けて、発送 SHP-00001 を作りました（2点）。
       後　： 特製カード（架空）、アクリルスタンド（架空）
       中身： {"isSplit":true,"itemCount":2,"orderNumber":"ORD-00001",
               "shipTo":"〒100-0001","shipmentNumber":"SHP-00001", …}
       実行者：確認用の担当者（ADMIN／OPERATOR）
       つながり： prev=fd477deb93ec… / hash=3663de6da58b…

seq=5  SHIPMENT_TRACKING_SET   発送 SHP-00001 に追跡番号を登録しました。
       後　： ヤマト運輸 4649-46145867

seq=12 SHIPMENT_CANCEL         発送 SHP-00003 を取り消しました。
       理由： 中身の傷を確認したため、箱を作り直します
```

- **誰が・いつ・何を・前は何で・後は何か・なぜ**が、1件ずつ残ります。
- 1件ごとに、前の記録のハッシュを含めています（`prev_hash` → `hash`）。
  途中の1行を書き換えると、そこから先が全部つながらなくなります。
- 取り消しには**理由が必須**です（4文字以上）。
