# 「管理サイト」と「ユーザー側」が、同じ1つのデータを見ていることの記録

ここに入っている16枚は、**1つのブラウザを開いたまま、途中で読み込み直さずに**
順番に撮ったものです。

途中でページを開き直すと、それは「別々のサンプルを2つ見せただけ」になり、
いちばん見ていただきたい「本当につながっているのか」が証明できません。
だから、通しで1回操作したものを、そのまま並べています。

撮り直すとき：

```
npm run dev                                        # 既定では http://localhost:3210
node scripts/shoot-two-sides.mjs http://localhost:3210
```

playwright はこのプロジェクトの依存ではありません。
同じリポジトリの `blog-to-social` が持っているものを借ります。
別の場所にあるときは `PLAYWRIGHT_DIR` で教えてください。

## この操作で確かめたこと

| 何を確かめたか | どの絵で分かるか |
| --- | --- |
| 上の帯で、どちら側を見ているかが常に分かる | 全16枚（どの絵にも帯が写っています） |
| 運営の入口は、ログインと2段階認証を通らないと開かない | 01 |
| お客様の画面には、ログインも2段階認証も要らない | 02 |
| 当たった商品は「発送する」か「ポイントに交換する」を選べる | 03・04 |
| 発送を選ぶと、もうポイントには交換できないと先に伝える | 05 |
| 発送の依頼は、その場で発送手配中に入る | 06 |
| ポイント交換は、交換後の残高まで見せてから確定する | 07 |
| **交換した商品は、もう発送できない（二重処理の防止）** | 08 |
| いまの残高になるまでの動きが、すべて残っている | 09 |
| AIが答えられない問い合わせは、人へ回る | 10 |
| **お客様の操作が、そのまま運営の数字に出ている** | 11 |
| さきほどの発送依頼が、運営の一覧に入っている | 12 |
| 人へ回った問い合わせが「要確認」として届いている | 13 |
| 残高と履歴が合っているかを、毎回点検して出している | 14 |
| 会員1人ごとに、商品・発送・問い合わせ・ポイントが1画面で追える | 15 |
| **お客様の操作も、誰が何をしたかの記録に残る** | 16 |

数の突き合わせは、絵を見て判断するのではなく、
スクリプトの中で機械的に確かめています。
「受け取り方法を選ぶ待ち」が、操作したぶんちょうど2件減っていなければ、
撮影そのものが止まります。

## この撮影で見つけて直したこと

**運営向けの知らせが、お客様の画面に出ていた。**

上の帯で切り替えると、お客様のマイページの先頭に

> 運営 太郎（管理者（全権））としてログインしました。

が出ていました。担当者の名前と役割です。
デモなので実害はありませんが、本番なら、そのまま情報の漏れです。

知らせに「どちら側に向けて書かれた文か」を持たせ、
お客様の画面には、お客様向けのものだけを出すようにしました。

印を付ける場所は1か所（`reducer` の出口）にしています。
知らせを作っている場所はこの中に30か所近くあり、
1つずつ手で書き足すと、必ず書き忘れが出るためです。
書き忘れた1か所が、お客様に運営の名前を見せます。

再発は `tests/consoleTwoSides.test.ts` で止めています。
