# 本番接続手順（公開まであと4つ）

最終更新: 2026-08-20

サイト側の作りはもう終わっています。**残っているのは「外のサービスにつなぐ」ことだけ**です。
つなぐのは4つ。全部あわせて、慣れていなければ2〜3時間、慣れていれば1時間ほどです。

| # | つなぐもの | 何のため | これが空だとどうなるか |
|---|---|---|---|
| ① | 問い合わせの通知先 | お客様からの相談を受け取る | **送信されても誰にも届かない**（＝売上ゼロ） |
| ② | GA4 | どこで離脱したかを見る | 改善が全部「なんとなく」になる |
| ③ | Microsoft Clarity | 実際にどこまで読まれたかを見る | 同上 |
| ④ | 本番ドメイン | 正しいアドレスで公開する | シェアや検索が別の場所を指す |

---

## いちばん大事な考え方：「設定した」で終わりにしない

この手順書のすべての項目は、**3段階**で見ます。

| 段階 | 意味 | 誰が判定するか |
|---|---|---|
| `IMPLEMENTED` | コードとして実装されているか | 自動（もう全部済んでいます） |
| `CONNECTED` | 本番の外部サービスにつながっているか | 自動（設定値で判定） |
| `E2E VERIFIED` | **本当に最後まで通ったのを、自分の目で確かめたか** | **人がやるしかない** |

なぜ分けるのか。**「GA4のIDを入れた」と「GA4に本当に届いている」は別のこと**だからです。
IDを入れただけで完了にすると、公開して1か月後に「1件も計測されていなかった」ということが起こります。
画面上は準備完了に見えるのに、実際には何も届いていない ——
これは、この製品でいちばん避けたい壊れ方そのものです。

進み具合は **`/launch`** の画面で確認できます。3つそろって初めて `PRODUCTION READY = YES` になります。

## ① 問い合わせの通知先

### つなぐ

環境変数 `CONTACT_WEBHOOK_URL` に、**問い合わせ内容が飛んでいくURL**を1つ入れます。

> **まずは、普段確実に確認するメールアドレス1つに届けば十分です。**
> 最初からCRMを用意する必要はありません。「確実に気づける場所」がいちばん重要です。

いちばん手軽なのは **Google Apps Script（GAS）** です。スプレッドシートに1行ずつ貯めながら、
同時に自分のメールにも飛ばせます。手順は次の通りです。

1. Googleスプレッドシートを新規作成する（名前は「AI GACHA OS 問い合わせ台帳」など）
2. メニューの「拡張機能 → Apps Script」を開く
3. 下のコードを貼り付ける（`宛先メール` を自分のアドレスに変える）
4. 「デプロイ → 新しいデプロイ → 種類：ウェブアプリ」
5. 「次のユーザーとして実行：自分」「アクセスできるユーザー：**全員**」にする
6. 発行された **ウェブアプリのURL** をコピーする → これが `CONTACT_WEBHOOK_URL` の値です

```javascript
const 宛先メール = "ここに自分のメールアドレス";

function doPost(e) {
  const d = JSON.parse(e.postData.contents);
  const sh = SpreadsheetApp.getActiveSpreadsheet().getSheets()[0];

  // 1行目が空なら見出しを作る
  if (sh.getLastRow() === 0) {
    sh.appendRow([
      "受付日時", "受付ID", "状態", "お名前", "会社", "メール", "電話",
      "検討段階", "ご意向", "ご相談内容", "興味", "押したプラン",
      "営業担当(初回)", "経路(初回)", "utm_source", "utm_medium", "utm_campaign",
      "着地URL", "参照元", "ABパターン",
      "営業担当(最後)", "経路(最後)", "入り直し時刻",
      "提示プラン", "価格への反応", "失注理由", "メモ"
    ]);
  }

  sh.appendRow([
    d.receivedAt, d.requestId, d.status, d.name, d.company, d.email, d.tel,
    d.stage, d.intent, d.message, (d.interests || []).join(" / "), d.plan,
    d.source.ref, d.source.channel, d.source.utmSource, d.source.utmMedium,
    d.source.utmCampaign, d.source.landing, d.source.referrer, d.source.variant,
    d.lastTouch.ref, d.lastTouch.channel, d.lastTouch.at,
    "", "", "", ""   // ← ここから右は、商談後に人が手で入れる欄
  ]);

  MailApp.sendEmail({
    to: 宛先メール,
    subject: "【AI GACHA OS】お問い合わせ " + (d.company || d.name),
    body:
      "受付日時: " + d.receivedAt + "\n" +
      "お名前  : " + d.name + "\n" +
      "会社名  : " + d.company + "\n" +
      "メール  : " + d.email + "\n" +
      "電話    : " + d.tel + "\n" +
      "検討段階: " + d.stage + "\n" +
      "押したプラン: " + d.plan + "\n" +
      "営業担当: " + d.source.ref + "（最後: " + d.lastTouch.ref + "）\n" +
      "経路    : " + d.source.channel + " / " + d.source.utmSource + "\n" +
      "─────────────\n" + d.message,
  });

  return ContentService.createTextOutput("ok");
}
```

> 台帳の右端（提示プラン・価格への反応・失注理由・メモ）は、**商談が終わってから人が入れる欄**です。
> ここが空のまま溜まると、あとから「なぜ売れなかったのか」を数えられなくなります。
> 何を入れるかは `docs/計測ガイド.md` の 5-3 を見てください。

### E2E VERIFIED にする（設定しただけでは完了にしない）

自分で実際に1件テスト送信して、**下の7つが全部そろったら**チェックを付けてください。

- [ ] 問い合わせが実際に届く
- [ ] 選んだプラン（GROWTHなど）が残っている
- [ ] 営業担当（sales_ref）が残っている
- [ ] 広告のUTMが残っている
- [ ] 最初の経路（first_touch）と最後の経路（last_touch）が両方残っている
- [ ] 日本語が文字化けしていない
- [ ] 同じ内容が二重に通知されない

テスト送信のやり方：

```
https://（本番URL）/?ref=sales01&utm_source=test&utm_medium=manual&utm_campaign=e2e
```

このURLで着地 → 料金セクションで **GROWTH** のボタンを押す → 問い合わせフォームを送信。
届いた通知に `sales01` と `growth` と `test` が入っていれば、導線がつながっています。

二重通知の確認は、**送信ボタンを素早く2回押す**か、送信後に**ブラウザの戻るボタンで戻って再送信**してみてください。
2件届いたら不具合です（2分以内の同じ内容は1件にまとめる作りになっています）。

## ② GA4（アクセス解析）

### つなぐ

1. GA4 で、このLP用のプロパティを作る（事業サイト用の既存プロパティに相乗りしても構いません）
2. 「データストリーム → ウェブ」を作り、**測定ID（`G-` から始まる）** をコピー
3. 環境変数 `NEXT_PUBLIC_GA4_ID` に入れて再デプロイ

**そのあと必ず1回だけやること：**
GA4 の「管理 → データの表示 → カスタム定義」で、次の3つを
**カスタムディメンション（イベントスコープ）** として登録してください。

```
sales_ref / lead_channel / hero_variant
```

登録しないと、探索レポートで**営業担当ごとに分けられません**。
「全体のCVRは3%でした」しか分からず、誰の資料の渡し方が悪いのかが永遠に見えなくなります。

### E2E VERIFIED にする

実際のブラウザで下の6つを操作し、GA4 の **「レポート → リアルタイム」** で受信を確認します。
（反映まで数十秒かかることがあります）

- [ ] `demo_start`（デモを開いた）
- [ ] `backtest_view`（バックテストを見た）
- [ ] `roi_complete`（ROI計算を最後までやった）
- [ ] `pricing_view`（料金まで到達した）
- [ ] `plan_select`（プランのボタンを押した）
- [ ] `contact_submit`（問い合わせを送った）

> 広告ブロッカーが入っていると届きません。確認は**シークレットウィンドウ**か、
> 拡張機能を切ったブラウザで行ってください。

## ③ Microsoft Clarity（録画・ヒートマップ）

### つなぐ

1. Clarity でプロジェクトを作る（無料）
2. **プロジェクトID** をコピー
3. 環境変数 `NEXT_PUBLIC_CLARITY_ID` に入れて再デプロイ

### E2E VERIFIED にする ── ここは「個人情報の事故」に直結します

タグを置いただけでは完了にしません。**録画に個人情報が写り込むと、それ自体が事故**です。

やること：自分で1回、**問い合わせフォームまで実際に入力**して送信する
→ 数分後に Clarity の「Recordings」でその録画を再生する
→ 下の4つが**見えないこと**を確認する。

- [ ] 録画に氏名が写っていない
- [ ] 録画にメールアドレスが写っていない
- [ ] 録画に電話番号が写っていない
- [ ] 録画に問い合わせ本文が写っていない

サイト側では入力欄をマスキングする指定を済ませていますが、
**実際の録画を1回見るまでは「効いている」と判断しないでください。**
1つでも見えていたら、公開せずに連絡してください（マスキング指定の追加で直せます）。

## ④ 本番ドメイン

### 決める

製品名そのものを使う形（`gacha-os.jp` / `aigacha-os.jp` / `gacha-system.jp` など）が、
このサービスとは相性が良いと考えています。制作会社っぽい社名ドメインより、
**何のシステムかが名前だけで伝わる**ためです。取得可否は別途ご確認ください。

### つなぐ

1. ドメインを取得する
2. Vercel のプロジェクトに独自ドメインとして追加する（DNS設定は Vercel の指示通り）
3. 環境変数 `NEXT_PUBLIC_SITE_URL` に **`https://（取得したドメイン）`** を入れる（末尾のスラッシュ無し）
4. 再デプロイ

> `localhost` / `〜.vercel.app` / `staging.〜` / `preview.〜` のURLは**本番URLとして受け付けません**。
> 入れた場合は公開前チェックが止めます。

canonical・OGP・sitemap・robots・構造化データは、すべてこの1か所を見ています。
**ソースにURLを直書きしていない**ので、ここを変えれば全部いっせいに変わります。

### E2E VERIFIED にする

- [ ] canonical が本番URLになっている
- [ ] OGP（SNSシェア時の画像・タイトル）が本番URLで正しく出る
- [ ] sitemap.xml が本番URLで出る
- [ ] robots.txt が本番URLで出る
- [ ] 構造化データが本番URLになっている
- [ ] 問い合わせURL・デモURLが本番URLに統一されている
- [ ] localhost / preview / staging / 古い vercel.app のURLが1つも残っていない

最後の1つは、目視では必ず見落とすので機械にやらせます。

```
npm run check:urls
```

「開発用・プレビュー用のURLは残っていません」と出れば完了です。
OGPの見え方は、X（Twitter）の Card Validator か、実際にSlackへURLを貼って確認するのが早いです。

## ⑤ 最後に、本番相当で1本通す

個々の項目が○でも、**つないだ瞬間に切れることがあります**。
なので最後に、営業が実際にやる順番のまま、最初から最後まで通します。
途中で情報が切れていたら、そこを直してやり直しです。

- [ ] 営業URL（`?ref=sales01`）を開く
- [ ] LPが正しく表示される
- [ ] デモを開く
- [ ] バックテストを見る
- [ ] ROIを計算する
- [ ] 料金まで到達する
- [ ] **GROWTH を選ぶ**
- [ ] 問い合わせを送る
- [ ] 通知が届く（プラン・営業担当・UTM・経路が残っている）
- [ ] GA4とClarityに記録されている

**ここが通ったら `PRODUCTION READY = YES` です。**

## 補足：ビルドが通っても、公開してよいとは限りません

デプロイ時に自動チェックが走り、**①〜④が未設定なら本番ビルドは失敗**します（＝公開されません）。
これは事故を防ぐための仕組みですが、逆は成り立ちません。

> **ビルドが通った ＝ CONNECTED まで済んだ**
> **公開してよい ＝ E2E VERIFIED まで済んだ**

機械に判定できるのは「IDが入っているか」までです。
「本当に届いたか」「本当に録画に個人情報が写っていないか」は、**人が1回やってみるしかありません。**
`/launch` の画面で、細目を1つずつチェックしてください。
