## 3. 各社のメモ

### 3-1. Resend

**【確認できた事実】**
- 無料3,000通/月・100通/日・ドメイン3個。Pro $20で50,000通、Scale $160で200,000通。追加ドメインは $20/月で100ドメイン（Pro/Scale限定）。専用IPは$30/月だが Scale かつ1日3,000通以上が条件。（https://resend.com/pricing）
- ドメイン追加をAPIでできる。リージョンに `ap-northeast-1`（東京）を選べる。返ってくるDNSは SPF(TXT) と DKIM(CNAME 3本)。**DMARCは返ってこない＝自分で別に設定が必要。**（https://resend.com/docs/api-reference/domains/create-domain）
- 配信停止リストは、ハードバウンス・苦情で自動追加。公式に「Suppressions apply to your entire team.（全ドメイン・全サブドメインで飛ばされる）」と明記＝**全店舗で共通**。API で一覧・追加・削除が可能。（https://resend.com/docs/dashboard/emails/email-suppressions）
- Webhook は `email.sent` / `delivered` / `bounced` / `complained` など。5秒→5分→30分→2時間→5時間→10時間で再送、at-least-once。（https://resend.com/docs/dashboard/webhooks/introduction）
- テスト用アドレス `delivered@resend.dev` / `bounced@resend.dev` / `complained@resend.dev` / `suppressed@resend.dev` がある。ただし**テスト送信も送信枠を消費する**と明記。（https://resend.com/docs/dashboard/emails/send-test-emails）

**【要確認・不明】**
- 配信停止リストが全店舗共通である点は、**このシステムにとって構造的な弱点**。A店でバウンスした人へ、B店から送れなくなる。店舗別に持ち直す実装が別途いる。
- 「Resend は Amazon SES の上で動いている」という指摘が第三者記事に複数あり、DKIMのCNAMEも `amazonses.com` を指している。ただし**公式の明示的な声明は確認できず＝不明。**
- 日本語サポートの有無：**不明**。
- 日本のキャリアメール宛の到達率に関する公式記述：**不明**。
- アカウント審査の有無・所要日数：**不明**。

### 3-2. Amazon SES

**【確認できた事実】**
- 従量課金は送信 **$0.10/1,000通**。プラン制は Essentials $0.16/1,000通（月額$0）、Pro $105/月＋$0.22/1,000通、Enterprise $500/月＋$0.23/1,000通。専用IPは標準$24.95/月/IP。（https://aws.amazon.com/ses/pricing/）
- **Tenants（テナント）機能が正式にある。** 1アカウント内に最大10,000テナント（申請で最大300,000）。テナントごとに送信ID・設定・**評判の記録を分ける**ことができ、公式に「a high bounce rate or complaint rate from one tenant doesn't impact the deliverability of emails sent by other tenants（1つのテナントのバウンス率・苦情率が、他のテナントの到達に影響しない）」と明記。1,000テナントを超えた分が $0.005/月/テナント。（https://docs.aws.amazon.com/ses/latest/dg/tenants.html）
- **配信停止リストをテナント単位にできる**（`SuppressionScope=TENANT`）。既定はアカウント単位で自動（ハードバウンスと苦情）。`ListSuppressedDestinations` などでAPI操作可。（https://docs.aws.amazon.com/ses/latest/dg/sending-email-suppression-list.html）
- **Sandbox**：新規は全リージョンでSandbox。検証済みアドレス宛のみ・24時間200通・毎秒1通。本番申請時に連絡言語で**日本語を選べる**。「The AWS Support team provides an initial response to your request within 24 hours（24時間以内に一次回答）」と明記。（https://docs.aws.amazon.com/ses/latest/dg/request-production-access.html）
- 東京（ap-northeast-1）・大阪（ap-northeast-3）ともエンドポイントあり。検証IDの上限は1リージョン10,000。（https://docs.aws.amazon.com/general/latest/gr/ses.html）

**【要確認・不明】**
- 本番申請は審査。**オンラインガチャ／オリパという業態でどう判断されるかは読めない＝要確認。**
- DNSレコードの具体的な手順（Easy DKIM の CNAME 3本、カスタムMAIL FROM の MX+SPF）は**今回、公式手順ページを直接確認していないため断定しない。**
- 「Essentials ではテナントを別途購入」という記述の正確な条件は**要確認**。
- Webhook 相当が SNS / EventBridge 経由で、他社のような HTTP POST をそのまま受ける形ではない。**受け取り側を自分で組む手間が増える。**

## 4. 日本のキャリアメールについて（★ここが一番の落とし穴）

**【確認できた事実】**
ドコモの公式ページで、利用者が**アドレス／ドメイン単位で受信・拒否を個別に設定できる**こと、
なりすまし対策・警告表示の仕組みがあることが確認できます。
（https://www.docomo.ne.jp/info/spam_mail/domain/）

**【要確認・不明】**
今回調べた**どの海外事業者も、docomo / au / SoftBank 宛の到達率を公式に保証・明示していません。**
つまり「この会社なら日本のキャリアに強い」という**断定は、どの会社についてもできません。**
blastengine だけが「国内到達率99%以上」と書いていますが、これは**ベンダー自身の主張**です。

**実務で本当に効くのは、会社選びよりも次の3つです。**

1. SPF・DKIM・DMARC を、**店舗のドメインで正しく立てる**
2. バウンス・苦情の**自動停止を必ず回す**（届かない宛先へ送り続けると、全体が巻き添えで落ちる）
3. **会員登録の画面に「@〜 からのメールを受信できるよう設定してください」の案内を必ず出す**
   （キャリア側の受信拒否は、利用者本人にしか解除できないため）

★3番目は**このシステム側で作る必要がある画面**です。会社選びでは解決しません。

## 5. おすすめ（※これは「おすすめ」であって確定ではありません）

### 第1候補：Amazon SES（東京リージョン）＋ Tenants

**理由：** 今回の要件で唯一、「店舗ごとの評判分離」と「店舗ごとの配信停止リスト分離」が
**公式機能として存在するのが SES だけ**だからです。
A店が荒れてもB店が巻き添えで止まらない、という性質は、
複数の店舗に売るシステムでは決定的です。
費用も桁が違い（20万通で約$20＝3,000円前後）、店舗が増えても料金の形が壊れません。
本番申請の連絡言語に**日本語を選べる**のも、運営者にとって安心材料です。

**正直に言うトレードオフ：**
SES は「部品」であって「完成品」ではありません。
配信状況の受け取りが HTTP ではなく AWS 内の仕組み経由になるため、
**作る手間が Resend の2〜3倍はかかります。**
管理画面も運営者が見て分かるものではないので、こちら側で作る前提です。
さらに Sandbox 解除の審査を通す必要があります。

### 第2候補：Resend（作る速さを優先する場合）

Next.js / TypeScript との相性が最も良く、ドメイン追加API・東京リージョン・
テスト用アドレス・Webhook が揃っていて、20万通でも$160。
**ただし配信停止リストが全店舗共通**という一点が構造的な弱点で、
店舗別のバウンス管理をこちらで作り直す必要があります。
**店舗が10〜30社くらいまでなら、十分に現実的です。**

### 実務的にはこれが最有力かもしれない：併用

まず Resend で作って最初の店舗を回しつつ、**並行して SES の本番申請を出しておく。**
店舗が増えた段階で SES へ寄せる。
送信部分をシステム内で1つの入口（`sendMail()`）にまとめておけば、あとから差し替えられます。
**この「1つの入口」は、すでに実装済みです**（Mail Provider を差し替え可能にする対応が完了しています）。

### 慎重に扱うもの

| 会社 | 理由 |
|---|---|
| SendGrid | Subuser 上限15の疑い。店舗が増える前提のSaaSでは上限に当たるリスク（**要確認**） |
| Postmark | 20万通で約$246と単価が高い。日本語サポートも確認できず |
| Brevo | 公式数値が取れず。宣伝と同じメーターの可能性があるため保留 |
| blastengine | 国内サポート・日本語という強みは明確。ただし**マルチテナント対応が公式ページで一切確認できない**ため、現時点では推奨も否定もできない |
