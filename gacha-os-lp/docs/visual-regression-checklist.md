# VISUAL REGRESSION CHECKLIST（見た目の再発防止表）

実機のiPhoneで撮った7枚のスクリーンショットから出てきた指摘を、
二度と出さないための表です。**「ビルドが通った」は、この表を1つも満たしません。**

機械で測る部分は `scripts/check-design.mjs` に入っています。

```
npm run build && npm start          # 別の窓で立ち上げておく
npm run check:design                # 7項目＋コンソールエラーを測る
```

すべて通ると `見た目の検査はすべて通りました。` と出ます。
1つでも残っていると、どの画面幅のどこが悪いかを名指しして終了コード1で止まります。

## 検査する画面幅

`375 / 390 / 430 / 768 / 1024 / 1280 / 1440`

390px がいちばん多いスマホです。**新しいセクションを作ったら、まず390pxで見ること。**

## 1. 日本語が語の途中で折り返されていない

**何が起きたか**
「ここまでで人がしたのは、『伝える』と『確／認する』だけ。」——
`確` と `認する` が別の行に割れていました。高額な業務システムの販売ページとして、
この1文字で信用が落ちます。

**なぜ起きるか**
ブラウザは日本語をどこでも折り返します。放っておくと、意味の切れ目を無視します。

**どう防ぐか（3段構え）**

1. **手で改行を決める** — 見出しは「意味のまとまり」で行を分ける。ブラウザ任せにしない。
2. **割れてはいけない言葉を封じる** — `lib/jp.ts` の `jp()` を通す。
   見えない接着剤（WORD JOINER）を文字の間に入れ、その語だけは絶対に割れなくなります。
3. **画面幅ごとに文字の大きさを変える** — 幅が狭いのに文字が大きいと、必ずどこかで割れます。

**封じている言葉**（`scripts/check-design.mjs` の `PROTECTED`）

```
オンラインガチャ / 管理画面 / 実還元率 / 還元率 / 市場価格 / バックテスト
確認する / 承認する / 販売停止 / ラストワン賞 / 発送依頼
AI GACHA OS / 49,800円 / 94.8% / 119.0%
```

**新しく大事な言葉が増えたら、必ずここに足すこと。**

**合格ライン** 7つの画面幅すべてで 0件。

## 2. カードの中に、意味のない大きな空白が無い

**何が起きたか**
390px の移行セクションで、カードの右側に206pxの空白が出ていました。
高級感のある余白と、レイアウトが崩れてできた空白は、まったくの別物です。
後者は「作りかけ」に見えます。

**なぜ起きるか**
パソコン用に作った横並びの列が、スマホでもそのまま残っているためです。
`grid-template-columns` の固定幅、`max-width`、3D用に取ってある予約領域などが原因になります。

**どう防ぐか**
スマホでは、使っていない列を**完全に消して1カラムにする**。
幅を0にして隠すのではなく、並びそのものを縦積みに変える。

**合格ライン** カードの右に「幅の30%かつ80px超」の空きが 0件。

**測り方（ここを間違えると全部が嘘になる）**

- **スマホ幅（500px以下）だけで測ること。**
  パソコン幅で同じ物差しを当ててはいけません。横に広いカードに
  「・想定売上と想定原価」のような短い箇条書きが並ぶのは、正しい形です。
  一度パソコン幅にも当てて、正しい箇条書きが20件も不合格になり、
  本当の問題がその中に埋もれました。
- **文字だけでなく、絵も中身として数えること。**
  お客様画面のガチャの絵は写真ではなく、色を塗った四角の重ね合わせです。
  文字だけ数えると「右が103px空いている」と誤って報告します。
- **`<p>` や `<span>` の箱を測ってはいけません。**
  カードの中には、タグに包まれていない生の文章が普通にあります。
  箱だけ数えるとその文章が無いことになり、「右に200px空いている」という
  嘘の報告が大量に出ます（実際に43件出しました）。
  文字が実際に描かれている範囲を測ること。

## 3. 大きく見せる数字が、等幅の数字で組まれている

**何が起きたか**
`94.8%` の「4」が読みにくい、という指摘。数字の幅がバラバラだと、
桁が揃わず、脳が一瞬つまずきます。金額と還元率は、この商品の中心です。

**どう防ぐか**
大きく見せる数字には `.num-lead`（`font-variant-numeric: tabular-nums`）を当てる。
**文字間は広げない。** 広げると桁がバラけて、かえって読みにくくなります。

**合格ライン** `.num` / `.num-lead` が付いた要素で、等幅になっていないものが 0件。

## 4. ボタンの文字が2行に割れていない

**何が起きたか**
「ただちに販売停止を検討してくださ／い」——
最後の「い」だけが次の行に落ちていました。

**どう防ぐか**
スマホでは**短い言い方に変える**（「販売停止を検討」「移行を相談する」）。
説明は文章としてボタンの上に置き、ボタン自体は短く保つ。
ボタンは押す場所であって、文章を読む場所ではありません。

**合格ライン** `btn-` が付いたリンク・ボタンで、2行になっているものが 0件。

---

## 5. スマホ下部の固定バーに、本文が隠れていない

**何が起きたか**
下部にボタンが3つ並び、画面のかなりの面積を占めて本文が隠れていました。

**どう防ぐか**
- 主ボタン＝無料デモ、副ボタン＝導入相談、料金は**小さいリンク**にする（枠にすると高さが戻る）。
- バーの**実際の高さを測って** CSS変数に入れ、本文の下余白をそこから決める。
  文言を変えて高さが変わっても、隠れないようにするためです。

**合格ライン** バーに重なっている本文・見出し・箇条書きが 0件。バーの高さは画面の15%以内。

## 6. お客様画面が「まだガチャがありません」で止まっていない

**何が起きたか**
`MY SHOP / 12,500pt` の下がほぼ空で、「まだガチャがありません」だけが出ていました。
初めて見た人には、**何を売っているサイトなのかが伝わりません。**

**どう防ぐか**
デモは**必ず完成した状態を最初に見せる**。
ガチャの絵・タイトル・価格・残り口数・メインの賞・「1回引く」「10連」まで出す。
空の画面は、承認前を表す演出として1〜2秒だけにする。

**合格ライン** お客様画面に「まだガチャがありません」が出たままにならない。

## 7. 横スクロールが出ていない／列が細く潰れていない

**何が起きたか**
価格急騰セクションのタイムラインが390pxで4列。1枚66pxしかなく、
「残り 1000 口」と還元率が枠からはみ出していました。

**どう防ぐか**
日本語は2〜3文字＋数字で最低100pxほど要ります。
**100pxを切る列は作らない。** 4列が入らないなら 2×2 にする
（1000→800→500→200 の順序も、左上から自然に追えます）。

**合格ライン** 横スクロール 0件。枠から文字がはみ出している列 0件。

**どこからを「はみ出し」と呼ぶか**

余白（padding）は、文字を線から離しておくための場所です。
日本語では行末の「）」「。」「%」が数pxだけ余白側へ出るのが**正しい組み方**
（ぶら下げ）で、これは不具合ではありません。
そこで **「余白の半分までなら見逃す」** ことにしています。

**2px や 6px の決め打ちに戻さないこと。**
その厳しさだと、正しく組めている場所まで毎回23件ほど不合格になり、
本当のはみ出し（枠から80px出て数字が読めない）が、その中に埋もれます。

**この物差しで実際に見つかった本物のはみ出し（今回直したもの）**

| 場所 | 幅 | 何が起きていたか |
|---|---|---|
| 実還元率のメーター | 768px | 「市場価格ベース実還元率」と「87.8%」を横に並べたままで、数字が枠の外へ82pxはみ出していた。入らないときは数字を次の行へ落とす |
| 価格急騰の金額札 | 375px | 札が162px・内側122pxしかなく、`¥1,500,000` が枠からはみ出していた。狭い画面では金額を少し小さくする |
| フッターのリンク | 375px | 「導入について相談する」が144pxの列から16pxはみ出し、隣の列との隙間に食い込んでいた。フッターには短い言葉だけを置く |

## 撮った写真の読み方（大事）

セクションだけを切り出した写真では、**下部の固定バーが写真の途中に描かれます**。
そのため「ここに大きな空白がある」「見出しが隠れている」ように見えることがあります。
これは撮り方のクセで、実機では起きません。

**本当の見え方は `_verify/after-390-screen/`（画面そのままの写真）で確かめること。**
一度これを取り違えて、直す必要のない場所を探しました。
