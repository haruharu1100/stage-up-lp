この文書は「指摘に対して何をどう直したか」を、後から人が読んで分かる形でまとめたもの。

対応順は指示どおり **緊急 → 高 → 中 → 低**。

## 緊急（1件）— 対応済み

### E-1. HTTPセキュリティヘッダーが1つも無かった

- **何が問題だったか**：他人のサイトの中に当サイトを枠として埋め込み、
  ボタンを誤って押させる手口（クリックジャッキング）や、
  外部から差し込まれたスクリプトを止める仕組みが無かった。
- **どう直したか**：`next.config.mjs` に以下を追加。
  - Content-Security-Policy（読み込んでよい配信元をGA4・Clarityなどに限定）
  - X-Frame-Options / X-Content-Type-Options / Referrer-Policy
  - Permissions-Policy（カメラ・マイク・位置情報・決済・USBを明示的に閉じる）
  - Strict-Transport-Security（常時HTTPS）
  - `poweredByHeader: false`（使用技術を外に出さない）
- **検証**：本番ビルドで全ページ表示・デモ操作・フォーム送信が正常動作することを確認。
  本番の配信ファイルに `eval(` / `new Function(` が1件も無いことを確認済み
  （＝本番では最も厳しい設定のままで動く）。開発時のみホットリロード用に緩和。

## 低（対応済み・記録のみ）

### L-1. 3D演出の端末負荷

- **測定した内容**（本番ビルド）
  - トップページの初回読み込みJS：**175 kB**（3Dを含む全体）
  - 3Dの描画は Hero が画面外に出た時点で**完全停止**（`frameloop` を停止側へ切替）
  - 描画解像度の上限は端末解像度の1.75倍まで（青天井にしない）
- **今回さらに入れた対策**
  - OS側で「視差効果を減らす」を有効にしている人には、**3Dを動かさない**
    （動きに酔いやすい方への配慮。アクセシビリティ対応）
  - **スマホでは描画解像度の上限を1.25倍へ引き下げ**、発熱とバッテリー消費を抑制
- **残るリスク**：数年前の低性能Android実機での実測はまだ行っていない。
  公開後に実機で確認し、必要なら3Dを静止画に差し替える出し分けを検討する。

### L-2. 開発・本番サーバーの出力先が同じで衝突する

- `distDir` を環境変数で切り替えられるようにし、
  開発中でも本番同等ビルドを並行して確認できるようにした。

## 監査後に自前で見つけて直した不具合（監査対象外）

### X-1. 流入元（?ref= / utm_*）が記録されていなかった【重大】

- **症状**：営業担当ごとのURL（`?ref=sales01`）や広告のUTMを付けてアクセスしても、
  問い合わせに流入元が一切乗らない。**項目8（リード管理）と項目10（営業電話連携）が
  実質まるごと機能していなかった。**
- **原因**：Hero表示時に走るA/Bテスト記号の保存処理が、流入元の記録より先に
  「中身が空の記録」を作ってしまい、後から来る本来の記録処理が
  「もう記録がある」と判断して何もしなくなっていた。
- **修正後の確認**：`?ref=sales01&utm_source=google&utm_medium=cpc&utm_campaign=gacha_os_aug`
  でアクセスし、全項目が正しく保存されることを実機確認済み。

### X-2. 発送タブが「見せかけの表」だった

- 発送機能が画像同然で、触っても何も起きなかった。
- 対象選択 → 発送処理 → 追跡番号の発行 → 会員へ自動通知 → 操作ログ記録
  まで実際に動く流れに作り直した（デモ動画のCUT 5、商談デモの⑤で使う）。
