**これまで、お客様側の画面は「管理画面の中の見本」でした。**

## 3. 保有ポイント

`/mypage/points` に、次の6種類が時系列で出ます。

開始時の残高 ／ 付与 ／ ガチャ利用 ／ 商品交換 ／ 返還 ／ 調整

★**履歴の合計と、いまの残高が一致していること**を、試験で毎回確かめています。
一致しない場合は、画面に赤い帯を出して「合いません」と表示します。
黙って残高だけを見せることはしません。

## 4. お届け先

- 住所を変えても、**すでに確定した荷物の宛先は動きません**
  （注文したときの住所を、荷物ごとに写し取って保存しています）。
- 変更後の住所は、**次の依頼から**効きます。
- 変えたときは「この変更で動かない荷物が◯件あります」とお客様に伝えます。
- お届け先が未登録なら、発送依頼は受け付けません。

### 追加の本人確認（Step-up）について

**まだ入っていません。正直に書きます。**
画面にも「お客様側の追加の本人確認は、まだご用意できていません（本番前に必ず有効にします）」と出しています。

ただし、**判断する場所は1か所に集めてあります**（`lib/server/stepUpPolicy.ts`）。
「住所を変えた直後の、高額商品の発送依頼」といった、止めるべき条件はすでに書いてあり、
本人確認をつないだ日に、**そこだけを有効にすれば効きます**。
また、いま止めていない操作のうち「つないでいたら止めていた件数」を記録しているので、
つなぐ前に、何件が止まるのかが分かります。

## 5. 発送通知（いまは Mock）

発送が確定すると、通知が1件できて、お客様の「お知らせ」に出ます。

発送確定 → 通知を作る → 通知履歴に保存 → お客様のお知らせに表示

★**本物のメール・SMSには、まだ1通も送っていません。**
送信会社への接続は、この後の工程です。
Mockのあいだは、画面にも記録にも「本当に送った」とは書きません。

確かめたこと：

- 途中の段（準備中など）では、まだお知らせを出さない
- 同じ発送で、お知らせが二重に作られない
- 未読の数が数えられ、読むと0になる
- お届けが終わると、その分のお知らせも届く

---

## 6. 通し確認（E2E）

次の1本を、試験として毎回走らせています。

**当選 → 獲得商品 → 発送 or ポイント交換 → 管理側に反映 → 発送 → 通知 → お客様が確認**

途中の8段階すべてで、
「お客様の画面」と「管理側の画面」が**同じデータを見ている**ことを確かめています。

## 7. 試験について（数ではなく、何を確かめたか）

全部で 445 本。今回のマイページに直接関わるのは、次の3ファイルです。

| ファイル | 何を確かめているか |
| --- | --- |
| `mypageE2E.test.ts`（25本） | 上の通し確認8段階と、住所・発送の食い違い |
| `customerShipping.test.ts`（10本） | お客様の発送状況が、見本ではなく実データであること |
| `pointsApi.test.ts`（16本） | 残高と履歴が食い違わないこと |

### 試験そのものの直し（今回まとめて直しました）

これまで、**中身は全部「ok」なのに、まとめだけが「失敗」と出る回**が
20回に2回くらいありました。原因は試験の中身ではなく、
データベース部品の後片付けの不具合です（異常終了・または終わらなくなる）。

★**赤いのに直す場所が無い試験は、いちばん危険です。**
何度か見ると、人は赤を無視するようになります。そうなった試験は、もう何も守りません。

そこで、2つを組にして直しました。

1. **試験のあいだは、データベースの接続を閉じない**（`lib/server/db.ts`）
   閉じなければ、落ちる原因の「閉じたあとの後片付け」が動きません。
   そのぶんプロセスは自分で終われなくなりますが、それは下で終わらせます。
   ★本番では、これまでどおり閉じます（閉じないと接続が増え続けるため）。
2. **走らせ方を作り直す**（`scripts/run-tests.mjs`）
   - 1つの試験ファイルにつき、1つのプロセスで走らせる
   - 「何本走って、何本通って、何本落ちたか」の締めくくりが出るまで、必ず待つ
   - 締めくくりが出たら、後片付けだけを待たずに終わらせる
   - まれに、締めくくりを言い終える**前**に落ちる回があります。
     そのときだけ、そのファイルを**最初から**走らせ直します（最大2回）。
     走らせ直したことは、画面に必ず出します。

★**走らせ直すのは「合否が取れなかったとき」だけ**です。
「落ちた試験があったとき」は走らせ直しません。
そこを緩めると、たまたま通るまで回す仕組みになってしまいます。

★**ごまかしていないことの確認も、実際にやりました。**

| わざと仕込んだもの | 結果 |
| --- | --- |
| 必ず落ちる試験を1本足す | ちゃんと「失敗」で止まった |
| 締めくくりの前に「成功」で勝手に終わる試験を足す | 「締めくくりが出ていない」として失敗になった |

つまり「後片付けで落ちたのを見逃す」ことはしますが、
**「走らなかった試験を、通ったことにする」ことはしません**。本数が1本でも合わなければ止まります。

★採用しなかった直し方も書いておきます。
`--test-force-exit` を足すと赤は消えましたが、
**445本のはずが417本しか走らないまま「成功」と出ました**。28本が黙って消えます。
これはいちばんやってはいけない直し方なので、使いませんでした。

## 7-2. 公開した Preview を、実物で確かめました

試験は「手元の部品が揃っているか」までしか言えません。
公開した場所で本当に動くかどうかは、実際に開いて触らないと分かりません。
そこで、Preview サイトに対して次の2つを走らせました。

| 何を見たか | 結果 |
| --- | --- |
| お客様として本当にログインでき、自分のデータが出るか | 通りました |
| 管理画面まで何回押して着くか（発送・実還元率・AI作成・問い合わせ） | すべて上限内 |
| 一覧の行を押すと右の板が開き、Esc で閉じるか | ガチャ・発送・問い合わせ・会員のすべてで通りました |
| キーボードだけで操作できるか（Enter / Esc / ⌘K） | 通りました |
| お知らせ帯が、画面を移ると消えるか・時間で消えるか | 通りました |

★このとき、確認の道具そのものが3か所で古くなっていたことが分かり、直しました。

1. 入口が「練習用のボタン1つ」から本番と同じログイン画面に変わっていたのに、
   道具のほうが練習用のボタンを探し続けていた。
2. 左メニューが、途中でボタンから本物のリンクに変わっていた
   （別のタブで開けるようにするため）のに、道具はボタンだけを探していた。
3. 手元では一覧が一瞬で出るのに、ネット越しでは1〜2秒かかる。
   待たずに数えていたので「押せる行がありません」という**嘘の指摘**が出ていた。

★3つとも「システムが壊れていた」のではなく、**確かめる側が古かった**ものです。
ただし、古いまま放っておくと
「確かめたつもりで、一度も確かめていない」状態になります。
入り方の手順は1か所（`scripts/lib/console-enter.mjs`）にまとめ、
次に入口が変わったときに探して回らなくてよいようにしました。
