## はじめに ― この表は「まだ売れない理由」の一覧です

いまの管理サイトは、19画面あります。
そのうち **6画面は本物のデータ**を出しています。
残りの **13画面は、まだ見本の数字**です。

見本の数字は、動きの確認には役に立ちます。
ですが、そのまま契約者にお渡しすると、こうなります。

    運営の方が画面を見て、判断する
      → その数字は、実際の売上とは関係がない
      → 判断そのものが、まちがう

ですから **PRODUCT PASS = NO** のままにしています。
「中の仕組みが強くなったこと」と「そのままお渡しできること」は、別です。

## 直すときの決まり（項目30・31）

### ★固定の数字を、製品のコードに残さないこと

いまは、画面のファイルの中に直接、見本の数字が書いてあります。
（`DAYS`、`ITEMS`、`MARKET_ROWS`、`0.944` など）

これを **`lib/demo/` の見本置き場（Demo Fixture）へ移します。**
移す理由は、消し忘れを見つけられるようにするためです。
画面の中に散らばっていると、消したつもりの数字が1つだけ残ります。
残った1つは、たいてい、いちばん大事な画面に残ります。

### ★見本モードと、本番モードを分けること

| | 見本モード（営業でお見せするとき） | 本番モード（契約者がお使いのとき） |
|---|---|---|
| 数字 | 架空の値でよい | **実データか、0件だけ** |
| 画面の断り書き | 「これは見本です」と出す | 出さない（本物なので） |
| 0件のとき | 見本を出す | **「まだありません」と正直に出す** |

★本番モードで、見本の数字を出さないこと。
　0件を隠すために見本を出すと、運営の方は「動いている」と思ってしまいます。
